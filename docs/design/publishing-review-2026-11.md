# Публикация в TikTok / YouTube: разбор и что улучшить (ноябрь 2026)

Жалоба: ролики, выложенные сервисом, почти не набирают просмотров, а выложенные с телефона —
нормально. Ниже: что делает наш код сейчас, что известно о «веб против приложения», что
сделано в ветке и что должен решить владелец.

Уровни доказательности: **[OFF]** официальный документ площадки, **[PS]** заявление площадки
(newsroom, Creator Liaison), **[STUDY]** большая выборка, **[3P]** пересказ или блог,
**[ANEC]** частный опыт, **[MYTH]** миф.

## 1. Коротко

* Нет ни официальных данных, ни контролируемых экспериментов о том, что загрузка «с сайта»
  сама по себе режет охват. TikTok Studio в браузере — официальный путь загрузки [PS].
  Но наш сервис — это не «загрузка с сайта», а **автоматизация** закрытых веб-эндпоинтов TikTok
  (подпись X-Bogus из безголового Chromium). TikTok прямо запрещает «automation tools, scripts,
  or other tricks designed to bypass our systems» [OFF]. Если сработала защита, ограничение
  ложится на аккаунт: временно убираются из рекомендаций все его ролики [PS].
* Вторая сильная причина — **неоригинальный контент**. У TikTok «unoriginal or reused material
  without anything new» не попадает в ленту «Для вас» [OFF]. YouTube с 01.10.2026 явно режет
  охват каналам-агрегаторам чужих клипов в Shorts [PS].
* Качество файла на охват не влияет: свидетельств нет. Оно влияет на то, как ролик выглядит
  после пережатия площадкой. Здесь мы недорабатывали мелочами (метки цвета, файлы не по
  спецификации). Это исправлено, но чудес от этого ждать не стоит.
* Что починено в ветке: мастер-файл перед выкладкой; ссылка на TikTok-пост (раньше статистика
  TikTok не собиралась **вовсе**, так что «почти не набирают» с нашей стороны было даже не
  видно); повторы и таймауты; аудитория «не для детей» на YouTube.

## 2. Что делает наш код сейчас

### TikTok — `app/providers/tiktok.py`

* **Путь загрузки.** Не официальный Content Posting API, а приватные веб-эндпоинты TikTok
  Studio по cookie аккаунта (код повторяет `makiisthenes/TiktokAutoUploader` @73475db):
  * `api/v1/web/project/create` →
  * `video/upload/auth` → VOD `ApplyUploadInner` → куски по 5 МБ → `finish` →
    `CommitUploadInner` →
  * `tiktok/web/project/post/v1/` с `app_name=tiktok_web`, `device_platform=web`, `X-Bogus` и
    `_signature`.
* **Подпись** считает Signer из `tiktok-signature` в безголовом Chromium (`node/tiktok-sign.cjs`). Браузер открывает
  `www.tiktok.com`, поэтому идёт через прокси аккаунта; до 11.2026 `browser.js` ходил туда с IP сервера.
* **User-Agent** был зашит: `X11; Linux x86_64 … Chrome/120`, то есть Linux и Chrome
  двухлетней давности. Cookie при этом обычно сняты из Chrome на Windows, а запросы идут через
  прокси аккаунта.
* **Что уходит в пост:**
  * `text` = заголовок + `\n\n` + описание (до 2200 символов), хэштеги размечены в
    `text_extra`;
  * `visibility_type`: 1 при `private`, иначе 0. **«unlisted» в TikTok уходит публично** — у
    TikTok нет «по ссылке»;
  * `allow_comment` — по заданию; дуэты и стежки всегда включены;
  * `music_info: {}` — без звука из библиотеки, только оригинальный звук ролика;
  * `tcm_params` с пустой коммерческой отметкой;
  * `poster_delay: 0` — обложка из первого кадра.
* **Чего в посте нет:** обложки-кадра, отложенной публикации на стороне TikTok (`schedule_time`;
  у нас отложка своей очередью), метки ИИ-контента (AIGC), гео-ограничений.
* **Ответ.** `remote_id` был VOD-id файла, а не id поста. `remote_url` был **пустым**, поэтому
  `platform_stats` TikTok-публикации не видел.
* **Сеть.** Ни таймаутов, ни повторов: зависшее соединение держало воркер бесконечно, а любой
  обрыв проваливал публикацию.

### YouTube — `app/providers/youtube.py` + `node/youtube-upload.mjs`

* **Клиент.** youtubei.js 17 (InnerTube) по cookie Студии, `yt.studio.upload`. Внутри
  библиотеки старт загрузки **представляется Android-приложением**:
  `frontendUploadId: innertube_android:…`, `deviceDisplayName: 'Pixel 6 Pro'`,
  `fileId: goog-edited-video://…`
  (`node_modules/youtubei.js/dist/src/core/clients/Studio.js`). Это поведение библиотеки, не
  наш код, но с точки зрения правил это та же «подмена клиента».
* **Что уходит:** заголовок, описание (`#shorts` вырезается у 16:9), приватность,
  `is_draft:false`. У 16:9 — миниатюра отдельным `updateVideoMetadata`.
* **Чего не было:**
  * аудитории «для детей» — YouTube требует указать её у каждого ролика [OFF];
  * категории, тегов, языка;
  * отметки «изменённый/синтетический контент» — в протоколе youtubei.js её нет [OFF о самом
    требовании];
  * повторов.
* Cookie самовосстанавливаются: обновлённые значения записываются обратно (было и раньше).

### Instagram — `app/providers/instagram.py`

instagrapi — закрытый **мобильный** API Instagram по `sessionid`. Это уже эмуляция приложения;
к ней относится то же замечание про правила площадки.

### Файл и воркер

* **Финальный рендер** (`app/render.py`):
  * libx264 без `-preset` и `-crf`, то есть x264 по умолчанию: medium, CRF 23. Исключение —
    если в `extra_json` пресета задан `crf`. Моушн-компоновщик кодирует с CRF 18;
  * два и больше поколения кодирования: куски → прожиг субтитров;
  * AAC 48 кГц 256k, `+faststart`.
* **Реальные клипы** из `D:\vvf-data\clips` (ffprobe):
  * H.264 High@4.0, yuv420p, 1080×1920, 30 к/с CFR;
  * видео 0,7–6,4 Мбит/с;
  * **меток цвета нет** (`unknown`).
* **Воркер** (`app/worker.py`) выкладывает цели задания по очереди, один и тот же файл на все
  аккаунты сразу. Отложка — только целиком на задание (`scheduled_at`).

### Чего не нашлось

* Контролируемого исследования «веб против приложения» нет.
* Официальных спецификаций TikTok по битрейту нет.
* Официальной связи качества файла с охватом нет.
* Документация YouTube Data API противоречит сама себе: запись 2020 года говорит, что загрузки
  неверифицированных проектов принудительно приватные, а текущая страница `videos.insert` — что
  уже нет. Перепроверить перед переходом на API.

## 4. Почему у нас так: гипотезы по убыванию вероятности

1. **Неоригинальный или переиспользованный контент.** Нарезки чужих стримов и аниме без
   существенной переработки — официальная причина не пускать ролик в ленту на всех трёх
   площадках. Если с телефона выкладывались другие ролики (свои, промо), сравнение нечестное.
2. **Автоматизация и сигналы риска у TikTok:**
   * подпись из безголового браузера;
   * UA Linux/Chrome 120 при cookie из другого браузера;
   * прокси с другим IP, чем у сессии;
   * несколько аккаунтов с одного сервера;
   * один и тот же файл сразу на несколько аккаунтов (дубли).

   Любое из этого может ограничить аккаунт целиком. Проверяется в **Account Check**.
3. **Аккаунты разного «возраста».** Если с телефона постится основной прогретый аккаунт, а
   сервисом — новые, разница может быть в аккаунтах, а не в способе загрузки.
4. **Чего нет в нашей загрузке, но есть в приложении:** звук из библиотеки, тренды, эффекты,
   обложка-кадр, текст на экране из редактора TikTok. Звуки и эффекты доступны только в
   приложении [3P].
5. **Мелочи:**
   * «unlisted» в TikTok уходит публично;
   * у YouTube не указана аудитория;
   * подпись TikTok = заголовок + описание: длинно, главное может не попасть в первую строку.
6. **Качество файла** — последнее место. Наши клипы уже по спецификации; не хватало меток цвета.

### Чего НЕ делать (или только по явному решению владельца)

* **Притворяться мобильным приложением** через его закрытый API, фермы device-id, подделка
  метаданных файла «как с iPhone». Нарушает условия TikTok: запрет «automated scripts» и обхода
  ограничений, запрет reverse engineering [20], [21], [1]. Аккаунты под угрозой бана. Не реализовано.
* Сам текущий способ (веб-эндпоинты TikTok с X-Bogus, InnerTube YouTube с Android-видом в
  youtubei.js, instagrapi) уже серый по правилам площадок:
  * TikTok — запрет «automation tools» [1];
  * YouTube — запрет доступа «automated means» [22].

  Это стоит держать в голове, а не усиливать. Легальная замена — п. 5.
* Накрутка первого часа, «прогрев» ботами, массовое создание аккаунтов — прямой запрет [1].

## 6. Что сделано в этой ветке

Каждый пункт — отдельный коммит, с тестами без сети.

1. **Мастер-файл для площадок** (`app/publish_master.py`, вызывается из `app/worker.py`).
   * Перед выкладкой файл разбирается ffprobe, и чинится только то, что не по спецификации
     YouTube [10]:
     * не H.264 / 10 бит / yuvj / VFR / >60 к/с / ниже 1080p / поворот телефона — видео
       заново: CRF 17, High@4.2, BT.709 на кадрах, CFR, GOP 0,5 с, 2 B-кадра, maxrate 16/24M;
     * звук не AAC / не 44,1–48 кГц / больше двух каналов — заново только звук (AAC 48 кГц 320k);
     * нет меток цвета или faststart — перепаковка без потерь.
   * Наш обычный клип получает только метки BT.709, кадры побитно те же (тест сверяет framemd5).
   * HDR не трогается.
   * Один мастер на задание, удаляется после. Сбой — уходит исходный файл, причина в
     `response.master` цели.
   * Настройки: `PUBLISH_MASTER=auto|always|off`, `PUBLISH_MASTER_CRF`, `_PRESET`, `_GOP_SEC`,
     `_AUDIO_BITRATE`, `_UPSCALE`.
2. **TikTok** (`app/providers/tiktok.py`):
   * id поста из ответа → `remote_url = https://www.tiktok.com/@/video/<id>` (формат понимает
     yt-dlp) — статистика TikTok начинает собираться;
   * id (`item_id`, `video_id`, `creation_id`, `project_id`) — в ответе и в логе;
   * повторы шагов **до** поста при обрыве сети, 429 и 5xx (`PUBLISH_UPLOAD_RETRIES`,
     `PUBLISH_UPLOAD_RETRY_SECONDS`); сам пост не повторяется никогда, чтобы не было дубля;
   * таймауты у всех запросов;
   * `TIKTOK_USER_AGENT`.
3. **YouTube** (`node/youtube-upload.mjs`, `app/providers/youtube.py`):
   * после загрузки ставятся аудитория (`YOUTUBE_MADE_FOR_KIDS=false` по умолчанию; `unset` —
     как раньше) и категория (`YOUTUBE_CATEGORY_ID`, по умолчанию не трогается). Best effort;
   * повторы только для ошибок до `createvideo`: сетевой сбой на самом `createvideo` не
     повторяется, иначе мог бы появиться дубль;
   * в ответе `uploadAttempts` и `metadataSet`;
   * помощник разбит на тестируемые функции, есть `node/youtube-upload.test.mjs`.

4. **Тревога «0 просмотров»** (`app/zero_views.py`): через `ZERO_VIEWS_HOURS` (2 ч) после публикации
   сервис сам снимает числа поста; просмотров не больше `ZERO_VIEWS_THRESHOLD` (0) — карточка
   «Внимание» в «Одобрении» и Telegram: что нашлось в данных (дубль одним заданием, клип уже
   выкладывали, у аккаунта ещё посты без просмотров, приватный пост, нарезка чужого видео) и чек-лист
   площадки (статус «не подходит для рекомендаций», Account Check, переиспользованный контент).
   Просмотры пошли — тревога снимается сама. Значок «👁 N» / «⚠ 0 за 2 ч» на клипе и в «Публикациях».

5. **Проверка перед первой настоящей публикацией (11.2026)**, тесты без сети:
   * вся сеть TikTok-аккаунта через его прокси: шаги загрузки, подпись, статистика и тревога «0 просмотров»;
     мёртвый прокси — ошибка, напрямую не пробуем (`tests/test_tiktok_proxy.py`, локальный прокси с записью);
   * один ролик на один аккаунт — один раз: двойной клик, тот же аккаунт дважды, «мог выйти» и перезапуск
     (`maybe_posted`, повтор только с «да» владельца), занятое задание, перенос в автопилоте; отмена из очереди;
   * правдивая причина: мёртвый прокси больше не «нужны cookie», мёртвая сессия — needs_reauth со словами TikTok;
   * «по ссылке» в TikTok — отказ при постановке, а не публичный пост; подпись больше 2200 — отказ;
   * расписание в UTC (экран переводит местное), прошедшее время — ошибка;
   * уходит файл с тем хэшем, что был при постановке; в ответе — какой текст ушёл;
   * форма аккаунта: JSON Cookie-Editor, прокси «логин:пароль:хост:порт», свежие cookie не стирают прокси;
     выгрузка cookie и настройка бота — только владелец.

## 7. Нужно решение владельца

1. **Переход на официальные API** (п. 5). Это самое существенное по риску для аккаунтов.
2. **Разные файлы или разное время для разных аккаунтов** одной площадки (п. 4). Сейчас один
   файл уходит сразу на все.
3. **«unlisted» в TikTok.** С 11.2026 — отказ при постановке (раньше уходило публично). Можно заменить на «только для
   друзей» (`visibility_type`), если владелец этого хочет.
4. **Отметка ИИ-контента в TikTok.** Нужно один раз снять запрос TikTok Studio в DevTools
   своего браузера с включённым тумблером «AI-generated» — только чтобы узнать имя поля. Затем
   ставить его у роликов из ИИ-видео.
5. **Аудитория YouTube по умолчанию «не для детей».** Это юридическая декларация. Для нарезок
   стримов и аниме верно; если появится детский контент — `YOUTUBE_MADE_FOR_KIDS=unset` или `true`.
6. **CRF 18 в пресетах рендера** (п. 9): картинка лучше, файлы больше.
