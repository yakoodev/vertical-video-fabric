# Как агенту улучшать клипы Vertical Video Fabric

Сервис сам находит моменты в длинном видео и режет их в вертикальные 9:16 клипы.
Ты (Claude, Codex или человек в терминале) можешь доводить любой клип **снаружи
сервиса**: не трогая его код и базу, только через **файл клипа** и API.

Всё делается инструментом `tools/vvf.py` (только стандартная библиотека Python 3.6+).

```bash
export VVF_URL=http://localhost:8088
export VVF_TOKEN_FILE=/data/api_token.txt   # или VVF_TOKEN=<токен>
python tools/vvf.py sources
```

## Подключение по MCP (Claude Code, Codex, любой MCP-клиент)

Сервис сам является MCP-сервером: `http://<хост>:8088/mcp`, транспорт **Streamable HTTP**,
авторизация тем же токеном API (`Authorization: Bearer <токен>`; токен — `data/api_token.txt`
или `POSTING_API_TOKEN`). Через MCP доступны те же инструменты, что у встроенного
ИИ-монтажёра в редакторе: смотреть клип и его кадры, ставить титры/эмодзи/стикеры/графику,
делать наезды камеры, искать картинки и звуки, править субтитры, переходы и подрезку.

**Claude Code:**

```bash
claude mcp add --transport http vvf http://localhost:8088/mcp --header "Authorization: Bearer <токен>"
```

**Codex** (`~/.codex/config.toml`; токен в переменной окружения `VVF_TOKEN`):

```toml
[mcp_servers.vvf]
url = "http://localhost:8088/mcp"
bearer_token_env_var = "VVF_TOKEN"
```

Сервер stateless: отвечает на POST обычным JSON (GET `/mcp` → 405, SSE-потока нет) —
это допустимый режим Streamable HTTP, все клиенты с ним работают.

### Инструменты

Инструментам клипа нужен `clip_id` (его дают `list_projects` → `list_clips`).
Каждая правка через MCP делает снимок истории: владелец откатит её Ctrl+Z в редакторе.
Ошибка — это `isError: true` и список `problems`: исправь и повтори.

| Инструмент | Что делает |
|---|---|
| `list_projects`, `list_clips(project_id)` | найти проект и клип |
| `get_clip(clip_id)` | куски, настройки, слои, камера, вставки, субтитры со временем слов (секунды клипа), предупреждения |
| `get_transcript(clip_id, from_sec?, to_sec?)` | реплики исходника (время исходника) — для подрезки |
| `view_frame(clip_id, t, with_layers?)` | **картинка** кадра готового вида (слои + камера) — смотри, что получилось |
| `contact_sheet(clip_id, n?)` | **сетка** из n кадров по всему клипу — ритм графики и перегруз видно сразу (`vvf.py contact`) |
| `suggest_cuts`, `apply_cuts` | найти и вырезать паузы/слова-паразиты (длинные паузы помечены `risky` — не режь вслепую) |
| `auto_edit(clip_id, style?)` | автомонтаж без ИИ: хук, субтитры с эмодзи, наезды и удары по речи — основа для правки |
| `compose_cover(clip_id, t, title, style?)` | обложка: кадр + крупный заголовок, включается сразу |
| `make_compilation(clip_ids, title?)` | новый клип «ТОП-N» из нескольких клипов проекта |
| `add_layers`, `update_layer`, `remove_layers`, `clear_layers` | моушн-слои (проверка `app/motion.py`) |
| `set_camera(keys)` | все ключи камеры разом (наезды) |
| `get_motion_reference` | шпаргалка по слоям |
| `list_fonts`, `search_emoji(q)`, `list_packs`, `search_pack(pack, q)` | шрифты, эмодзи, паки стикеров/звуков/мемов |
| `list_assets(q?)` | «Файлы для монтажа» владельца (asset_id) |
| `search_web_images(query, free_only)`, `add_image_from_url(url)`, `generate_image(prompt)` | найти/скачать/нарисовать картинку → asset_id |
| `list_subtitle_styles`, `set_subtitles`, `edit_subtitle_lines` | субтитры: вкл/стиль/высота, правка текста строк |
| `set_transition`, `trim_piece`, `add_insert`, `remove_insert` | переход, подрезка куска, вставки-мемы |

Полный список с JSON Schema параметров: `GET /api/agent/tools`.

### Моушн-слои: шпаргалка

Контракт — [`docs/motion/spec.md`](motion/spec.md), схема полей — `GET /api/motion/schema`.

- Кадр 1080×1920; `x`, `y` — центр слоя в долях кадра; размеры — опорные пиксели.
- Время `start`/`end` — секунды **готового** клипа; `keys` — время от начала слоя.
- Безопасная зона для текста: `y` 0.15–0.72 (внизу интерфейс площадки и субтитры, вверху шапка).
- Типы: `text`, `emoji`, `image` (`asset_id` или `src: "emoji:1f525" | "sticker:<pack>/<file>"`),
  `shape` (arrow/ellipse/…), `counter`, `progress`, `chart`, `callout`, `audio` (`sfx:<pack>/<file>`).
- Вход/выход: `pop`, `words`, `typewriter`, `slideUp`, `zoom`, `draw`…; постоянное: `pulse`, `wiggle`, `shake`.
- Камера: `[{t, zoom 1..4, x, y, ease}]` — панч-ин на панчлайн 1.0 → 1.2–1.35 за 0.2 с.

```json
{"type":"text","start":0.0,"end":2.2,"x":0.5,"y":0.24,
 "props":{"text":"ОН ЭТО СДЕЛАЛ","size":100,"weight":900,"color":"#FFFFFF","stroke":{"color":"#000000","width":10}},
 "in":{"type":"words","duration":0.35},"out":{"type":"fade","duration":0.2}}
```

### Без MCP: встроенный ИИ-монтажёр и слои из терминала

```bash
python tools/vvf.py agent 812 "добавь хук и подпиши цифры"   # встроенный агент, печатает шаги
python tools/vvf.py layers 812                                # слои и камера
python tools/vvf.py layers 812 --json > layers.json           # → правишь → обратно:
python tools/vvf.py layers-set 812 layers.json                # проверка + замена (Ctrl+Z откатит)
python tools/vvf.py frame-motion 812 --at 3.2 -o f.png        # кадр со слоями и камерой
```

Встроенный агент — это `POST /api/clip-plans/{id}/agent` `{message}` и опрос
`GET /api/clip-plans/{id}/agent` (шаги видны по мере работы); модель — `GEMINI_AGENT_MODEL`.

## Клипы без Gemini: сам выбираешь моменты

Анализ Gemini не обязателен. Чтобы нарезать исходник (серию, стрим) самому:

1. `GET /api/sources/{id}/transcript` — расшифровка всего исходника `[{start, end, text}]`
   во времени исходника. Первый вызов — локальный Whisper, несколько минут; потом из кэша.
   `?from_sec=&to_sec=` — только окно.
2. Выбери моменты: завязка → развязка, клип 30–75 с, самодостаточный. Посмотри кадры
   (`GET /api/sources/{id}/frame?t=`), чтобы смешное не было только в звуке.
3. `POST /api/sources/{id}/manual-clips` `{title, description?, pieces: [{start_sec, end_sec, title?}]}` —
   клип из кусков исходника (каждый 5–180 с, до 12). Ответ — клип с `id`; дальше обычный цикл ниже.

## Цикл работы

1. **Выбрать клип.** `vvf.py clips <проект> --favorites` — избранные (★) владелец
   отметил как годные. ⚙ значит, что у клипа уже есть свои настройки рендера.
2. **Забрать файл.** `vvf.py pull <клип> -o clip.json`.
3. **Посмотреть материал.** Файл — это цифры. Прежде чем их менять, посмотри на картинку:
   - `vvf.py frame <проект> --at <секунда> -o f.jpg` — кадр исходника целиком;
   - `vvf.py frame <проект> --at <секунда> --x 0.62 -o c.jpg` — ровно то окно 9:16,
     которое останется при фокусе `x`.
4. **Поправить файл** (правила ниже).
5. **Проверить:** `vvf.py check clip.json`. Сервер перечислит ВСЕ проблемы сразу.
6. **Применить:** `vvf.py push clip.json --write-back`. Файл применяется целиком или
   не применяется вовсе. `--write-back` перезапишет его свежей версией с сервера,
   например с id новых кусков.
7. **Отрендерить:** `vvf.py render <клип>`. Рендер синхронный: команда ждёт готового
   видео и печатает отчёт о качестве (QC).
8. **Проверить результат.** Посмотри QC, при сомнениях скачай видео
   (`vvf.py download <рендер> -o out.mp4`) и посмотри кадры. Дальше повтори с шага 4.

## Файл клипа (`vvf.clip/1`)

```jsonc
{
  "schema": "vvf.clip/1",
  "clip_id": 812,                 // только чтение
  "source": { "id": 50, "duration_sec": 15050, "width": 1280, "height": 720, ... },  // только чтение
  "title": "Прерогатива Чугуняшки",
  "description": "…",
  "favorite": true,
  "notes": "почему смонтировано так — оставь заметку для человека",
  "pieces": [                     // куски клипа по порядку
    { "segment_id": 1201, "title": "Повод", "start_sec": 2963.0, "end_sec": 2981.5,
      "focus": [{ "t": 0, "x": 0.71 }, { "t": 6.2, "x": 0.35, "cut": true }] }
  ],
  "render": {                     // настройки рендера ЭТОГО клипа
    "preset_id": 3, "mirror": false,
    "subs_on": true, "sub_id": 2, "sub_engine": "", "sub_pos_pct": 12,
    "banner_on": false, "banner_id": null, "banner_height_pct": 14, "banner_pos_pct": 4,
    "music_on": false, "track_id": null,
    "transition": { "type": "fade", "duration": 0.35, "audio": "smooth", "sfx": "whoosh", "sfx_volume": 0.5 },
    "cover": { "mode": "frame", "piece": 0, "offset": 2.4, "image": "", "burn": true, "burn_sec": 0.1 },
    "layers": [ { "type": "text", "start": 3.2, "end": 6.0, "x": 0.5, "y": 0.3,
                  "props": { "text": "ПАНЧЛАЙН" }, "in": { "type": "pop", "duration": 0.35 } } ],
    "camera": [ { "t": 4.0, "zoom": 1.0 }, { "t": 4.3, "zoom": 1.35, "y": 0.4 } ]
  },
  "renders": [ { "clip_id": 431, "status": "succeeded", "qc": { ... } } ]   // только чтение
}
```

Схема целиком: `vvf.py schema`.

### Правила

- **Куски.** Каждый кусок длится от 5 до 180 с и лежит внутри исходника; всего до 12 кусков.
  - Оставь `segment_id`, чтобы менять существующий кусок.
  - Убери `segment_id`, чтобы добавить новый.
  - Не перечисляй кусок, чтобы убрать его из клипа.
  - Порядок в списке — это порядок в клипе.
- **Общий кусок копируется сам.** Если кусок используется ещё в другом клипе, при
  изменении таймкодов сервер сделает копию: чужой клип не пострадает.
- **Кадрирование.** Кадр 9:16 вырезается из широкого исходника, и `x` — центр
  этого окна по ширине (0 — левый край, 1 — правый).
  - `focus` — трек точек `{t, x}` от начала куска, камера плавно ведёт между ними; `cut: true` означает резкую смену кадра в этой точке.
  - Одна точка `[{ "t": 0, "x": 0.4 }]` — неподвижный кадр на весь кусок.
  - Можно писать короче: `"manual_x": 0.4` вместо `focus`, сервер сам превратит это в трек из одной точки.
  - Не указывай `focus`, если не меняешь его: трек останется прежним.
- **Переходы** работают, только если кусков больше одного.
  - Типы: `cut`, `fade`, `fadeblack`, `fadewhite`, `flash`, `slide`, `smooth`, `wipe`, `zoom`, `dissolve`.
  - `audio`: `smooth` (звук перетекает, на резкой склейке нет щелчка) или `hard`.
  - `sfx` — звук на каждом стыке: `none`, `whoosh`, `click`, `pop`.
- **Обложка** (`render.cover`):
  - `mode`: `none`, `frame` — момент самого клипа (`piece` — номер куска с 0, `offset` — секунды от его начала), `image` — загруженная картинка (`POST /api/covers`, в `image` пишется имя, которое вернёт сервер).
  - `burn: true` кладёт обложку на первые `burn_sec` секунд ролика (0.04–0.5): площадки, которые берут превью с первого кадра, покажут её.
  - Готовая обложка лежит в `renders[].cover_url`.
- **Моушн-слои и камера** (`render.layers`, `render.camera`): титры, плашки, стикеры,
  стрелки, счётчики, графики, звуки на акценты и наезды камеры. Контракт —
  `docs/motion/spec.md`, схема полей — `GET /api/motion/schema`.
  - Время слоя — секунды готового клипа (`start`/`end`), `x`/`y` — доли кадра 9:16.
  - Проверить без сохранения: `POST /api/clip-plans/{id}/layers/validate`; посмотреть
    кадр: `POST /api/clip-plans/{id}/motion/frame?t=3.2` (PNG).
  - Ошибки формы слоёв отклоняют файл клипа целиком — сервер перечислит все.
- **Раскладка стрима** (`render.layout`): самый частый формат стрим-шортсов — вебка
  сверху, игра снизу.
  - `mode`: `single` (обычный кадр 9:16, по умолчанию), `split` (вебка полосой сверху
    или снизу, `cam_pos: top|bottom`, `ratio` 0.2–0.6 — её доля высоты), `pip_cam`
    (обычный кадр + вебка окошком: `pip {x, y, w}` — центр и ширина в долях кадра 9:16).
  - `cam {x, y, w, h}` — где вебка в исходнике (доли всего кадра). Найти сама:
    `POST /api/sources/{id}/detect-facecam` (вернёт `{cam, confidence}` и запомнит
    на источнике); сохранённая — `GET /api/sources/{id}/facecam`.
  - `border {color: "#rrggbb", width}` и `gap` — рамка вебки и зазор (px кадра 1080×1920).
  - В `split` трек `focus` ведёт окно игры (оно шире 9:16), `x` значит то же самое.
- **Не трогай** `clip_id`, `source`, `renders`: сервер их игнорирует.
- **Не рендери всё подряд.** Рендер длинный. Меняй один клип, рендери, проверяй.

## Что обычно улучшает клип

- **Хук в первые 1–2 секунды.** Если лучшая фраза или реакция в середине, поставь
  этот кусок первым либо подрежь `start_sec` начального куска к моменту, где уже
  что-то происходит.
- **Мёртвое начало и хвост.** Паузы, «эээ», переход к другой теме — подрезай.
  Смотри тишину в QC: `тишина N с на T с`.
- **Лицо или действие вне кадра.** Возьми кадры через `frame --x`, подбери `x` так,
  чтобы главное было в центре окна. Если объект перемещается, задай `focus` с 2–4
  точками. Если говорящий не двигается, хватит одной точки (`manual_x`).
- **Склейка разных сцен.** Встык даёт резкий перескок, `fadeblack` 0.3–0.5 с читается
  как «прошло время». Для мемного монтажа подходят `flash` или `zoom` со `sfx: whoosh`.
- **Субтитры.** Для шортсов почти всегда включать: большинство смотрит без звука.
- **Обложка.** Бери кадр с яркой эмоцией или самым смешным моментом, не первый попавшийся. Смотри кандидатов через `frame --x` и вшивай (`burn: true`).

## Подводные камни (собрано по отзыву агента-монтажёра)

- **Время после вырезов.** Слои, камера, вставки и субтитры всегда задаются во времени
  клипа **до** вырезов (`duration` из `get_clip`) — при рендере они сдвигаются сами,
  а то, что целиком внутри выреза, пропадает (хук с 0 с остаётся в начале). Если вырезы
  есть, `get_clip` отдаёт `cuts` и `finished_duration` — длину готового ролика.
  Вставка, через которую проходит вырез, укорачивается на его длину.
- **GIF — только вставкой.** Слой `image` рисует первый кадр (гифка будет стоять);
  анимированные гифки и видео-мемы — `add_insert` (mode `pip`). `scale` у вставки —
  доля **ширины** кадра (0.5 = полкадра), высота по пропорциям. Окошко само
  отодвигается от хука, субтитров и крупных титров.
- **Правка кусков и субтитры.** Подрезал, переставил или выкинул кусок — субтитры переезжают
  сами: каждое слово привязано к секунде исходника и едет со своим куском, слова из
  отрезанного пропадают. Распознавать заново нужно только если кусок РАСШИРИЛИ на новую
  речь (get_clip предупредит: «речь есть, а субтитров нет»). Слои, камера, вставки и
  вырезы тоже едут за своими кусками (кроме перестановки кусков — тогда проверь руками).
- **На слово, а не на секунду.** Звук, титр или мем ровно на слово: в add_layers/add_insert вместо
  start/at передай `at_word: {line, word}` (номера из get_clip.subtitles) или `{text: "Артас", nth: 2}`;
  `word_offset: -0.1` — чуть раньше слова, `duration` — длина слоя.
- **Послушать, а не гадать.** `listen` (без параметров — последние 6 с) распознаёт звук ГОТОВОГО
  клипа с вырезами: договорена ли развязка, сколько тишины после последнего слова, не торчит ли
  слово из выреза. `contact_sheet` с `times` — кадры в нужные моменты (все панчлайны, финал).
- **Концовка = развязка.** Владелец: «концовки бессмысленные». Клип кончается на панчлайне,
  реакции, выводе или фейле — и 0.5–1 с реакции после. Не на нейтральной фразе и не на первых
  словах новой темы: такое отрезай. Не попала развязка — продли последний кусок до неё. Не обрывай
  на последнем слове (get_clip и trim_piece предупредят про полуслово).
- **Голоса в субтитрах.** У слова может быть `speaker` (A — главный, B/C/D — гость,
  донат-TTS, ролик). Слой `captions`: `speakers: ["A"]` — показывать только эти голоса,
  `speakerColors: [{s, color}]` — цвет слов голоса (по умолчанию у не-A свой цвет).
  Голоса размечает `separate_voices` (нужен Gemini).
- **Без Gemini (нет ключа / кончились кредиты)** работают: распознавание речи
  (локальный whisper — сервис переключается сам), поиск картинок (`search_web_images`
  ищет в Imgflip-мемах и Wikimedia Commons; гифки — через Giphy, если задан
  `GIPHY_API_KEY`; запросы лучше по-английски), слои, камера, вставки, рендер, QC.
  Не работают: анализ, «ИИ выбирает», встроенный ИИ-монтажёр, `separate_voices`,
  рамка героя (`subject_box`) и проверка «картинка про запрос?» (пропускается).
- **Минимальная длина куска — 5 с.** Короткие реплики вырезай `apply_cuts` внутри куска,
  а не отдельными кусками.

## QC — что значит отчёт

| Замечание | Что делать |
|---|---|
| `чёрный кадр N с на T с` | подрезать кусок или сдвинуть границу |
| `картинка стоит N с` | подрезать; если это пауза, убрать её |
| `тишина N с на T с` | подрезать, особенно в начале и конце |
| `тихо: −23 LUFS` / `пережато: −7 LUFS` | площадки ждут около −14: проверить пресет и музыку |
| `пик … dBFS` | риск хрипа после пережатия площадкой: тише музыка или громкость |
| `длиннее 3 минут` | YouTube не примет как Shorts: сократить |
| `размер …, обычно 1080×1920` | выбрать пресет 1080×1920 |

`ok: true` в отчёте означает, что предупреждений нет.
