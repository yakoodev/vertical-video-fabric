# Как агенту улучшать клипы Vertical Video Fabric

Сервис сам находит моменты в длинном видео и режет их в вертикальные 9:16 клипы.
Ты (Claude, Codex или человек в терминале) можешь доводить любой клип **снаружи
сервиса**: не трогая его код и базу, только через **файл клипа** и API.

Всё делается инструментом `tools/vvf.py` (только стандартная библиотека Python 3.6+).

```bash
export VVF_URL=http://localhost:8088
export VVF_TOKEN_FILE=/data/api_token.txt   # или VVF_TOKEN=<токен>
python tools/vvf.py sources
```

## Подключение по MCP (Claude Code, Codex, любой MCP-клиент)

Сервис сам является MCP-сервером: `http://<хост>:8088/mcp`, транспорт **Streamable HTTP**,
авторизация тем же токеном API (`Authorization: Bearer <токен>`; токен — `data/api_token.txt`
или `POSTING_API_TOKEN`). Через MCP доступны те же инструменты, что у встроенного
ИИ-монтажёра в редакторе: смотреть клип и его кадры, ставить титры/эмодзи/стикеры/графику,
делать наезды камеры, искать картинки и звуки, править субтитры, переходы и подрезку.

**Claude Code:**

```bash
claude mcp add --transport http vvf http://localhost:8088/mcp --header "Authorization: Bearer <токен>"
```

**Codex** (`~/.codex/config.toml`; токен в переменной окружения `VVF_TOKEN`):

```toml
[mcp_servers.vvf]
url = "http://localhost:8088/mcp"
bearer_token_env_var = "VVF_TOKEN"
```

Сервер stateless: отвечает на POST обычным JSON (GET `/mcp` → 405, SSE-потока нет) —
это допустимый режим Streamable HTTP, все клиенты с ним работают.

### Инструменты

Инструментам клипа нужен `clip_id` (его дают `list_projects` → `list_clips`).
Каждая правка через MCP делает снимок истории: владелец откатит её Ctrl+Z в редакторе.
Ошибка — это `isError: true` и список `problems`: исправь и повтори.

| Инструмент | Что делает |
|---|---|
| `list_projects`, `list_clips(project_id)` | найти проект и клип |
| `get_performance(limit?)` | что заходит: топ и антитоп опубликованных клипов по просмотрам с признаками монтажа (хук, субтитры, музыка, звуки, вырезы, раскладка, хромакей) и сравнение «с признаком / без». Пусто и `hint` — публикаций с числами ещё нет: это нормально, монтируй по правилам ниже |
| `get_source_transcript(project_id, from_sec?, to_sec?)` | реплики всего исходника — выбрать моменты без Gemini; звук без речи (игра) — пустой список и `no_speech`. Первый раз Whisper распознаёт **фоном**: вызов ждёт ≤ ~45 с и, если не готово, отвечает `status: "running"` — «распознаю: готово N из M мин, повтори через ~K с» (`retry_after_sec`); зови тот же вызов снова, второе распознавание не запустится. Готово — `status: "done"` и реплики из кэша |
| `source_loudness(project_id, from_sec?, to_sec?, step?, top?, track?)` | громкость исходника (RMS дБ) по шагу ≥ 0.5 с в окне ≤ 10 мин, пики и громкие отрезки, медиана и порог «громко» (медиана + 6 дБ) — перестрелки и реакции без Gemini; `track` — одна дорожка записи вместо смеси (сравнить игру и микрофон) |
| `source_contact_sheet(project_id, from_sec, to_sec, step?, x?)` | **сетка** кадров ИСХОДНИКА (до 24) с временем исходника; `step` от 0.04 с — покадрово на коротком окне (подписи до сотых); `x` 0..1 — окно 9:16 с этим центром |
| `set_source_audio(project_id, tracks?, speech_tracks?)` | звуковые дорожки записи (см. «Звуковые дорожки записи»): `tracks` — смесь для рендера `[0, 1]` или со своей громкостью `[{track, gain_db}]` (`"auto"` — замерить); `speech_tracks` — дорожка для распознавания речи (`[1]` — один микрофон) |
| `chat_activity(project_id, from_sec?, to_sec?, bucket?)`, `get_chat(project_id, from_sec, to_sec)` | чат Twitch (время исходника): всплески по минутам/окнам и сами сообщения (см. «Чат Twitch») |
| `get_shots(project_id, from_sec?, to_sec?)` | склейки планов исходника — куда ставить жёсткую смену кадра (`cut: true`) |
| `auto_focus(clip_id, piece?, use_vlm?, first_person?)` | кадрирование 9:16 само: говорящий по планам (Gemini смотрит кадр каждого плана; `use_vlm: false` — только лица/движение), смена на склейках; длинный план с диалогом — по репликам субтитров, плавный поворот к ответившему (`turns` в ответе). Игра от первого лица — окно неподвижно на прицеле (см. «Кадр и интерфейс игры») |
| `set_focus(clip_id, piece, points[{t, x, cut?}])` | кадрирование 9:16 куска: центр окна `x(t)` (t — секунды от начала куска или `source_t` — секунды исходника прямо из `get_shots`; x 0..1 — доля ширины исходника; `cut: true` — жёсткий переход на смене плана). Без cut окно плавно ведётся; одна точка — неподвижный кадр; `[]` — по центру. Заменяет трек куска целиком |
| `set_piece_fit(clip_id, piece, w, bg?)` | кусок **шире окна 9:16**: в кадре доля `w` ширины исходника (0.35..1; 1 — весь кадр), сверху и снизу фон `bg` (`blur` — размытый тот же кадр; анимированный — имя стиля `aurora`/`grid`/`bokeh`/`waves` или объект фона, см. «Фоны»; `black`/`#rrggbb` — только если владелец просил); центр — тот же `focus`. `w: null` — обычный кадр. Раскладка клипа на этот кусок не действует |
| `create_clip(project_id, title, pieces)` | новый клип из таймкодов исходника |
| `build_app_promo(clip_id, spec, dry_run?)` | **заготовка промо приложения** на холсте одним вызовом: хук, сцены с телефоном по долям трека, наезды на кнопки, окно кульминации, финал с CTA, звуки и музыка; повторный вызов заменяет только слои «promo: …» (см. «Промо приложения») |
| `create_canvas_clip(duration, background?, title?)` | **пустой холст**: клип без исходного видео (5–180 с), весь кадр — анимированный фон (`aurora`/`grid`/`bokeh`/`waves`/`gradient`/`solid` или объект фона, см. «Фоны»); дальше слои, музыка, звуки и рендер как у клипа (см. «Пустой холст») |
| `listen(clip_id, from_sec?, to_sec?, before_cuts?)` | что реально звучит в готовом клипе (с вырезами и наплывами переходов); время — шкала `final`, с `before_cuts: true` — `clip`; по умолчанию последние 6 с; распознаёт дорожку речи (`speech_tracks`); речи нет — `words: []`, пометка и громкость отрезка `level`. Для **концовок и вырезов** (договорена ли развязка, не торчит ли слово) — не для исправления распознавания: это тот же Whisper, он повторит те же ошибки |
| `find_noises(clip_id, threshold_db?)` | громкие места без речи — вшитые эффекты старого монтажа, шум, в игре — выстрелы (слитые отрезки, шкала `clip` — годятся прямо в `mute_audio`/`set_source_gain`; порог по умолчанию — медиана клипа без речи + 6 дБ; речь вычитается по субтитрам, без них — по своей дорожке речи) |
| `set_subtitle_words(clip_id, words)` | слова субтитров целиком: текст, время (шкала `clip` — ровно как в get_clip) и голос `s`/`speaker` (A/B/C/D: второй голос, TTS-донат — без Gemini) каждого слова; `[]` — убрать субтитры. Строки собираются сами: новая строка на конце предложения (`. ! ? …`), паузе > 0.6 с, смене голоса и после 7 слов; «какой» «-то» склеивается в «какой-то»; подсветка слов остаётся на тех же словах |
| `get_clip(clip_id)` | куски (`start_sec`/`end_sec` — время исходника, как в trim_piece и create_clip; `clip_start`/`clip_end` — шкала clip; у каждого — `focus`, `fit` и рамка героя `subject_box`), `framing.window_w` — доля ширины исходника в окне 9:16, настройки и каким пресетом отрендерится (`render.effective_preset`), слои, камера, вставки, вырезы, тишина и громкость исходника, субтитры со временем слов (шкала clip; 4-й элемент слова — голос), места для текста (`positions`: хук с `y_by_lines` и под полосой вебки в split), звуковые дорожки исходника (`source.audio`), `time_scales`, предупреждения |
| `get_transcript(clip_id, from_sec?, to_sec?)` | реплики исходника (время исходника) — для подрезки |
| `view_frame(clip_id, t, with_layers?, final?, subtitles?)` | **картинка** кадра готового вида (слои + камера + субтитры клипа, если включены — тот же ASS, что прожжёт рендер: видно наезд на HUD игры; `subtitles: false` — без них); `t` — шкала clip, с `final: true` — секунды готового ролика |
| `contact_sheet(clip_id, n?, times?, before_cuts?, subtitles?)` | **сетка** из n кадров по всему клипу — ритм графики и перегруз видно сразу (`vvf.py contact`); `times` — секунды ГОТОВОГО ролика (`final`, как подписи), с `before_cuts: true` — шкала clip, как у слоёв; субтитры клипа — как у `view_frame` |
| `suggest_cuts`, `apply_cuts` | найти и вырезать паузы/слова-паразиты (длинные паузы помечены `risky` — не режь вслепую); шкала clip, `cuts` из suggest_cuts можно передать в apply_cuts как есть (`piece` — чей вырез в зоне наплыва) |
| `auto_edit(clip_id, style?)` | автомонтаж без ИИ: хук, субтитры с эмодзи, наезды и удары по речи — основа для правки |
| `compose_cover(clip_id, t, title, style?, final?)` | обложка: кадр (t — шкала clip, `final: true` — готовый ролик) + крупный заголовок, включается сразу |
| `make_compilation(clip_ids, title?)` | новый клип «ТОП-N» из нескольких клипов проекта |
| `add_layers`, `update_layer`, `remove_layers`, `clear_layers` | моушн-слои (проверка `app/motion.py`) |
| `set_camera(keys)` | все ключи камеры разом (наезды); `zoom` 1..4 — камера только приближает, «отъехать» (zoom < 1) нельзя — шире окна делает `set_piece_fit` |
| `get_motion_reference` | шпаргалка по слоям |
| `list_fonts`, `search_emoji(q)`, `list_packs`, `search_pack(pack, q)` | шрифты, эмодзи, паки стикеров/звуков/мемов |
| `list_assets(q?)` | «Файлы для монтажа» владельца (asset_id) |
| `search_web_images(query, free_only)`, `add_image_from_url(url)`, `generate_image(prompt)` | найти/скачать/нарисовать картинку → asset_id |
| `upload_image(data_base64, filename, label?)` | своя картинка (скриншот сайта, сделанный у себя) → asset_id; GIF/APNG — ответ `animation` (кадры, fps, альфа): слой `image` играет её по кругу |
| `add_pngtuber(idle_asset, talk_asset, shout_asset?, track?, x?, y?, w?, start?, end?, threshold_db?, hold?, attack?, shout_db?, bounce?, flipX?, pixelated?, voice_asset?, id?, allow_multiple?)` | **PNGtuber**: аватар, который «говорит», когда звучит голос дорожки `track` (0 — игра, 1 — микрофон; `"speech"` — `speech_tracks`) — см. «PNGtuber» ниже; ответ `voice_check` — доля клипа с открытым ртом и выбранный порог. Один аватар на клип: повторный вызов заменяет прежний (второй — `allow_multiple: true`) |
| `upload_video(data_base64, filename, label?)` | своё видео (запись экрана приложения, .mp4/.webm/.mov, до 40 МБ) → asset_id для слоя `video`; больше — `vvf.py asset rec.mp4` или `POST /api/montage-assets` (до 300 МБ) |
| `add_video_from_source(source_id, start?, end?, label?, audio?)` | кусок исходника сервиса (запись, загруженная проектом через `vvf.py upload`) → видео в библиотеку (до 180 с, со звуком; `audio: false` — немое) → asset_id для слоя `video` (звук играет только с `props.audio: true`) |
| `add_video_from_url(url, start, end, label?)` | **отрезок ролика по ссылке владельца** (YouTube и всё, что умеет yt-dlp): скачивается только `start..end` (≤ 180 с, ≤ 1080p) тем же yt-dlp и прокси сервиса, что источники → видео со звуком в библиотеку → asset_id для слоя `video`. REST `POST /api/montage-assets/video-from-url {"url", "start", "end", "label"?}`, CLI `vvf.py asset-url URL --start 61 --end 79.5` |
| `auto_crop_layer(layer_id, aspect?, mode?, use_vlm?)` | **автофокус video-слоя**, чей файл шире окна (кусок ролика 4:3/16:9 во весь кадр): окно `props.crop` пропорции `aspect` (`"9:16"`; нет — как у нынешнего `crop`) и ключи `cropX` (`cropY` у высокого видео) по планам — склейки (как `auto_focus` + ffmpeg-детектор сцен) ключом со `ease: "step"` ровно на склейке, внутри плана окно плавно ведёт лицо/главный объект (`mode: "shot"` — одна рамка на план); Gemini по кадру на план — как у `auto_focus` (`use_vlm: false` — только CV). Учитывает `from`/`speed`/`loop`/`hold`, не больше 200 точек |

| `set_source_gain(ranges)` | громкость звука исходника на отрезках `[{start, end, gain_db}]` (шкала clip): поднять тихий кусок, приглушить громкий; в редакторе — группа «Громкость исходника» |
| `add_music_from_url(url, label?)` | трек фона по ссылке владельца (YouTube и т.п.) |
| `add_sound_from_url(url, label?, start?)` | звуковой эффект по ссылке владельца (страница freesound.org или видео), до 6 с → asset_id для слоя `audio` |
| `list_music`, `set_music(on, track_id, start_sec?)` | фоновая музыка (пак CC0 + загруженная владельцем), громкость сама под голос; `start_sec` — с какой секунды трека играть на 0 с клипа (в настройках клипа `music_start_sec`); у трека `energy_start_sec` / `drop_sec` / `bpm` — где кончается тихое вступление, самый сильный подъём, темп |
| `freeze_frame(at, duration?, audio?, layers?)` | стоп-кадр посреди ролика (`render.freezes`): кадр в `at` (шкала final — готовый ролик без стоп-кадров, как contact_sheet/listen) стоит `duration` 0.2–2.0 с (1 по умолчанию). `audio: "silence"` (по умолчанию) — вставка: звук исходника молчит, музыка играет, ролик длиннее, субтитры/слои/звуки/вставки/тишина после `at` сдвигаются сами; `"continue"` — звук идёт дальше, картинка продолжится с `at+duration`, длина та же. `layers: "freeze"` (по умолчанию) — слои, камера, анимированные субтитры стоят с кадром; `"continue"` — анимируются дальше. Тот же `at` — заменить, `remove: true` + `at` — снять один, `reset: true` — все. Проверка — `view_frame(t, final: true)`: при стоп-кадрах `t` — готовый ролик СО стоп-кадрами (`finished_with_freezes` в ответе) |
| `set_end_hold(sec)` | стоп-кадр в конце готового ролика на клип: `sec` 0..1.5 (`render.end_hold_sec`); мему — `0` (обрывается на последнем кадре); `reset: true` — как у сервиса (RENDER_END_HOLD_SEC). Разово для одного рендера — `POST /api/clip-plans/{id}/render {"end_hold_sec": 0}` или `vvf.py render 812 --end-hold 0` |
| `set_format(format, layers_format?)` | формат вывода **любого** клипа: `"9:16"` (как всегда), `"1:1"` (1080×1080), `"4:5"` (1080×1350), `"16:9"` (1920×1080) — из того же монтажа: видео кадрируется само, слои переносятся сами (см. «Форматы вывода»). `set_aspect(aspect)` — старое имя |
| `set_chroma_key(on, color?, similarity?, blend?, despill?)`, `set_backdrop(kind?, colors?, speed?, intensity?)` | персонаж на зелёнке: вырез и **анимированный** фон за ним (см. «Фоны»; слои за персонажем — `behind: true`) |
| `set_layout(mode?, cam?, ratio?, cam_pos?, pip?, …, game_x?, piece?)` | раскладка кадра: single, split (вебка полосой + игра), pip_cam, meme (`bg` — фон под видео, объект фона или имя стиля, см. «Фоны»); `game_x` — центр окна игры (см. «Стрим: раскладка split») |
| `list_brands`, `apply_brand(clip_id, brand_id)` | бренд заказчика: субтитры и хук в его цветах, логотип, призыв в конце, музыка, фон (см. «Бренд») |

Полный список с JSON Schema параметров: `GET /api/agent/tools`.

### Шкалы времени — одна таблица

У клипа четыре шкалы; каждый ответ инструмента называет свою (`time`). Почти всё — шкала **clip**.

| Шкала | Что это | Где |
|---|---|---|
| `clip` | секунды клипа ДО вырезов, С наплывами переходов (наплыв съедает секунды на стыке) | `get_clip`: `duration`, `pieces[].clip_start/clip_end`, слои, камера, вставки, `cuts`, `mute`, `gain`, субтитры (слова); `view_frame`, `compose_cover`, `at_word`, `find_noises`, `suggest_cuts`/`apply_cuts`, `set_subtitle_words`, `mute_audio`, `set_source_gain`, `add_insert` |
| `final` | секунды ГОТОВОГО ролика: после вырезов и наплывов | `finished_duration`; `contact_sheet` (подписи и `times`), `listen` — по умолчанию; у `view_frame`/`compose_cover` — с `final: true` |
| `source` | секунды исходника | `pieces[].start_sec/end_sec`, `trim_piece`, `create_clip`, `get_transcript`, `get_source_transcript`, `get_shots`, `source_loudness`, `source_contact_sheet`, `chat_activity`, `get_chat` |
| `piece` | секунды от начала куска | `pieces[].focus`, `set_focus` (`t`; или `source_t`) |

- Перевод между clip и final: `contact_sheet`/`listen` с `before_cuts: true` отвечают в clip, `view_frame`/`compose_cover` с `final: true` принимают final. Вырезов нет — clip и final совпадают.
- Вырезы и слова субтитров внутри хранятся «кусками подряд» (без наплывов, так их пишет редактор), но
  инструменты переводят сами: слово или вырез из `get_clip` отдавай обратно как есть.
- В зоне наплыва (последние `overlap` секунд куска на шкале clip) звучат хвост одного куска и голова
  следующего — момент оттуда без подсказки относится к следующему куску; у выреза подскажи `piece`.
  Лучше, чтобы речи в зоне наплыва не было: `set_transition` предупредит.

### Моушн-слои: шпаргалка

Контракт — [`docs/motion/spec.md`](motion/spec.md), схема полей — `GET /api/motion/schema`.

- Кадр 1080×1920; `x`, `y` — центр слоя в долях кадра; размеры — опорные пиксели.
- Время `start`/`end` — шкала **clip** (до вырезов, с наплывами; см. «Шкалы времени»); `keys` — время от начала слоя.
- Безопасная зона для текста: центр `y` 0.15–0.72; края текста не выше 10% и не ниже 80% кадра
  (внизу интерфейс площадки и субтитры, вверху шапка) — так же проверяет add_layers. Это 9:16; у 1:1, 4:5,
  16:9 — свои поля (см. «Субтитры, безопасные зоны, обложки»).
- Готовый ролик на 0.5 с длиннее клипа: в конце стоп-кадр, пока затухает звук (RENDER_END_HOLD_SEC;
  на клип — `render.end_hold_sec` 0..1.5, инструмент `set_end_hold`; мему — `0`, без «замирания»).
  Музыка (`set_music`) доигрывает на стоп-кадре и затухает к самому концу файла; голос и звук
  исходника затухают на конце клипа, без музыки стоп-кадр тихий.
  Слои, что идут до конца клипа, держатся и на стоп-кадре — финальную плашку ставь до конца.
  У слоя до самого конца (end ≥ длина готового клипа − 0.05) `out` не играет: он держится на
  стоп-кадре, а не гаснет перед ним. `out: null` или `{duration: 0}` — без анимации.
- Типы: `text`, `emoji`, `image` (`asset_id` или `src: "emoji:1f525" | "sticker:<pack>/<file>"`),
  `video` (видео из библиотеки: `asset_id`, `from`, `speed`, `loop`, `freeze`; по умолчанию немое, `audio: true` —
  со звуком, см. «Звук слоёв»), `shape` (arrow/ellipse/…),
  `counter`, `progress`, `chart`, `callout`, `audio` (`sfx:<pack>/<file>`). У `image` и `video` —
  `device: "phone"`: содержимое в корпусе телефона (см. «Промо приложения»).
- Вход/выход: `pop`, `words`, `typewriter`, `rise`, `slideUp`, `zoom`, `draw`…; постоянное: `pulse`, `wiggle`, `shake`.
  `rise` (только текст) — каждое слово по очереди выезжает снизу из-под невидимой маски своей строки
  (с плашкой — из-под её края) с проявлением: «дорогие» титры промо; на выходе — уходит под маску.
- **Скролл экрана внутри неподвижного телефона** (промо приложения): длинный скриншот — слой `image`
  с `radius` (обрезает картинку по скруглению) и окном `crop`; двигается не слой, а окно — ключи `cropY`
  (сверху вниз 0 → 1 − `crop.h`) при неизменных `w` слоя и `crop.h`. Высота окна под экран W×H:
  `crop.h` = (ширина картинки / высота картинки) · H / W. Листать экраны влево-вправо — склеить их в ряд
  и анимировать `cropX` (шаг = `crop.w`, `ease: "step"` — прыжком). Корпус телефона — `props.device: "phone"`
  (размеры корпуса — от `w`; `radius` не нужен — скругление экрана как у iPhone). То же у слоя `video`.
  ```json
  {"type":"image","start":2,"end":7,"x":0.5,"y":0.45,
   "props":{"asset_id":12,"w":560,"radius":56,"crop":{"x":0,"y":0,"w":1,"h":0.42}},
   "keys":{"cropY":[{"t":0.6,"v":0},{"t":2.4,"v":0.3,"ease":"outCubic"},{"t":3.4,"v":0.58}]}}
  ```
- Камера: `[{t, zoom 1..4, x, y, ease}]` — панч-ин на панчлайн 1.0 → 1.2–1.35 за 0.2 с.
  Между ключами значения (zoom, x, y, shake) переходят плавно; `ease` ключа A задаёт переход **от A к
  следующему** ключу (по умолчанию `inOutCubic`, есть `linear`, `outCubic`, `outBack`…). `ease: "step"` —
  держать значения A до времени следующего ключа и прыгнуть разом (жёсткий кадр без наезда, как склейка).
  До первого ключа и после последнего — их значения. Панч-ин: `[{t:3.0, zoom:1}, {t:3.2, zoom:1.3}, {t:4.2,
  zoom:1.3}, {t:4.5, zoom:1}]`; «скачок» крупности: `[{t:3.0, zoom:1, ease:"step"}, {t:3.5, zoom:1.3}]` —
  до 3.5 с крупность 1, на 3.5 с сразу 1.3.
  В раскладках `pip_cam` и `split` камера двигает только игру: окошко вебки/килфида и полоса
  вебки стоят на месте (`x`/`y` камеры — доли окна игры).
  Слои камера не трогает — кроме слоёв с `followCamera: true` (кратко `camera: "follow"`): они
  едут и зумятся вместе с видео в той же трансформации (с хромакеем — фон-скрин `behind` за
  персонажем, рамка/подпись у объекта на видео). Путь камеры в ключи слоя **не копируй** —
  ставь флаг. Без флага слой стоит на экране, как раньше (титры, субтитры, плашки).

```json
{"type":"text","start":0.0,"end":2.2,"x":0.5,"y":0.24,
 "props":{"text":"ОН ЭТО СДЕЛАЛ","size":100,"weight":900,"color":"#FFFFFF","stroke":{"color":"#000000","width":10}},
 "in":{"type":"words","duration":0.35},"out":{"type":"fade","duration":0.2}}
```

## Клипы без Gemini: сам выбираешь моменты

Анализ Gemini не обязателен. Чтобы нарезать исходник (серию, стрим) самому:

0. Исходника ещё нет — загрузи: `POST /api/sources` multipart с полем `file` (видео с диска;
   `vvf.py upload ролик.mp4`) или JSON `{"url": "..."}`. Ответ — JSON источника, его `id` — это
   `project_id`. Видео нет вовсе (промо из картинок) — см. «Пустой холст».
1. `GET /api/sources/{id}/transcript` — расшифровка всего исходника `[{start, end, text}]`
   во времени исходника. Первый раз — локальный Whisper **фоном** (минуты): запрос ждёт ≤ 45 с
   (`?wait=` до 55) и, если не готово, отвечает **202** с `Retry-After` и
   `{status: "running", done_min, total_min, retry_after_sec, note}` — повтори тот же запрос через
   `retry_after_sec`; повтор подключается к уже идущему распознаванию, второго не будет. Готово — 200
   и реплики из кэша. `?from_sec=&to_sec=` — только окно.
2. Выбери моменты: завязка → развязка, клип 30–75 с, самодостаточный. Посмотри кадры
   (`GET /api/sources/{id}/frame?t=`), чтобы смешное не было только в звуке.
3. `POST /api/sources/{id}/manual-clips` `{title, description?, pieces: [{start_sec, end_sec, title?}]}` —
   клип из кусков исходника (каждый 1.5–180 с, до 12; короткий кусок 1.5–3 с — отдельный кадр под широкий
   баннер или титр; 5 с — минимум только у хайлайтов анализа). Ответ — клип с `id`; дальше обычный цикл ниже.
4. Черновые моменты, которые не пошли, — удаляй: `DELETE /api/clip-plans/{id}` (готовые рендеры
   остаются). Не плоди у владельца список из десятков пробных клипов.

### Чат Twitch

У стрима с Twitch бывает импортирован чат зрителей: всплески сообщений и реакций (KEKW, «ахаха», «+»)
показывают, где был момент. Время чата — секунды исходника.

- `chat_activity(project_id, from_sec?, to_sec?)` — всплески: `windows` — горячие окна (`hype` 0..1, `top`
  — самая частая реакция), `buckets` — сообщений по минутам (на окне до 15 мин — по 10 с). Зрители пишут
  с задержкой 5–20 с: само событие чуть **раньше** всплеска — смотри расшифровку и кадры перед ним.
- `get_chat(project_id, from_sec, to_sec)` — сами сообщения `[секунда, кто, текст]` (окно до 15 мин):
  реакция зрителей — хорошая подпись или хук.
- Чата нет — ответ `has_chat: false`. Импорт — это запрос к Twitch (`POST /api/sources/{id}/chat/import`):
  **сам не импортируй** — спроси владельца; он запустит импорт, если разрешает. Подробно — `docs/twitch-chat.md`.
- REST: `GET /api/sources/{id}/chat/activity?bucket=60`, `GET /api/sources/{id}/chat?from=&to=`; слой
  `chat` (чат на экране) — шаблон «Чат стрима».

### Звуковые дорожки записи

Запись NVIDIA DVR / OBS часто несёт **две** звуковые дорожки: игру и микрофон. По умолчанию сервис
берёт первую — голос стримера тогда пропадает целиком. Сколько дорожек и какие выбраны — `get_clip`
(`source.audio`), `list_projects` (`audio_tracks`) или `GET /api/sources/{id}/audio`. Выбор хранится
у источника и действует везде: рендер, субтитры, `listen`, `find_noises`, `source_loudness`, расшифровка:

- `set_source_audio(project_id, tracks=[0, 1])` — смешать игру и микрофон (REST:
  `PATCH /api/sources/{id}/audio {"audio_tracks": [0, 1]}`); `[1]` — только микрофон; `[]` — по умолчанию;
- **громкость каждой дорожки**: amix сводит дорожки поровну, и микрофон на 15–25 дБ тише игры в смеси
  тонет. `tracks: [{"track": 0, "gain_db": 0}, {"track": 1, "gain_db": 14}]` — микрофон на 14 дБ громче;
  `"gain_db": "auto"` — сервис сам замерит дорожки (несколько окон записи по 0.25 с) и поставит голос на
  ~9 дБ громче остальных дорожек **в моменты речи**: игру меряет в те же окна, где звучит голос (когда
  стример говорит, в игре обычно стреляют — медиана игры за всё время занижала её и голос тонул).
  Усиление −12..+24 дБ; если пики усиленного голоса съедают запас нормализации (пик выше громкости смеси
  больше чем на 15.5 дБ — −14 LUFS при потолке −1.5 dBTP не дотянуть), усиление снижается, но голос
  остаётся не меньше чем на 4 дБ над игрой. Ответ: `auto_gain`, `auto[дорожка]` (`voice_db`/`others_db` в
  моменты речи, `over_db` — итоговый перевес, `speech_sec`, `peak_limited`, `note`) и `levels`. Хочешь
  точнее — сравни `source_loudness(track=0)` и `track=1` и задай число сам. Ролик потом всё равно
  выравнивается целиком до −14 LUFS: gain задаёт баланс голоса и игры, а не громкость ролика;
- **дорожка для распознавания**: `speech_tracks: [1]` — расшифровка исходника, субтитры клипа, `listen`
  и сверка субтитров в QC идут по одному микрофону (на смеси с игрой Whisper выдумывает фразы и режет
  речь кусками по 40–85 с). Рендер, `find_noises` и `source_loudness` — по смеси `tracks`. `[]` — как
  `tracks`. REST: `PATCH /api/sources/{id}/audio {"speech_tracks": [1]}`;
- сменился звук для распознавания — расшифровка исходника сбрасывается сама, а субтитры уже сделанных
  клипов распознай заново (`generate_subtitles`);
- не уверен, где что, — поставь `[1]`, послушай `listen` на отрезке, где должен быть голос, и
  верни как надо (`GET /api/sources/{id}/audio` покажет и подписи дорожек, если запись их хранит);
- один кусок клипа тихий (голос отошёл от микрофона) — `set_source_gain` на этом отрезке, а не дорожке.

Владелец видит и меняет то же в редакторе: группа «Звуковые дорожки» (галочки «в звук ролика»,
дБ на дорожку, «Авто: голос над игрой», дорожка речи). Выбор общий для источника — не меняй его
молча на чужой записи, если владелец уже настроил.

## PNGtuber — аватар, который говорит голосом дорожки

Аватар владельца в углу кадра: молчит — одна картинка/анимация, звучит его голос — другая (рот
открыт), громко — третья. Состояние по кадрам считает сервис по громкости дорожки голоса — агенту
ничего замерять не нужно.

1. Загрузи состояния в библиотеку: `upload_image` (GIF/APNG/PNG, до 12 МБ) или `vvf.py asset idle.gif` —
   ответ скажет «анимированная картинка: 5 кадров, 16.7 fps, с прозрачностью». Пиксель-арт (EmoteLab:
   112×112) так и оставь — сервис увеличит его без мыла.
2. `add_pngtuber(idle_asset, talk_asset, shout_asset?, track?)` — слой на весь клип, правый нижний угол
   над безопасной зоной (у 16:9 — левее водяного знака), `w` ≈ 300 px. Голос:
   - `track` — номер звуковой дорожки ИСХОДНИКА: запись NVIDIA/OBS — **0 игра, 1 микрофон** (сколько
     дорожек — `get_clip.source.audio`);
   - `"speech"` — дорожки распознавания речи источника (`speech_tracks` из `set_source_audio`);
   - не задан — `speech_tracks`, если они свои; иначе у записи с несколькими дорожками — 1; иначе звук
     клипа (игра и голос вместе — рот откроется и на взрывы: лучше разделить дорожки);
   - `voice_asset` — голос из файла библиотеки (секунда файла = время от начала слоя).
   Повторный `add_pngtuber` (с тем же `id` или без `id`) **заменяет** аватар клипа, а не добавляет
   второй; второй аватар (двое ведущих) — `allow_multiple: true`.
3. Порог «звучит голос» по умолчанию — `"auto"`: шум дорожки (15-й перцентиль громкости) + 12 дБ, в рамках
   **−55..−40 дБ** (тихая фраза на −42 дБ открывает рот, шум пустого микрофона — нет). Ответ
   `voice_check`: `talking_share` — доля клипа с открытым ртом, `threshold` — какой порог выбран и почему.
   Почти 0 — голос тише порога (`threshold_db` ниже, −50) или не та дорожка; почти 1 — порог ниже
   шума/игры (`threshold_db` выше, −35, или другая дорожка). Поправить — `update_layer(id, {props: {voice:
   {...}}})`, его ответ тоже с `voice_check`; место и размер — `x`, `y`, `props.w`.
4. Тонкая настройка: `hold` (0.18 с — рот не хлопает между слогами), `attack` (0.03 с — щелчок клавиатуры
   не открывает рот), `shout_db` (−12), `bounce` (px 0..40 — подскок в такт голосу), `flipX`,
   `pixelated: false` — сглаживать (фото-аватар).

Проверь `view_frame` в момент речи и в паузе: кадр агента считает голос вокруг `t`. Вырезы
(`apply_cuts`) и наплывы учитываются — рот остаётся на голосе.

Слой руками: `{type: "pngtuber", start, end, x, y, props: {states: {idle, talk, shout?}, voice: {track: 1},
w: 300, bounce: {amount: 8}}}`. Слой `image` с анимированным GIF/APNG тоже играет его по кругу с
прозрачностью (с начала слоя).

## Диалоги и многоплановые сцены (сериал 16:9 → 9:16)

Окно 9:16 видит треть ширины 16:9 (`get_clip.framing.window_w` ≈ 0.32). Мультфильм или сериал — это
смена планов каждые 2–5 с, и центр окна должен ехать за тем, **кто говорит в кадре**:

0. Сначала `auto_focus(clip_id)`: сам найдёт говорящего на
   каждом плане и поставит жёсткую смену на склейках. Проверь `contact_sheet` — и только промахи
   правь вручную по шагам ниже (Gemini в проверочном прогоне потратил 8 шагов на подбор x «на глаз»
   и всё равно попал в стену).
   Длинный план (≥ 3 с), где говорят по очереди, auto_focus делит по репликам субтитров (пауза
   больше 0.5 с или смена голоса `speaker`): Gemini смотрит кадр каждой реплики с её текстом, окно
   плавно (0.35 с, без `cut`) поворачивается к ответившему; в ответе `turns` — сколько таких
   поворотов. Поэтому **сначала субтитры** (и `separate_voices`, если голосов несколько), потом
   auto_focus. Без субтитров и при одном голосе в плане — один центр на план. Промах по
   реплике — `set_focus` с точками на смене говорящего вручную.
1. `get_shots(project_id, from_sec, to_sec)` — склейки планов в куске (секунды исходника; внутри
   клипа `project_id` можно не передавать — возьмётся источник клипа).
2. `source_contact_sheet(project_id, from_sec, to_sec, step, x)` по каждому плану: подбери `x`, при
   котором говорящий в окне (сетка с `x` показывает ровно то окно, что останется).
3. `set_focus(clip_id, piece, points)` — точка на начало каждого плана с `cut: true` (можно прямо
   `source_t` из `get_shots`), `x` — говорящий этого плана; внутри длинного плана, где говорят по
   очереди, — плавный переход без `cut` (0.3–0.6 с между точками) или `cut` на реплике.
4. Проверка — `contact_sheet` клипа или `view_frame` сразу после каждой склейки.

Двое по краям широкого плана (Рик слева, Морти справа) в окно не влезают, а камера только приближает
(`zoom` ≥ 1). Приёмы, по порядку предпочтения:

- **фокус на говорящего** с жёсткой сменой (`cut: true`) на его реплике — так монтируют диалог в
  вертикали; слушающий виден на соседнем плане;
- **быстрый переход** между ними без `cut` (0.3–0.5 с) — «камера поворачивается» к ответившему;
- **кусок шире окна** — `set_piece_fit(piece, w, bg)`: в кадре доля `w` ширины (≈0.6 — оба крупно,
  1 — весь кадр), сверху и снизу размытый фон; для общего плана, где важны оба сразу. Действует на
  весь кусок: нужен только на отрезке — вынеси его в отдельный кусок (файл клипа: раздели кусок на два
  встык). Раскладка клипа (split/pip/meme) на таком куске не действует; редактор владельца
  показывает такой кусок так же, как рендер (полоса видео на фоне), проверка — `view_frame`.

`subject_box` в `get_clip` — рамка героя на кадре 9:16: `positions.subject_box` — объединение по всему
клипу, `pieces[].subject_box` — по каждому куску. Внутри куска со сменой планов это тоже объединение и
ненадёжно — где персонажи на плане, смотри `source_contact_sheet`.

## Стрим: раскладка split (вебка полосой + игра)

`set_layout(mode: "split", cam_pos: "top"|"bottom", ratio)` — вебка полосой сверху или снизу, игра — остальное.

- **Камера двигает только игру.** Наезды `set_camera` зумят окно игры; полоса вебки стоит на месте
  (`x`/`y` камеры — доли окна игры). Что из игры попадает в окно — фокус кусков: `set_layout(game_x: 0.4)` —
  один центр на все куски (или `piece` — на один), трек по куску — `set_focus`.
- **Вебка.** `cam` не задан — берётся вебка источника (`POST /api/sources/{id}/detect-facecam`). Полоса
  заполняется вебкой целиком: если пропорции разные, лишнее срезается (широкая полоса режет высоту вебки —
  «лицо до лба»). `set_layout`/`get_clip` предупредят и подскажут `ratio` под пропорции вебки. Большая
  `cam` (шире 0.3 или выше 0.45 кадра) часто захватывает вшитый чат или оверлей — проверь
  `source_contact_sheet` и сузь `cam`.
- **Текст не на лице.** `get_clip.positions` учитывают раскладку: при вебке сверху хук стоит под полосой
  (`positions.hook.y`, `y_by_lines` и `cam_strip`), `add_layers` предупредит про текст на полосе вебки.
  Субтитры — на игре, при вебке снизу — над полосой (`positions.captions`).
- Проверка — `view_frame` на хуке и на пике наезда: лицо в полосе целиком, текст на игре.

## Игры и записи экрана (Apex Legends и т.п.)

Речи может не быть вовсе: `get_source_transcript` вернёт пустой список с `no_speech`, `listen` —
`words: []` и громкость. Это не ошибка. Моменты ищутся по звуку и картинке:

1. `source_loudness(project_id, from_sec, to_sec)` — окно до 10 мин; пики (`peaks`) и громкие отрезки
   (`loud`) над медианой — это перестрелки, взрывы, крики. 4-часовую запись проходи окнами подряд.
2. `source_contact_sheet(project_id, from_sec, to_sec, step)` вокруг пиков — что на экране; с `x` —
   как ляжет окно 9:16.
3. `create_clip` по найденным таймкодам; внутри клипа громкие места — `find_noises` (без субтитров он
   просто показывает громкие отрезки клипа).

Кадр и интерфейс игры:

- **Шутер от первого лица — окно на прицеле.** `auto_focus` в игре от первого лица ставит неподвижный
  x на прицел (≈ 0.5) без погони за движением (Apex без Gemini прыгал x 0.51–0.58 — прицел уезжал с
  центра). Игру узнаёт по названию у записи/клипа (Apex, Valorant, CS2, Call of Duty…) или по прицелу —
  неподвижному рисунку в центре, пока сцена вокруг движется; в ответе куска `first_person: {x, why}`.
  Явно — `auto_focus(first_person: true)`; герой в кадре (третье лицо) — `first_person: false`.

- **Килфид / HUD — окошком.** Важная часть интерфейса (лента убийств, счёт команд) в 9:16 не влезает —
  ставь её окошком: `set_layout` `mode: pip_cam`, `cam` = угол исходника, `pip` — куда в вертикальном
  кадре. Для Apex лента убийств: `cam {x: 0.70, y: 0.185, w: 0.245, h: 0.155}` (доли кадра исходника),
  окошко — `pip {x: 0.75, y: 0.2, w: 0.5}`. Камера (наезды) двигает только игру — окошко на месте,
  одно: зумится игра без окошка, само окошко берётся из незумленного кадра (рендер и `view_frame`).
- **Интерфейс игры не под субтитрами и титрами.** Прицел, полоски здоровья, миникарта — смотри
  `view_frame`/`contact_sheet` и ставь текст на пустое место (`positions` в `get_clip`).
- **Звуки-эффекты** в клипе без речи сервис ставит на 4 дБ ниже громких мест игры (не громче их);
  с речью — на 10 дБ тише голоса. Не задирай `volume` — выше 1 срезается.

### Приватность записей экрана

В записях экрана бывают окна рабочего стола: Alt-Tab, уведомления мессенджеров, браузер, личные
данные. Такие места в клип **не брать**: перед `create_clip` и перед рендером смотри кадры
(`source_contact_sheet` по всему куску, `contact_sheet` клипа). Попало в кусок — подрежь кусок
(`trim_piece`) или вырежи место (`apply_cuts`), а не прикрывай плашкой.

## Персонаж на зелёнке (хромакей)

Втубер или ведущий, записанный на зелёном/синем фоне, — основа без фона. Ключ хранится
у источника и ставится сам при загрузке (`chroma_key` в источнике; вручную —
`set_chroma_key` / `PATCH /api/sources/{id}/chroma-key`). С ключом:

- зелёнка вырезается при рендере; за персонажем — фон клипа `set_backdrop`: анимированный
  зацикленный (по умолчанию аврора в цветах ролика, см. «Фоны»);
- слой с `behind: true` лежит ЗА персонажем: скрин сайта, картинка, фон-мем можно во весь
  кадр — проверка «не закрывай видео» их не трогает. Слой без `behind` — поверх персонажа:
  на лице и теле ничего крупного;
- камера (`set_camera`) зумит вырезанного персонажа, а слои за ним стоят — сцена «плывёт».
  Слоям, которые часть сцены (скрин за персонажем, предмет в руке), ставь `followCamera: true`;
- крупность и место персонажа — `set_layout` `mode: meme`, `video_scale` 2–3 (видео шире
  кадра, края с зеленью срезаются), `video_y` — чтобы низ тела был у нижнего края;
- лук пресета (цвет, зерно, зеркало) ложится на персонажа после выреза; виньетки с ключом нет;
- вырезы на неподвижном персонаже видны как рывок головы («моргает на склейке»): короткие паузы
  не режь, длинные — только со сменой плана за персонажем или наездом камеры на стыке;
- проверяй `view_frame`: края персонажа без зелёной каймы (кайма — `similarity` выше, 0.3;
  рваные волосы — ниже);
- после выреза гасится зелёный ореол (`despill`): `"auto"` (по умолчанию) — полное подавление,
  оно же рыжит жёлтое и серит зелёное **во всём кадре** (жёлтая карточка → оранжевая, зелёная
  плашка → серая). Промо с жёлтыми/зелёными цветами, записи экрана — `despill: "none"`; ореол
  на волосах заметен, а цвета нужны — мягко, число 0..1 (`0.3`). В ключе источника
  `{color, similarity, blend, despill}`; в редакторе — «Раскладка» → «Подавление зелёного ореола».

## Фоны

Где нужен фон — за персонажем на зелёнке (`set_backdrop`), под/над видео раскладки meme
(`set_layout bg`), сверху и снизу куска «шире окна» (`set_piece_fit bg`) — **статичная заливка
только если владелец попросил**. По умолчанию — анимированный зацикленный фон в цветах ролика.
Фоны рисует код (без видеофайлов), одинаково в превью редактора и в рендере; цикл бесшовный.

Фон — объект `{kind, colors, speed, intensity}`:

- `kind`: `aurora` — плавные цветовые переливы (по умолчанию), `grid` — светящаяся неоновая
  перспективная сетка (едет на зрителя), `bokeh` — мягкие блики плывут вверх, `waves` — светящиеся
  линии-волны; `gradient` / `solid` — статичные (только по просьбе);
- `colors`: до трёх `#rrggbb` — `[тёмная основа, акцент, второй акцент]`; `[]` — в цветах ролика
  (тёмная основа + цвет звучащего слова субтитров); один цвет — акцент;
- `speed` 0.1..4 (1 — цикл 10 с), `intensity` 0..1 (яркость свечения, 0.7; под титрами 0.5–0.8).

Где угодно вместо объекта можно имя стиля строкой (`"grid"`). Старый `{color, color2}` /
`#rrggbb` читается как заливка/градиент. Подбор: неон-сетка — игры и техно; аврора и боке —
спокойнее, под разговор; фон не должен спорить с титрами. Проверка — `view_frame`.

## Пустой холст (промо из картинок, без видео)

Ролик из картинок, титров и музыки не требует исходника: `create_canvas_clip(duration, background?,
title?)` или REST `POST /api/canvas-clips` `{"duration": 20, "background": "grid", "title": "Промо"}`
(`background` — имя стиля или объект `{kind, colors, speed, intensity}`, см. «Фоны»; `name` — синоним
`title`). Ответ — клип (`id`, `editor_url`); дальше обычные инструменты клипа: `add_layers`
(картинки — `image`, записи экрана — `video` в телефоне, см. «Промо приложения», звуки — `audio`),
`set_music`, `set_backdrop` (сменить фон), рендер.

- Устроено как хромакей: основа — тихое зелёное видео 1080×1920, вырезается целиком, видно только
  фон клипа. Генерировать зелёное видео и грузить его источником самому больше не нужно.
- Холсты лежат в одном **скрытом** проекте (в `list_projects` и «Проектах» его нет; `project_id` —
  в ответе, `list_clips(project_id)` покажет все холсты).
- Проверка «не закрывай видео» на холсте не действует: картинка во весь кадр — это и есть монтаж.
- Звука исходника нет: громкость ролика задают музыка и звуки, финальный проход доводит до −14 LUFS
  с учётом пиков.
- Формат — не только 9:16: квадрат 1:1, 4:5 и 16:9 из того же монтажа (см. «Форматы вывода»).

### Квадрат 1:1, 4:5 и 16:9 (из того же монтажа)

Заказчик просит «ещё квадрат» или «горизонталь для YouTube» — монтаж не переделывается:
`set_format("1:1")` (или `"4:5"`, `"16:9"`), рендер; вертикаль — `set_format("9:16")` и рендер ещё раз.
Без смены настроек — REST `POST /api/clip-plans/{id}/render {"format": "16:9"}` или
`vvf.py render 812 --format 16:9`; в редакторе — «Формат» над кнопкой «Рендерить». Каждый рендер —
отдельный файл в рендерах клипа. Подробно — «Форматы вывода» ниже.

- Кадр 1080×1080 (1:1), 1080×1350 (4:5) или 1920×1080 (16:9), фон холста (`backdrop`) — на весь кадр.
- Слои **не трогай** — они остаются в опорном кадре своего формата разметки (`layers_format`, обычно
  9:16, 1080×1920) и переносятся при рендере и в `view_frame` (app/aspect.py): рамка содержимого (от
  верха самого высокого до низа самого низкого слоя, с ключами `y`) вписывается в новый кадр с полями
  4 % **одним масштабом** на весь ролик (не крупнее 1.25 × высота/1920: 0.70 в квадрате и 16:9, 0.88 в
  4:5). Положение и размеры внутри сцены сохраняются точно: титр не наедет на телефон, если не наезжал
  в 9:16, касания по экрану остаются на кнопках.
- Сцена — слои, что идут вместе по времени; у сцены с другой рамкой (концовка с логотипом) свой центр —
  она встаёт по центру кадра. Фоны во всю ширину (≥ 1060 px) остаются во всю ширину; вспышки
  (прозрачность кончается нулём — взрыв, кольцо касания) рамку не раздувают.
- Камера переносится вместе со слоями — её ключи тоже **не трогай**: центр наезда — та же точка
  содержимого, а слои `followCamera` (телефон, кольца касаний) при наезде целиком остаются в кадре с
  полями 4 %. Ради этого общий масштаб чуть меньше (не больше чем в 1.25 раза; в 574-м клипе 0.578 →
  0.564), а если и так не влезает — zoom ключа слабее; центр сдвигается ровно настолько, чтобы низ и верх
  телефона не ушли за край. Титр (он не едет с камерой) при наезде ложится на верх экрана телефона
  чаще, чем в 9:16 — держи под титрами затемнение, которое проявляется на наездах.
- Типичный промо с телефоном во весь рост выходит в квадрате с масштабом ≈0.57: заголовок 72 px → ≈41 px.
  Хочешь крупнее — делай отдельную вертикальную раскладку под квадрат (короче телефон / меньше этажей),
  а не правь опорные размеры под квадрат: они общие с 9:16.
- Проверка — `get_clip` (`render.format`, `render.frame`), `view_frame` на титрах, сменах сцен и
  концовке (кадр уже нужного формата). Превью в редакторе — тоже в формате клипа (с переносом слоёв).

## Форматы вывода

Сервис рендерит не только вертикаль: **9:16** (1080×1920, как всегда), **1:1** (1080×1080),
**4:5** (1080×1350) и **16:9** (1920×1080) — у любого клипа, с исходником или холста. Реестр —
`app/formats.py` (зеркало для превью и компоновщика — `frontend/src/motion/formats.ts`).

**Как хранится.** `render.format` — формат вывода клипа (нет — 9:16; старое поле `render.aspect`
читается как `format`). `render.layers_format` — в каком формате размечены слои (их опорный кадр;
нет — 9:16). Формат — настройка клипа: `set_format` (агент), `PATCH /api/clip-plans/{id}/render-settings`
с `{"settings": {"format": "16:9"}}` (редактор, который не шлёт `format`/`layers_format`, их не
сбрасывает), разово — `POST …/render {"format": "16:9"}` / `vvf.py render N --format 16:9`.
`get_clip` отдаёт `render.format`, `render.frame` ([ширина, высота]), `render.layers_format`,
`render.layers_ref`.

**Опорный кадр слоёв.** `x`, `y` слоя — доли кадра в любом формате; размеры (кегль, `w`, тени) — px
опорного кадра формата разметки: 9:16 — 1080×1920, 1:1 — 1080×1080, 4:5 — 1080×1350, 16:9 —
1920×1080 (короткая сторона везде 1080: кегль 96 — те же 96 px готового ролика). Слои размечены в
одном формате, рендер в другом — слои и камера переносятся сами (одним масштабом по сценам, см. выше),
в любую сторону, включая 9:16 → 16:9 и 16:9 → 9:16. Размечаешь слои сразу под 16:9 (опорный 1920×1080) —
скажи это: `set_format("16:9", layers_format="16:9")`; иначе слои считаются вертикальными.

**Видео (основа) по форматам:**

| исходник → формат | что делает рендер |
|---|---|
| любой → 9:16 / 1:1 / 4:5 | тот же умный кроп с фокусом (трек `focus`, автофокус), окно — пропорции формата |
| горизонтальный 16:9 → 16:9 | без кропа, scale до 1920×1080 |
| шире 16:9 (21:9) или 4:3 → 16:9 | окно 16:9 с тем же фокусом (у 4:3 срезается верх/низ по `crop_anchor`) |
| вертикальный / квадратный → 16:9 | целиком по высоте на размытой подложке того же кадра (с хромакеем — поля цвета ключа, за ними `backdrop`) |

**Раскладки в 16:9** (в 9:16 / 1:1 / 4:5 — как всегда, геометрия от размера кадра):
`split` (вебка сверху/снизу) → игра на весь кадр, вебка окошком в правом верхнем (`cam_pos: top`) или
правом нижнем (`bottom`) углу; `pip_cam` → окошко в ближайшем углу той же ширины в px, что в
вертикали; `meme` → обычный кадр (горизонтальное видео и так на весь кадр; слои-скриншоты
перекомпонуются); кусок «шире окна» (`fit`) не нужен — широкий план и так целиком. Хромакей и холст —
кадр формата, `backdrop` — на весь кадр.

**Что ещё не по формату.** Перекомпоновка 9:16 → 16:9 ставит монтаж колонкой по центру (масштаб по высоте),
а не раскладывает сцены по горизонтали; хочешь «настоящую» горизонталь — размечай слои в 16:9
(`layers_format`). Проверяй `view_frame` — он уже в формате клипа. Редактор (этап 2A) — в формате клипа:
превью, холст слоёв, окно кропа; слои другой разметки показаны перенесёнными (тот же расчёт, что у
рендера, — frontend/src/motion/reframe.ts), кнопка «Разметить слои в этом формате» сохраняет перенос
и `layers_format`; шаблоны слоёв вставляются под опорный кадр формата разметки. Субтитры, безопасные
зоны, линт, обложки и баннер — тоже по формату (ниже).

### Субтитры, безопасные зоны, обложки (этап 2B)

**Безопасные зоны площадок** — `app/safe_zones.py` (зеркало `SAFE_ZONES` в `frontend/src/motion/formats.ts`),
доли кадра:

| формат | площадки | текст по высоте | по ширине | субтитры не ниже | ещё |
|---|---|---|---|---|---|
| 9:16 | Shorts / Reels / TikTok | 0.10–0.80 (шапка, подпись и кнопки) | не проверяется | 0.82 | как всегда |
| 1:1, 4:5 | лента Instagram / Telegram | 0.05–0.95 | 0.05–0.95 | 0.94 | интерфейса поверх нет, превью режут углы |
| 16:9 | YouTube | 0.05–0.95 | 0.05–0.95 | 0.93 | правый нижний угол (x 0.86–0.985, y 0.78–0.97) — водяной знак канала и длительность на превью |

Зона берётся по формату **разметки слоёв** (`layers_format`: в его опорном кадре стоят слои): её
проверяют `add_layers`/`update_layer`/`get_clip` (текст у краёв, в углу водяного знака, субтитры-слой ниже
зоны — с числом «подними до y≤…»/«сдвинь до x≥…»), линт промо (геометрия в опорном кадре формата),
`get_clip.frame` (`width`/`height` — опорный кадр слоёв, `safe_zone`; слои и рендер в разных форматах — ещё
`render_format`, `render_safe_zone`), `positions` (хук, `text_band`), бренд (логотип, плашка призыва),
шпаргалка ИИ-монтажёра (`motion_reference`). У 9:16 ответы и предупреждения — слово в слово прежние.

**Субтитры (прожиг ASS).** PlayRes — кадр формата. Кегль, обводка и тень — от короткой стороны кадра (как
px слоёв: у всех форматов 1080 — те же px, что в вертикали). Поля по бокам — от ширины: в 16:9 строка не
шире 64 % кадра (поля 346 px), в 1:1/4:5 — 80 px; переносы и караоке-страницы (2 строки) считаются по
этой ширине. Отступ снизу: `sub_pos_pct` — доля высоты кадра формата (разовый рендер в другом формате —
та же доля), без него — отступ стиля в px кадра 1920 переводится долей; и не ниже «субтитры не ниже» из
таблицы. Слой `captions` в 1:1/4:5/16:9 поднимается движком до той же границы. `get_clip.render.subtitle_zone`
— полоса субтитров в долях кадра формата. Превью субтитров (`subtitlePreview.ts`, аргумент `format`) —
те же правила. 9:16 — побитно как раньше (эталоны `tests/test_format_golden*.py`).

**Обложка и баннер.** `compose_cover` рисует титр сразу в опорном кадре формата клипа (16:9 — кегль 150,
строка до 1600 px, в зоне YouTube) и сохраняет JPEG размера кадра: 16:9 — 1920×1080, превью YouTube.
`POST /api/covers` принимает `format` или `clip_plan_id` (без них — 1080×1920, как всегда); рендер всё
равно подгоняет обложку под кадр. Баннер — доля высоты кадра формата, как в вертикали; вне 9:16 — не шире
90 % кадра.

**Раскладка стрима.** Вне вертикали px раскладки (`gap`, `border.width`) — по короткой стороне (рамка 6 px
в 16:9 — 6 px); полоса вебки split в 1:1/4:5 — во всю ширину кадра формата (`facecam_warnings` считает
обрез по ней), в 16:9 полосы нет (окошко в углу). `framing.window_w` в `get_clip` — окно формата клипа.

**Заготовка промо (`build_app_promo`) по форматам — решение.** 9:16 — как всегда; 1:1 и 4:5 — заготовка
размечает слои в опорном 9:16 (`layers_format` 9:16 — инструмент ставит его сам, если своих слоёв нет), при
рендере они переносятся в кадр формата одним масштабом (ответ называет это в `format`). **16:9 — честный
отказ** с объяснением: приёмы эталонов (телефон во весь рост, титр над ним, наезд на кнопку) держатся на
высоком кадре, а горизонтальная раскладка (телефон сбоку, титры рядом, финал по центру) — отдельная
работа, не втиснутая в заготовку. Что делать: собрать в 9:16 и `set_format("16:9")` (колонка по центру),
или вручную слоями с `layers_format` 16:9.

### ИИ, анализ и публикация по форматам (этап 2C)

- **ИИ-монтажёр** (чат редактора, `app/ai/editor_agent.py`) берёт формат из клипа на каждом вызове модели:
  кадр W×H, опорные px разметки (`layers_format`), правила раскладки (16:9 — хук сверху, субтитры снизу,
  титры/мемы/телефон в боковой трети, вебка окошком в углу; 1:1 и 4:5 — компактнее по высоте). Слои
  размечены в другом формате — он знает, что они перекомпонуются сами, и их не трогает; слоёв нет —
  сначала `set_format(fmt, layers_format=fmt)`. Формат выбирает владелец: `set_format` без просьбы не
  зовётся. Клип без `format` — промпт слово в слово прежний (снимок `tests/fixtures/editor_prompt_9x16.txt`).
  `get_motion_reference(format?)` и инструкции MCP — кадр из формата клипа.
- **Анализ и выбор моментов**: `POST /api/sources/{id}/analyze {"format": "16:9"}` (или настройка приложения
  `analysis_format`; нет — 9:16, запрос модели прежний). Другой формат дописывает модели блок OUTPUT FORMAT:
  16:9 — обычное видео, не шортс, клип до `LANDSCAPE_MAX_CLIP_SECONDS` (настройка `landscape_max_clip_sec`;
  по умолчанию прежние 180 с, «до нескольких минут» — задать больше); 1:1/4:5 — те же короткие ролики для
  ленты. ✨ выбор лучших (`ai-pick`, `format?`) и 🤖 ИИ-монтаж (по формату клипа) — та же логика длины.
- **Фокус**: `app/formats.focus_needed` — у 16:9 из горизонтального исходника (и вертикального — он
  целиком на подложке) фокус не нужен: `auto_focus` отвечает `focus_needed: false`, анализ не просит
  трек фокуса. 1:1/4:5 — окно своей пропорции (подсказка Gemini в `vlm_focus`/`subject_box` называет формат).
- **Публикация** (`app/publish_format.py`): формат — по размеру готового файла клипа. YouTube: 16:9 —
  **обычное видео** (из заголовка/описания убирается `#shorts`, горизонтальная обложка клипа ставится
  миниатюрой), 9:16/1:1/4:5 — Shorts, как раньше. TikTok: 16:9/1:1/4:5 публикуются с предупреждением
  (ждёт вертикаль, покажет с полосами). Instagram: 9:16 — Reels, 1:1/4:5 — пост в ленту, 16:9 — в ленту
  с предупреждением (Reels только вертикальные). Проверка до публикации — `GET /api/clips/{id}/publish-check?targets=1,2`
  (`publish_as`: shorts | video | reel | feed | tiktok, `warnings`); `posts-batch` отвечает `format_warnings`.
  ✨ метаданные (`publish-meta`) у 16:9 пишут заголовок/описание обычного ролика YouTube, без `#shorts`.

## Промо приложения: запись экрана в телефоне

Промо приложения (Collabika и т.п.) собирается целиком в сервисе: записи экрана в корпусе телефона,
нарезка по 1–3 с, свайпы, наезды — на пустом холсте.

### Заготовка одним вызовом: `build_app_promo`

Сильная основа по приёмам эталонных промо (клипы 574, 579; модуль `app/promo_scaffold.py`) — сначала она,
потом точечные правки; слоями с нуля промо не собирают. На клипе-холсте (`create_canvas_clip`):

```json
{"spec": {
  "brand": {"accent": "#FF6A1F", "dark": "#0b1018", "font": "Nunito"},
  "hook": ["Ищешь коллаб?", "Хватит ждать.", "Свайпай."],
  "scenes": [
    {"asset_id": 147, "from": 0, "to": 5, "title": "Листай VTuber'ов — свайпом", "focus": {"x": 0.5, "y": 0.55}},
    {"asset_id": 148, "from": 0.3, "to": 4.4, "title": "Открой анкету", "focus": {"x": 0.5, "y": 0.95}},
    {"asset_id": 149, "from": 1, "to": 7.6, "title": "Зови на коллаб — в пару тапов",
     "focus": {"x": 0.5, "y": 0.86}, "window": {"x": 0.04, "y": 0.32, "w": 0.92, "h": 0.3}, "climax": true},

```

| поле | что это |
|---|---|
| `duration?` | 20–40 с; не задано — по длинам сцен. Холст подгоняется по сетке долей |
| `brand` | `accent` (обязателен), `text`, `dark`, `font` (по умолчанию Unbounded), `weight` |
| `hook` | 1–3 удара по 1–3 слова — каждый на свою долю, крупно (110–140 px) над телефоном первой сцены |
| `scenes[]` | 1–6 сцен: `asset_id` записи, `from`/`to` — секунды записи; `title` 2–6 слов (« — » делит на строку и акцент); `focus {x, y, t?}` — доли экрана записи, куда наезд и касание (`t` — секунда нажатия в записи: она встанет на долю наезда); `window {x, y, w, h}` — окно записи (доли её кадра) с результатом; `climax: true` — одна |
| `end` | `logo_asset_id`, `lines` (дата/оффер, до 2), `cta` (ссылка на плашке), `sub?` |
| `music` | `{track_id, start_sec?}` или `null`; bpm, `energy_start_sec`, `drop_sec` берутся из библиотеки |
| `background?`, `variant?` | фон холста (как `set_backdrop`); другая раскладка поз |

Что делает (Collabika выше, 122 BPM, доля 0.49 с): 0–3.9 с хук — три удара на долях 0/2/4, телефон первой
сцены въезжает снизу, последний удар акцентом со вспышкой и кольцом; 3.9–23.6 с пять сцен по долям — телефон
по центру крупно → слева → справа (наклон ±7°, въезд-свайп со своей стороны, выезд перед следующей), наезд
камеры до 1.3× на `focus` на сильной доле с кольцом касания (глубина подобрана, чтобы корпус не уходил за
кадр), титр сцены над телефоном с затемнением; 13.8 с — кульминация на первой доле такта: окно записи
(crop `window`) с ударом-наездом, вспышка, кольцо, частицы за окном, бас-дроп; 23.6–27.5 с финал — логотип с
частицами, строки, плашка CTA с пульсом и кольцом; тихие звуки (вжухи на свайпах, хлыст на окне, райзер в
хук, киношный вжух в финал, поп на плашке); музыка — дроп трека на кульминацию, иначе с `energy_start_sec`.
Результат проходит проверку слоёв и линт промо без предупреждений (~46 слоёв, ~22 ключа камеры).

Все слои заготовки — с именем «promo: …»: повторный вызов заменяет только их (свои слои остаются), камеру —
целиком. `dry_run: true` — план без применения. Ответ: число слоёв, сцены по секундам, кульминация, финал и
`next` — на каких секундах смотреть `view_frame` и что подстроить.

### Вручную (правки поверх заготовки)

Без обещаний: суммы начислений, бонусов и сроки («+100 ✦ за новость») в титры и счётчики не выносим,
даже если бриф заказчика их разрешает (владелец убрал их из промо VTubika News) — говорим качественно
(«получаешь баллы»), а такие строки внутри записи закрываем плашкой цвета фона приложения.

1. Холст: `create_canvas_clip(duration: 20, background: "aurora", title: "Промо")` — клип без исходника
   на анимированном фоне (см. «Пустой холст»).
2. Записи в библиотеку: `vvf.py asset rec.mp4 -l "Экран задач"` (любой размер, до 300 МБ) или
   `upload_video` (base64 до 40 МБ); запись уже загружена проектом (`vvf.py upload`) —
   `add_video_from_source(source_id, start, end)`. Ответ — `asset_id`, `duration_sec`, размер.
3. Слои `video` с `props.device: "phone"` — по слою на кусок записи.

```jsonc
// add_layers: три куска записи (монтаж ≈ 2 + 1.8 + 2.5 с): свайп между экранами, наезд, заголовок НАД телефоном
[
 {"type":"video","name":"Экран: вход","start":0,"end":2,"x":0.5,"y":0.6,"track":1,
  "props":{"asset_id":41,"from":3.2,"w":600,"device":"phone","deviceColor":"#2c2c2e"},
  "in":{"type":"slideUp","duration":0.45},"out":{"type":"none"},
  "keys":{"x":[{"t":1.65,"v":0.5,"ease":"inCubic"},{"t":2.0,"v":-0.5}]},          // свайп: уезжает влево
  "shadow":{"color":"#000000","blur":70,"x":0,"y":34,"opacity":0.55}},
 {"type":"video","name":"Экран: лента","start":1.65,"end":3.5,"x":0.5,"y":0.6,"track":2,
  "props":{"asset_id":41,"from":11,"w":600,"device":"phone"},
  "keys":{"x":[{"t":0,"v":1.5,"ease":"outCubic"},{"t":0.35,"v":0.5}]},             // …следующий въезжает справа
  "in":{"type":"none"},"out":{"type":"none"},
  "shadow":{"color":"#000000","blur":70,"x":0,"y":34,"opacity":0.55}},
 {"type":"video","name":"Экран: кнопка (наезд)","start":3.5,"end":6,"x":0.5,"y":0.6,"track":1,
  "followCamera":true,                                                            // наезд — камерой (ниже)
  "props":{"asset_id":42,"from":0.5,"speed":1.5,"w":600,"device":"phone"},
  "in":{"type":"pop","duration":0.3},"out":{"type":"fade","duration":0.25},
  "shadow":{"color":"#000000","blur":70,"x":0,"y":34,"opacity":0.55}},
 {"type":"text","name":"Заголовок","start":0.2,"end":6,"x":0.5,"y":0.12,"track":3,  // над корпусом (верх ≈ 0.25)
  "props":{"text":"Задачи — в одном месте","size":64,"weight":900,"maxWidth":900,"backdrop":true},
  "in":{"type":"rise","duration":0.5}}
]
// set_camera: наезд на кнопку — телефон с followCamera едет с камерой, заголовок стоит
// [{"t":3.8,"zoom":1},{"t":4.6,"zoom":1.3,"x":0.5,"y":0.62,"ease":"inOutCubic"},{"t":5.6,"zoom":1.3,"x":0.5,"y":0.62}]
```

- **Время файла**: в момент `start` слоя виден кадр записи на секунде `from`, дальше
  `from + (t − start)·speed` (`speed` 0.25..4). Запись кончилась: `freeze` (по умолчанию) держит
  последний кадр, `loop: true` — снова с `from`, `freeze: false` — тёмный экран.
- **Нарезка = несколько `video`-слоёв подряд** (конец одного = начало следующего, одна дорожка) с разными
  `from`. Склейка жёсткая (`in`/`out` `none`) или с въездом `slideUp`/`slideLeft`/`pop` 0.25–0.35 с.
  Один длинный кусок без склеек выглядит как скринкаст — режь по 1–3 с на действие.
- **Свайп между экранами** — ключи `x` слоя: старый телефон уезжает влево (0.5 → −0.5 за ~0.35 с,
  `inCubic`), следующий слой на дорожке выше въезжает справа (1.5 → 0.5, `outCubic`) — слои перекрываются
  на время свайпа. **Скролл** внутри неподвижного телефона — окно `crop` и ключи `cropY`: нужна запись
  (или скриншот) выше экрана; окно под пропорции экрана `crop.h` = (ширина файла / высота файла) · 19.5/9
  (меньше — экран телефона станет ниже). Обычная запись экрана свайпы и скролл уже содержит — просто
  правильный `from`.
- **Наезд** — камера (`set_camera`, zoom 1.2–1.35 на кнопку) + `followCamera: true` у телефона и колец
  касаний: на холсте камера двигает основу под фоном и слои с `followCamera`, титры и фон стоят
  (параллакс). Можно и ключами `scale`/`y` самого слоя. Проверь `view_frame` на пике наезда: корпус в
  кадре (иначе предупреждение «за краем кадра»), заголовок, под который заезжает телефон, — с `backdrop`.
- **Строка статуса** — в записи нет своей (запись приложения/эмулятора начинается с шапки) —
  `props.statusBar: true`: полоса «9:41 · связь · батарея» над записью, островок в ней. Без `statusBar`
  у `video` островка нет (он лёг бы на шапку приложения); `island: true` — вернуть явно.
  `statusBarColor` — цвет полосы (белая — значки чёрные), `screenGlare: true` — блик стекла.
- **Стоп-кадр** — `props.hold: true`: весь слой держит кадр секунды `from` («замереть на экране оплаты»,
  подпись поверх). Рендер режет один кадр.
- **Заголовок над телефоном при наезде** — у текста `props.backdrop: true` (или `{opacity: 0.7, spread: 120}`):
  мягкое затемнение-градиент за буквами — телефон заезжает под титр, а титр читается.
- **Кульминация / итог** — один слой `particles` вместо десятков звёздочек: `{"type":"particles","start":5.6,
  "end":7,"x":0.5,"y":0.45,"track":4,"props":{"kind":"burst","count":120,"colors":["#ffd400","#ffffff"],
  "spread":420,"glow":true}}`; `sparkle` — мерцание вокруг (держи весь кусок), `confetti` — финал, `rise` —
  искорки вверх под CTA. Символы `✦ ★ ♥ → ✓` прямо в тексте можно — рисуются векторно цветом текста.
- **Пределы**: до 200 слоёв в клипе (сверх — `add_layers` откажет и скажет, сколько осталось), 120 ключей
  камеры, 200 точек на свойство. Предупреждение «перегруз ≤ 3 слоя графики» не считает фон и декор:
  фигуры, частицы, `behind`, полупрозрачные картинки во всю ширину, а на холсте — любые картинки/видео
  во всю ширину и телефоны (`device`) — это сама сцена промо.
- **Корпус** — `device: "phone"`: тёмный металл с бликом по краю, узкая рамка, кнопки, «островок»
  (`island: false` — без него), цвет `deviceColor` (`#2c2c2e` чёрный титан, `#8a857c` натуральный,
  `#d9d6cf` белый, `#2f3b4c` синий). Размеры корпуса — от `w` (ширина экрана); экран — пропорции
  записи (или окна `crop`). Тень — силуэт корпуса.
- **Запись экрана — немой `video`** (без `audio`): музыка — `set_music`, акценты — слои `audio`.

### Звук слоёв: эффект, дорожка, звук видео

- **Эффект** — слой `audio` без `mode` (или `mode: "effect"`): сервис сам ставит громкие места звука на
  10 дБ тише голоса клипа; `volume` 0..1 — только тише (больше 1 схема срежет до 1 и скажет; раньше схема
  пускала 2, а рендер молча резал). Так бум/свист никогда не перекроет речь.
- **Дорожка** — `audio` с `mode: "track"` (песня, звук чужого ролика, подложка): без автоподгонки,
  громкость = `volume` 0..2 × `gain_db` −30..+12 (вместе не громче +12 дБ), края с фейдом 15 мс (нет щелчка).
  Общую громкость ролика всё равно выравнивает финальная нормализация клипа (−14 LUFS).
- **Звук видео** — у слоя `video` `props.audio: true` (+ `volume` 0..2 / `gain_db`): звук файла входит в микс
  рендера дорожкой, ровно с той секунды, что и картинка (`from`, сдвиг на `start`, `speed` через atempo,
  `loop` — по кругу от `from`). Тишина: `hold` (стоп-кадр), `speed` вне 0.5–2, за концом файла без `loop`.
  Отдельный `audio`-слой со звуком того же ролика (wav, вынутый ffmpeg'ом) больше не нужен. Без `audio` —
  немое, как раньше: старые клипы не меняются. В превью редактора видео-слой звучит только с
  `audio: true` и включённым звуком превью; в инспекторе — «Звук видео», у звука — «Дорожка».
- Пример мема (клип 582): ролик и припев — два `video`-слоя со звуком, окно припева — `auto_crop_layer`:

```json
[
  {"id": "kid_video", "type": "video", "start": 0, "end": 24.5,
   "props": {"asset_id": 199, "w": 1080, "audio": true}},
  {"id": "chorus_video", "type": "video", "start": 24.5, "end": 43.27,
   "props": {"asset_id": 201, "from": 0.73, "w": 1080, "audio": true, "gain_db": -6}}
]
```

  затем `auto_crop_layer("chorus_video")` (окно 9:16 и ключи `cropX` по планам) и `set_end_hold(0)`.
- Проверка «не закрывай видео» на холсте не действует; на обычном клипе видео-слой — такая же
  «картинка» (≤ 40 % кадра). Проверяй `view_frame` — кадр рисуется с нужным кадром записи.
- В редакторе: «Мемы и картинки» → «📤 Своя картинка / видео» — видео сразу встаёт слоем в телефоне;
  шаблон «Запись экрана в телефоне» (категория «Промо»).

### Чек-лист промо и предупреждения линта

Проверочный прогон Gemini (клип 575) собрал промо новыми инструментами, но слабее эталона (клипы 572/574):
заголовки шагов легли на экран телефона, логотип финала влетел поверх не ушедшего телефона, ссылка в
финале бледная, хук висел все 18 с, музыка шла с тихого вступления. Перед отчётом:

1. **Хук 2–4 с**, дальше заголовки шагов **над** телефоном: верх корпуса y ≈ 0.22–0.25 (телефон w 580–600
   на y ≈ 0.6), заголовок y ≈ 0.10–0.14 с `props.backdrop` — не на экране (он закрывает интерфейс).
2. **Наезд** — `set_camera` + `followCamera` у телефона; `view_frame` на пике наезда — корпус в кадре.
3. **Сцены разводи**: телефон уходит (`end`/выезд) до входа логотипа; вместе внахлёст — не дольше 0.3 с.
4. **Финал ≥ 3 с**: логотип, дата **и время** («1 ноября, 19:00 МСК»), плашка CTA (`shape` rect или `text`
   с `bg` акцентного цвета) и ссылка ≥ 44 px (лучше 56) белым/контрастным — не цветом пятен фона.
5. **Музыка** — `list_music` → `set_music(start_sec=energy_start_sec)`, а не с тихого вступления.
6. `view_frame` на 3–4 ключевых секундах (хук, шаг, пик наезда, финал) и исправь предупреждения.

Предупреждения (`get_clip`, `add_layers`, `update_layer`; не ошибки) — на холсте или когда в клипе есть
телефон (`device: "phone"`); на обычных клипах со стримов эти правила молчат:

| Предупреждение | Когда | Что делать |
|---|---|---|
| `титр … на экране телефона` | текст закрывает экран телефона больше чем на 15 % своей площади дольше 0.3 с (с затемнением `backdrop` на наезде ключом `scale` — можно; на наезде камерой `followCamera` — нет) | поднять титр: в ответе `y ≤ …` (зазор ≥ 24 px от верха корпуса) или уменьшить/опустить телефон; на наезде камеры — меньше `y` камеры или `zoom` |
| `… за краем кадра на N %` | телефон/крупная картинка по ключам `x`/`y`/`scale` (и камере у `followCamera`) выходит за кадр больше чем на 12 % площади; въезд/выезд ≤ 0.5 с у краёв слоя и растворение не считаются | меньше `scale`/zoom, сдвинуть `x`/`y` |
| `… вместе и внахлёст … переход сцен без разведения` | телефон и другая крупная сцена (картинка ≥ 40 % ширины, логотип) видны вместе > 0.3 с с пересечением > 25 % меньшей | раньше `end` (выезд) первой или позже `start` второй; окно записи (`crop` той же записи) поверх своего телефона — не нахлёст |
| `в финале шрифт N px` / `контраст …` / `сольётся` | текст последних 4 с мельче 44 px, контраст к основе фона < 3:1 (к своей плашке < 2.5:1) или цвет как у пятен фона | крупнее, белый/яркий, плашка `bg` |
| `хук … висит N с поверх M смен сцен` | текст с первых 0.5 с живёт > 6 с, а под ним меняются сцены | хук 2–4 с, дальше заголовки шагов |
| `Музыка: первые N с музыки тихие` | трек играет с тихого вступления (`energy_start_sec` трека дальше `music_start_sec`) | `set_music(start_sec=energy_start_sec)` |
| `пустой кадр A–B с: нет слоёв — проверь, применились ли последние пачки` | на холсте дольше 1 с не видно ни одного слоя, кроме фона (учитываются `start`/`end`, половины `in`/`out`, ключи `opacity`/`scale`, выезд за кадр; частицы и субтитры не считаются) | проверить `skipped` последнего `add_layers`, дослать пропущенные слои или продлить сцену |
| `нет финала: в последних 4 с …` | промо с телефоном: в последних 4 с ни картинки-логотипа (`image` без `device`), ни текста/плашки `callout` со ссылкой или призывом | финал ≥ 3 с: логотип, дата, плашка CTA и ссылка |

`add_layers` применяет пачку частично (прогон 578: финал из 9 слоёв отклонили целиком из-за одного
`sfx:freesound/success.ogg`, агент не повторил — ролик кончился пустым фоном). Битый слой (неизвестный
`sfx:`/`sticker:`, нет файла `asset_id`, неверный тип, неверные значения) пропускается, остальные встают;
ответ — `partial: true`, `applied: "применено N из M"`, `skipped` — причина по каждому `layers[i]` и как
исправить (для неверного звука — 5 похожих по написанию из паков, difflib). Ни один слой не прошёл или
пачка превышает лимит слоёв клипа — ошибка целиком, как раньше. Перенос строки в тексте — настоящий `\n`
в JSON; литеральные «\n», «\\n», «\N» в `text`, подписях счётчика, плашки и графика нормализация
превращает в перенос («\t» — в пробел), иначе капс рисовал «\N» прямо в кадре.

Телефон на холсте — сама сцена, в «перегруз ≤ 3 слоя графики» не считается (на смене сцен их два).

## Бренд (повторяющийся заказчик)

Когда роликов для одного заказчика много (реклама магазина VTuber-моделей и т.п.), их стиль
задан **брендом**: шрифт, цвета (текст, акцент, плашка), логотип, вид субтитров и хука,
концовка-призыв (`cta`: текст, адрес, сколько секунд), трек, фон за персонажем, политика
эффектов (`none` / `minimal` — не больше двух). Бренды заводит и правит владелец
(Настройки → Бренды, `/api/brands`); агент их только смотрит (`list_brands`) и применяет.

`apply_brand(brand_id)` (REST: `POST /api/clip-plans/{id}/apply-brand {brand_id}`):

- перекрашивает все слои `captions` (стиль, шрифт, цвет; звучащее слово — акцентом, выделенные слова —
  вторым цветом бренда `colors.highlight` или контрастным к звучащему: не тем же акцентом, иначе
  подсветки не видно)
  и хук (`auto_hook` или первый текст в первые 3 с); текст и тайминг не трогает. Слоя субтитров
  нет, а речь есть — ставит свой `brand_caps`;
- ставит логотип маленьким в верхнем углу — после хука и до призыва, видео не закрывает;
- ставит призыв на последние `cta.duration_sec` **готового** ролика (с учётом вырезов) — над
  субтитрами, мимо героя, если его рамка известна; на зелёнке плашка уходит за персонажа
  (`behind`), текст — поверх;
- включает трек бренда, ставит фон за персонажем (и под видео раскладки meme) — анимированный в цветах
  бренда, снимает лишние эффекты по политике.

Применяй **после** монтажа (автомонтаж, хук, вырезы, подрезка): бренд красит то, что есть.
Повтор безопасен — слои бренда (`brand_*`) снимаются и ставятся заново, дублей нет; поменял
концовку или вырезы — просто примени ещё раз. Ctrl+Z откатит одним шагом.

После — проверь: `view_frame` на концовке (время — в `check` ответа): призыв читается и не
лежит на лице; при нужде `update_layer brand_cta {y}` (на зелёнке — и `brand_cta_plate`; повторный
`apply_brand` вернёт место по умолчанию). И `view_frame` в середине — логотип не
спорит с титрами. Предупреждения ответа (`warnings`) — читай: нет логотипа/трека, призыву не
нашлось места.

## Цикл работы

0. **Глянуть, что заходит.** Перед монтажом нового клипа — `get_performance` (MCP) или
   `GET /api/stats/clips`: просмотры и лайки опубликованных клипов рядом с признаками их
   монтажа. Повторяй приёмы топа, избегай того, что общее у антитопа. Числа сервис
   собирает сам раз в `STATS_INTERVAL_HOURS` (6 ч), вручную — кнопка «Обновить статистику»
   на странице «Публикации» (`POST /api/stats/refresh`). Смотри на `views_per_day` и
   `age_days`: вчерашний клип не сравнить с месячным; клипов с числами меньше 4 — выводов не делай.
1. **Выбрать клип.** `vvf.py clips <проект> --favorites` — избранные (★) владелец
   отметил как годные. ⚙ значит, что у клипа уже есть свои настройки рендера.
2. **Забрать файл.** `vvf.py pull <клип> -o clip.json`.
3. **Посмотреть материал.** Файл — это цифры. Прежде чем их менять, посмотри на картинку:
   - `vvf.py frame <проект> --at <секунда> -o f.jpg` — кадр исходника целиком;
   - `vvf.py frame <проект> --at <секунда> --x 0.62 -o c.jpg` — ровно то окно 9:16,
     которое останется при фокусе `x`.
4. **Поправить файл** (правила ниже).
5. **Проверить:** `vvf.py check clip.json`. Сервер перечислит ВСЕ проблемы сразу.
6. **Применить:** `vvf.py push clip.json --write-back`. Файл применяется целиком или
   не применяется вовсе. `--write-back` перезапишет его свежей версией с сервера,
   например с id новых кусков.
7. **Отрендерить:** `vvf.py render <клип>`. Рендер синхронный: команда ждёт готового
   видео и печатает отчёт о качестве (QC).
8. **Проверить результат.** Посмотри QC, при сомнениях скачай видео
   (`vvf.py download <рендер> -o out.mp4`) и посмотри кадры. Дальше повтори с шага 4.

## Файл клипа (`vvf.clip/1`)

```jsonc
{
  "schema": "vvf.clip/1",
  "clip_id": 812,                 // только чтение
  "source": { "id": 50, "duration_sec": 15050, "width": 1280, "height": 720, ... },  // только чтение
  "title": "Прерогатива Чугуняшки",
  "description": "…",
  "favorite": true,
  "notes": "почему смонтировано так — оставь заметку для человека",
  "pieces": [                     // куски клипа по порядку
    { "segment_id": 1201, "title": "Повод", "start_sec": 2963.0, "end_sec": 2981.5,
      "focus": [{ "t": 0, "x": 0.71 }, { "t": 6.2, "x": 0.35, "cut": true }],
      "fit": null }                // или { "w": 0.6, "bg": "blur" } — кусок шире окна 9:16
  ],
  "render": {                     // настройки рендера ЭТОГО клипа
    "preset_id": 3, "mirror": false,
    "subs_on": true, "sub_id": 2, "sub_engine": "", "sub_pos_pct": 12,
    "banner_on": false, "banner_id": null, "banner_height_pct": 14, "banner_pos_pct": 4,
    "music_on": false, "track_id": null,
    "transition": { "type": "fade", "duration": 0.35, "audio": "smooth", "sfx": "whoosh", "sfx_volume": 0.5 },
    "cover": { "mode": "frame", "piece": 0, "offset": 2.4, "image": "", "burn": true, "burn_sec": 0.1 },
    "layers": [ { "type": "text", "start": 3.2, "end": 6.0, "x": 0.5, "y": 0.3,
                  "props": { "text": "ПАНЧЛАЙН" }, "in": { "type": "pop", "duration": 0.35 } } ],
    "camera": [ { "t": 4.0, "zoom": 1.0 }, { "t": 4.3, "zoom": 1.35, "y": 0.4 } ]
  },
  "renders": [ { "clip_id": 431, "status": "succeeded", "qc": { ... } } ]   // только чтение
}
```

Схема целиком: `vvf.py schema`.

### Правила

- **Куски.** Каждый кусок длится от 5 до 180 с и лежит внутри исходника; всего до 12 кусков.
  - Оставь `segment_id`, чтобы менять существующий кусок.
  - Убери `segment_id`, чтобы добавить новый.
  - Не перечисляй кусок, чтобы убрать его из клипа.
  - Порядок в списке — это порядок в клипе.
- **Общий кусок копируется сам.** Если кусок используется ещё в другом клипе, при
  изменении таймкодов сервер сделает копию: чужой клип не пострадает.
- **Кадрирование.** Кадр 9:16 вырезается из широкого исходника, и `x` — центр
  этого окна по ширине (0 — левый край, 1 — правый).
  - `focus` — трек точек `{t, x}` от начала куска, камера плавно ведёт между ними; `cut: true` означает резкую смену кадра в этой точке.
  - Одна точка `[{ "t": 0, "x": 0.4 }]` — неподвижный кадр на весь кусок.
  - Можно писать короче: `"manual_x": 0.4` вместо `focus`, сервер сам превратит это в трек из одной точки.
  - Не указывай `focus`, если не меняешь его: трек останется прежним.
  - `fit` — кусок шире окна: `{w 0.35..1, bg blur|aurora|grid|bokeh|waves|{фон}|black|#rrggbb}` (или просто число `w`), `null` —
    обычный кадр; не указан — без изменений. Через MCP — `set_focus` и `set_piece_fit`.
- **Переходы** работают, только если кусков больше одного.
  - Типы: `cut`, `fade`, `fadeblack`, `fadewhite`, `flash`, `slide`, `smooth`, `wipe`, `zoom`, `dissolve`.
  - `audio`: `smooth` (звук перетекает, на резкой склейке нет щелчка) или `hard`.
  - `sfx` — звук на каждом стыке: `none`, `whoosh`, `click`, `pop`.
- **Обложка** (`render.cover`):
  - `mode`: `none`, `frame` — момент самого клипа (`piece` — номер куска с 0, `offset` — секунды от его начала), `image` — загруженная картинка (`POST /api/covers`, в `image` пишется имя, которое вернёт сервер).
  - `burn: true` кладёт обложку на первые `burn_sec` секунд ролика (0.04–0.5): площадки, которые берут превью с первого кадра, покажут её.
  - Готовая обложка лежит в `renders[].cover_url`.
- **Моушн-слои и камера** (`render.layers`, `render.camera`): титры, плашки, стикеры,
  стрелки, счётчики, графики, звуки на акценты и наезды камеры. Контракт —
  `docs/motion/spec.md`, схема полей — `GET /api/motion/schema`.
  - Время слоя — секунды готового клипа (`start`/`end`), `x`/`y` — доли кадра 9:16.
  - Проверить без сохранения: `POST /api/clip-plans/{id}/layers/validate`; посмотреть
    кадр: `POST /api/clip-plans/{id}/motion/frame?t=3.2` (PNG).
  - Ошибки формы слоёв отклоняют файл клипа целиком — сервер перечислит все.
- **Раскладка стрима** (`render.layout`): самый частый формат стрим-шортсов — вебка
  сверху, игра снизу.
  - `mode`: `single` (обычный кадр 9:16, по умолчанию), `split` (вебка полосой сверху
    или снизу, `cam_pos: top|bottom`, `ratio` 0.2–0.6 — её доля высоты), `pip_cam`
    (обычный кадр + вебка окошком: `pip {x, y, w}` — центр и ширина в долях кадра 9:16).
  - `cam {x, y, w, h}` — где вебка в исходнике (доли всего кадра). Найти сама:
    `POST /api/sources/{id}/detect-facecam` (вернёт `{cam, confidence}` и запомнит
    на источнике); сохранённая — `GET /api/sources/{id}/facecam`.
  - `border {color: "#rrggbb", width}` и `gap` — рамка вебки и зазор (px кадра 1080×1920).
  - В `split` трек `focus` ведёт окно игры (оно шире 9:16), `x` значит то же самое.
  - Камера (`render.camera`) в `split` и `pip_cam` зумит только окно игры; полоса и окошко вебки
    стоят на месте (компоновщик кладёт их поверх из незумленного кадра).
- **Не трогай** `clip_id`, `source`, `renders`: сервер их игнорирует.
- **Не рендери всё подряд.** Рендер длинный. Меняй один клип, рендери, проверяй.

## Что обычно улучшает клип

- **Хук в первые 1–2 секунды.** Если лучшая фраза или реакция в середине, поставь
  этот кусок первым либо подрежь `start_sec` начального куска к моменту, где уже
  что-то происходит.
- **Мёртвое начало и хвост.** Паузы, «эээ», переход к другой теме — подрезай.
  Смотри тишину в QC: `тишина N с на T с`.
- **Лицо или действие вне кадра.** Возьми кадры через `frame --x`, подбери `x` так,
  чтобы главное было в центре окна. Если объект перемещается, задай `focus` с 2–4
  точками. Если говорящий не двигается, хватит одной точки (`manual_x`).
- **Склейка разных сцен.** Встык даёт резкий перескок, `fadeblack` 0.3–0.5 с читается
  как «прошло время». Для мемного монтажа подходят `flash` или `zoom` со `sfx: whoosh`.
- **Субтитры.** Для шортсов почти всегда включать: большинство смотрит без звука.
- **Обложка.** Бери кадр с яркой эмоцией или самым смешным моментом, не первый попавшийся. Смотри кандидатов через `frame --x` и вшивай (`burn: true`).

## Подводные камни (собрано по отзыву агента-монтажёра)

- **Время после вырезов.** Слои, камера, вставки, субтитры и сами вырезы задаются на шкале
  **clip** — до вырезов (`duration` из `get_clip`), с наплывами переходов (см. «Шкалы времени») — при
  рендере они сдвигаются сами, а то, что целиком внутри выреза, пропадает (хук с 0 с остаётся в начале).
  Если вырезы есть, `get_clip` отдаёт `cuts` и `finished_duration` — длину готового ролика.
  Вставка, через которую проходит вырез, укорачивается на его длину.
- **Переход не на речь.** Наплыв (`fade`, `fadeblack`…) занимает последние `duration` секунд куска и
  первые следующего: слова там уходят под переход (на `fadeblack` — речь на чёрном). `set_transition` и
  `get_clip` предупредят, какие слова и как поправить: короче переход (`fit_speech: true`) или продлить
  кусок `trim_piece`, чтобы фраза кончилась до стыка.
- **GIF — только вставкой.** Слой `image` рисует первый кадр (гифка будет стоять);
  анимированные гифки и видео-мемы — `add_insert` (mode `pip`). `scale` у вставки —
  доля **ширины** кадра (0.5 = полкадра), высота по пропорциям. Окошко само
  отодвигается от хука, субтитров и крупных титров.
- **Правка кусков и субтитры.** Подрезал, переставил или выкинул кусок — субтитры переезжают
  сами: каждое слово привязано к секунде исходника и едет со своим куском, слова из
  отрезанного пропадают. Распознавать заново нужно только если кусок РАСШИРИЛИ на новую
  речь (get_clip предупредит: «речь есть, а субтитров нет»; смех и междометия — фразы короче 0.6 с
  или из одного слова — не в счёт). Слои, камера, вставки и
  вырезы тоже едут за своими кусками (кроме перестановки кусков — тогда проверь руками).
- **На слово, а не на секунду.** Звук, титр или мем ровно на слово: в add_layers/add_insert вместо
  start/at передай `at_word: {line, word}` (номера из get_clip.subtitles) или `{text: "Артас", nth: 2}`;
  `word_offset: -0.1` — чуть раньше слова, `duration` — длина слоя, `until_word` — держать слой
  до начала другого слова (титр ровно до следующей реплики). Не больше 30 слоёв за вызов.
- **Послушать, а не гадать.** `listen` (без параметров — последние 6 с) распознаёт звук ГОТОВОГО
  клипа с вырезами: договорена ли развязка, сколько тишины после последнего слова, не торчит ли
  слово из выреза. Сверять им субтитры бесполезно: это тот же Whisper, он ошибётся так же —
  неверное слово исправляй по смыслу сцены (`set_subtitle_words`). `contact_sheet` с `times` — кадры в нужные моменты (все панчлайны, финал).
  `times` у `contact_sheet` — секунды ГОТОВОГО ролика (после вырезов, как подписи на листе); чтобы
  проверить слой по его `start`, передай `before_cuts: true` — тогда секунды ДО вырезов, как у слоёв,
  камеры и `view_frame`.
- **Видео не закрывать.** Владелец: «плашки перекрывают видео — говно». Картинки, скрины и плашки —
  на пустом месте, не больше 40 % кадра непрозрачно (больше — add_layers откажет). Нужно много места
  под скрины — раскладка «Мем» (видео сверху, фон снизу), а не панель поверх кадра.
- **Звуки.** Только настоящие записи: пак `freesound` (`search_pack freesound`, слой `audio`
  с `asset_id: "sfx:freesound/<файл>"`). **0–2 эффекта на ролик**, только на смене смысла
  (не на каждом слове), ровно на слово (`at_word`). Громкость сервис выравнивает сам от голоса
  ЭТОГО клипа — эффект на 10 дБ тише речи, volume выше 1 срезается; ставь 0.3–0.6. В клипе без речи
  (игра, музыка: субтитров нет и в расшифровке исходника на кусках ни слова) «голос» — это громкие
  места самого клипа, и эффект ставится на 4 дБ ниже них (не громче), а не на 10. Что когда:

  | Момент | Звук |
  |---|---|
  | переход, смена темы | `whoosh-soft` (мягкий), `whoosh-cinematic`, `whoosh-1` (короткий), `whip` (резко) |
  | нагнетание перед развязкой | `riser-subtle`, `riser` — конец райзера ровно на панчлайне |
  | панчлайн, вывод | `impact-low`, `drama-boom` (вайн-бум, мемно), `sub-drop`, `bass-drop` |
  | шок, «вот это поворот» | `braam`, `impact-cinematic`, `sting`, `hit-transition` |
  | резкая остановка, «стоп, что?» | `record-scratch` |
  | смешно / удивление / фейл | `laugh-small`, `laugh-sitcom`; `crowd-gasp` (ох!); `crowd-aww` (оу-у); `sad-trombone` |
  | победа, успех | `applause`, `cheer` |
  | скриншот, фото | `camera`, `camera-2` |
  | цена, деньги | `cash`, `cha-ching` |
  | появление плашки | `pop-soft`, `pop` |
  | напряжённая пауза | `tension` |

  Интерфейсных «дзынь/клик/треугольник» и мультяшных боингов в паке больше нет — владелец назвал их
  дешёвыми (старые ссылки на них играют замену); паки Kenney с UI-звуками не бери. Нужен конкретный
  звук, которого нет, — только по ссылке владельца: `add_sound_from_url(url, label)` (страница
  freesound.org или видео; `start` — с какой секунды), сам звуки в интернете не ищи.
- **Музыка.** `list_music` → `set_music(track_id)`: тихий фон под голос (громкость сама, под речью
  приглушается). Для рекламы и рассказа — почти всегда; бодрый трек под бодрую подачу.
  Музыка играет с начала трека; длинное тихое вступление — `set_music(track_id, start_sec: 12.5)`:
  на 0 с клипа звучит 12.5 с трека (сразу барабаны/дроп; с петлёй следующий круг — с начала трека).
  Где вступают барабаны, сервис знает сам: `list_music` отдаёт у трека `energy_start_sec` (с какой
  секунды громкость держится у «рабочей» — конец тихого вступления), `drop_sec` (самый сильный подъём)
  и `bpm` (темп, если пульс слышен). Считаются при загрузке трека (файл, ссылка), у старых треков —
  лениво при первом `list_music`/`set_music` (по одному). `set_music` отвечает `track_energy` и на
  холсте/промо — `hint` «энергичная часть с X с: set_music(start_sec=X)»; сам `start_sec` не меняет.
  `get_clip` на промо предупреждает «первые N с музыки тихие». Промо и холст — почти всегда
  `start_sec = energy_start_sec`; под голосом стрима тихое вступление не беда. В редакторе это
  «Старт трека» и «Старт отсюда» с плеера. Новый трек без `start_sec` — с начала.
- **Концовка = развязка.** Владелец: «концовки бессмысленные». Клип кончается на панчлайне,
  реакции, выводе или фейле — и 0.5–1 с реакции после. Не на нейтральной фразе и не на первых
  словах новой темы: такое отрезай. Не попала развязка — продли последний кусок до неё. Не обрывай
  на последнем слове (get_clip и trim_piece предупредят про полуслово).
- **Строки субтитров.** После распознавания (`generate_subtitles`) и `set_subtitle_words` строки
  собираются из слов: новая строка на конце предложения (`. ! ? …`), паузе > 0.6 с, смене голоса и
  после 7 слов; каждое слово — ровно в одной строке; оторванные Whisper дефисные части («какой -то»,
  «кунг -фу», «ну -ка») склеиваются в одно слово с общим временем.
- **Фантомы и время слов — сервис сам.** Строки, которые Whisper (и Gemini голосов) выдумывает на
  тишине — «Субтитры сделал DimaTorzok», «Продолжение следует…», «Спасибо за просмотр» — и любой
  сегмент, на время которого дорожка речи тише порога речи (авто-порог, как у голоса PNGtuber),
  выкидываются из субтитров, `listen` и расшифровки исходника; «речь есть, а субтитров нет» по
  ним не приходит. Начала слов прилипают к началу звука дорожки речи (микрофон; без `speech_tracks`
  при смеси игры и микрофона — дорожка, похожая на голос), а внутри сплошной речи сдвигаются на
  ту же поправку, на какую распознавание спешило у слов после пауз. Вручную сдвигать все субтитры
  на +0.25 с не нужно.
- **Подсветка слов.** В стилях `hormozi`, `mrbeast`, `karaoke` звучащее слово и так жёлтое — жёлтые
  `highlightWords` на нём не видны (add_layers/get_clip предупредят). Ключевые слова — контрастным:
  `#FF3B30` (эмоция, мат), `#22C55E` (смысл). Задавай подсветку словом — `{text: "дорого", nth: 1, color}`
  вместо номера `i`: метка хранит якорь (текст и время слова) и после `set_subtitle_words`,
  `generate_subtitles`, правки строк и вырезов остаётся на том же слове (слова нет — метка снимается).
- **Хук сверху.** `positions.hook.y` (0.13) — для одной строки 96 px. Две строки — центр ниже
  (`positions.hook.y_by_lines`: ≈0.158, три — ≈0.187): верх текста не выше 10% кадра. add_layers
  оценивает перенос по `maxWidth` и кеглю и предупредит, если верх текста выше зоны. В split с вебкой
  сверху `positions.hook` уже под полосой вебки (`text_band.top`), а не на лице.
- **Голоса в субтитрах.** У слова может быть `speaker` (A — главный, B/C/D — гость,
  донат-TTS, ролик). Слой `captions`: `speakers: ["A"]` — показывать только эти голоса,
  `speakerColors: [{s, color}]` — цвет слов голоса (по умолчанию у не-A свой цвет).
  Голоса размечает `separate_voices` (нужен Gemini) или ты сам: `set_subtitle_words` с `s` (или
  `speaker`) у слова — второй голос и TTS без Gemini.
- **Без Gemini (нет ключа / кончились кредиты)** работают: распознавание речи
  (локальный whisper — сервис переключается сам), поиск картинок (`search_web_images`
  ищет в Imgflip-мемах и Wikimedia Commons; гифки — через Giphy, если задан
  `GIPHY_API_KEY`; запросы лучше по-английски), слои, камера, вставки, рендер, QC.
  Не работают: анализ, «ИИ выбирает», встроенный ИИ-монтажёр, `separate_voices`,
  рамка героя (`subject_box`) и проверка «картинка про запрос?» (пропускается).
- **Минимальная длина куска — 5 с.** Короткие реплики вырезай `apply_cuts` внутри куска,
  а не отдельными кусками.

## QC — что значит отчёт

| Замечание | Что делать |
|---|---|
| `чёрный кадр N с на T с` | подрезать кусок или сдвинуть границу |
| `картинка стоит N с` | подрезать; если это пауза, убрать её |
| `тишина N с на T с` | подрезать, особенно в начале и конце |
| `тихо: −23 LUFS` / `пережато: −7 LUFS` | площадки ждут около −14: проверить пресет и музыку. Готовый файл тише цели при запасе по пикам сервис сам поднимает ещё одним проходом (после лимитера, до −1.8 dBTP); финальный звук — AAC 256k (на 192k кодек добавлял к пику до +2.3 дБ, лимитер опускался и громкость терялась: промо 575 вышло −16.2 LUFS) |
| `пик … dBFS` | true peak готового файла: лимитер держит −1.5 dBTP (работает на ×4 частоте, файл перепроверяется и при перебое пересобирается); если всё же пик — тише музыка или громкость эффекта |
| `длиннее 3 минут` | YouTube не примет как Shorts: сократить |
| `размер …, обычно 1080×1920` | выбрать пресет 1080×1920 (1080×1080 и 1080×1350 холста — заказанный формат, не замечание) |
| `субтитры спешат/опаздывают на N с` | сверено по дорожке речи (если она своя — `speech_tracks`) или по громкости; в игре, где выстрелы громче голоса, сверка по громкости не делается вовсе — поставь `speech_tracks`, чтобы проверка была |

`ok: true` в отчёте означает, что предупреждений нет.

## Чего не делать

- Не писать в базу и файлы сервиса напрямую: только API.
- Не удалять избранное владельца и не снимать ★ без причины.
- Не менять `render.preset_id` на пресет, которого нет. Список пресетов: `GET /api/ffmpeg-presets`
  (`default: true` — пресет, которым рендерится клип с `preset_id: null`). Клип из `create_clip` сразу
  получает пресет по умолчанию числом.
- Публиковать клипы на площадки может только человек (кнопка «Опубликовать» в сервисе).
