# Будущий ресерч: публикация в TikTok через настоящий телефон (ADB)

Статус: **отложено** — владелец 02.11.2026: «Запиши как будущий ресерч». Не начинать без его команды.

## Идея

Владелец подключает к компьютеру ненужный Android-телефон с приложением TikTok, где выполнен
вход в его аккаунт. Сервис публикует ролики через само приложение, как человек:

1. `adb push` готового mp4 в галерею телефона и запуск сканирования медиа.
2. Открыть загрузку TikTok системным «Поделиться» (`ACTION_SEND`, пакет `com.zhiliaoapp.musically`).
3. Пройти экраны приложения: подпись, хештеги, обложка, «Опубликовать». Управление через
   uiautomator2/Appium или тапы ADB, каждый шаг проверяется скриншотом экрана (`adb exec-out screencap`).
4. Убедиться, что пост вышел (профиль, «Публикации»), и записать ссылку в сервис.

Почему это может помочь: жалоба из `docs/design/publishing-review-2026-11.md`. Загрузки с ПК
набирали около 0 просмотров, а с телефона руками больше. Здесь работает настоящее приложение на
настоящем телефоне, без подделки мобильного клиента (подделка запрещена условиями TikTok и грозит
баном).

## Что нужно от владельца

- Только Android: с iPhone без джейлбрейка/Mac автоматизация сильно сложнее.
- Вход в TikTok в приложении. Отладка по USB включена, разрешение для компьютера подтверждено.
- Телефон всегда на зарядке, экран без PIN или «не блокировать при зарядке».

## Риски и вопросы для ресерча

- Обновления интерфейса TikTok ломают селекторы. Нужны устойчивые якоря (resource-id, тексты)
  и запасной поиск по скриншоту.
- Капча и подтверждение входа делает человек, нужен канал «позови владельца» в TG.
- Антибот: человеческие паузы, не пачками, лимит постов в день. Выяснить, видит ли TikTok
  ADB/accessibility-автоматизацию и есть ли случаи банов.
- Честный A/B со способом публикации из «публикационного ревью»: телефон-автомат против телефона
  руками против браузера.
- Встраивание в сервис: новый способ публикации «телефон» рядом с браузерным. Очередь, одна
  публикация за раз, отчёт со скриншотом.
