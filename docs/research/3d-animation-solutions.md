# Готовые решения для «крутой» анимации 3D-персонажей

Дата ресерча: 12.11.2026. Для владельца, простым языком.
Задача: персонажи VRM в three.js сейчас двигаются слабо (несколько записей CMU, ручные позы, рот только по громкости, почти нет «живости»). Ниже что можно взять готовым, а не писать с нуля.

Как читать таблицы:
- **Лицензия для коммерческих видео**: да / нет / неясно. Если я не смог прочитать первоисточник, так и написано «неясно» или «по вторичным источникам».
- **Сложность подключения** к нашему конвейеру (node/vrm, three.js + three-vrm 3.5.5, headless Chromium, покадровый рендер): низкая / средняя / высокая.

Про то, что у нас уже есть: пакет `@pixiv/three-vrm` 3.5.5 умеет «пружинные кости» (волосы, одежда), взгляд (lookAt) и выражения лица. Так что часть «живости» вообще не нужно искать, это включается.

## 4. Губы и лицо из звука (липсинк)

В VRM есть стандартные выражения рта: `aa`, `ih`, `ou`, `ee`, `oh`. Задача: по звуку определять, какое сейчас, вместо «чем громче, тем шире».

|---|---|---|---|---|---|---|---|
| **wLipSync** (порт uLipSync для веба) | В браузере по звуку (WebAudio + WASM, MFCC) вычисляет смесь гласных A/I/U/E/O | Хорошее для гласных, язык не важен (подходит для русского после калибровки профиля) | Бесплатно | **Да.** MIT (проверено через GitHub API); оригинал uLipSync тоже MIT | Прямое соответствие: A->`aa`, I->`ih`, U->`ou`, E->`ee`, O->`oh` | Средняя: работает в реальном времени через AudioWorklet, а у нас покадровый рендер, поэтому либо заранее считать полосу за один прогон (OfflineAudioContext), либо переписать расчёт на Node | https://github.com/mrxz/wLipSync |
| **Rhubarb Lip Sync** | Готовая программа: звуковой файл -> список «мгновенная форма рта A-H и X» с временем (TSV/JSON/XML) | Хорошее по времени. | NVIDIA Audio2Face-3D | Звук -> 52 блендшейпа в стиле ARKit, с эмоциями | Очень высокое | Бесплатно (SDK и модели открыты в 2025) | **Да, с условиями.** SDK: MIT; модели: «NVIDIA Open Model License»; модель эмоций Audio2Emotion имеет отдельные ограничения (запрет использования вне Audio2Face и для распознавания эмоций) | Только на моделях VRM с «perfect sync» (ARKit-блендшейпы). ## Рекомендуемый стек (в порядке подключения)

Принцип: наибольший скачок качества при наименьшей работе.

1. **Библиотека клипов (CC0 + Mixamo).** Скачать Quaternius UAL 1 и 2 (бесплатные стандартные наборы), KayKit и несколько десятков клипов Mixamo (скачивает человек, вручную, из своего аккаунта; без скриптов). Прогнать все через единый перенос на VRM, как делает `tools/cmu_to_vrm.py`. Сразу появляется выбор из 300+ движений вместо 5. Время: 1-2 дня.
2. **Слой «жизни» поверх любой анимации.** Дыхание, моргание, саккады, взгляд на камеру/собеседника, плавные входы и выходы между клипами (перекрёстный фейд 0.2-0.3 с), включённые пружинные кости. Это самый дешёвый способ убрать «манекенность». Время: 1-2 дня.
3. **Липсинк по гласным.** Rhubarb или wLipSync вместо громкости, с таблицей на `aa/ih/ou/ee/oh` и сглаживанием. Время: 1-2 дня. Проверка на русской речи обязательна.
4. **Движение с телефона.** Подписка на 1 месяц на DeepMotion (коммерческая лицензия включена) или Rokoko Vision Basic; снимаем себя 5-10 раз (стоя, жесты, ходьба), получаем FBX/BVH, перенос на VRM. Сравниваем с библиотекой. Время: 2-3 дня на пробу.
5. **Текст -> движение, пробой.** Если у владельца есть видеокарта на 17+ ГБ: Kimodo (SOMA, лицензия NVIDIA Open Model), перенос SOMA -> VRM. Использовать для редких действий. Время: 3-5 дней, результат неопределён.
6. **Позже:** Audio2Face-3D, только если появятся VRM с «perfect sync» блендшейпами.

Конкретные следующие шаги:
- Проверить у владельца, какая видеокарта (для пунктов 5 и 6).
- Скачать пробные паки UAL 1 и KayKit и перенести 10 клипов на нашу VRM-модель, показать видео.
- Написать слой «жизни» (пункт 2) в `node/vrm/src/rig.ts`.
- Прогнать Rhubarb на 3 готовых озвучках и сравнить со старым ртом.
- Прочитать условия (ToS) на сайте выбранного мокап-сервиса и сохранить копию.

## Чего НЕ брать и почему

- **GVHMR** (видео -> SMPL): лицензия «educational, research and non-profit purposes only».
- **Любая цепочка на SMPL/SMPL-X без отдельной лицензии Meshcapade** (в том числе WHAM с кодом MIT: сама модель тела SMPL не свободна для коммерции).
- **Kimodo-SMPLX**: только «R&D»-лицензия. Брать SOMA-версии.
- **LAFAN1** (Ubisoft): CC BY-NC-ND, запрещены коммерция и производные.
- **Датасет Bandai Namco**: некоммерческий (по условию задачи).
- **Radical**: закрыт после покупки Autodesk.
- **AITuberKit версии 2+**: коммерция только по отдельной лицензии.
- **ActorCore (бесплатные паки)**: условия противоречивы, оставить на потом, после письменного ответа Reallusion.
- **Автоматическая выкачка Mixamo скриптом**: правила прямо не разрешают, есть ограничение частоты запросов, а запрет на сбор датасетов есть. Качать вручную и только то, что нужно.
- **HY-Motion** в первых планах: условия по территории (ЕС, Великобритания, Южная Корея исключены), железо тяжелее, чем у Kimodo.
- **MoMask/MotionGPT/T2M-GPT**: старые, дрожащие, данные обучения с неясными правилами.
- **Kalidokit и MediaPipe-проекты**: качество для «живого» показа, не для чистых клипов; Kalidokit давно не обновлялся.
- **OVR LipSync**: привязан к Unity.
- **AnimaSync**: платный после 30 дней.
- **ChatVRM**: репозиторий в архиве; использовать только как пример кода.

Общие предупреждения:
- Лицензия на анимацию не отменяет лицензию на саму модель VRM: условия каждого персонажа проверять отдельно.
- Лицензии меняются. Перед тем как положить файл в продакшен, сохранить скриншот лицензии с датой в `docs/research/`.
- Я не юрист; места с пометкой «неясно» стоит уточнять у авторов.
