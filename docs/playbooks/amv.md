# AMV (кадры одного аниме или фильма под песню)

AMV — эдит кадров ОДНОГО тайтла под песню: история по актам, склейки в ритм, цвет и паузы как у профи. Одобренный
владельцем эталон — «Человек-бензопила: Резе» под «Pain» (`D:\vvf-offload\amv\out_csm`, сюжет
`D:\vvf-offload\amv\work_csm\story.json`). Разбор профессионального референса и список приоритетов —
`D:\vvf-offload\amv\analysis_refs2.md` («Warriors「AMV」», TumpyGFX, 14 млн просмотров).

Чего НЕ делать (владелец забраковал): смесь несвязанных фильмов («нихуя не понятно» — раунд 1 с открытыми фильмами
Blender), пиратские исходники (торрент с релизом, перезалив серии с чужого канала), ИИ-музыку, свою «подходящую»
песню без спроса, текст и логотипы исходника в кадре (титры, плашка «в кино с…», субтитры в полосе), вспышку на каждой
доле, тряску всего ролика, замедление каждого кадра.

## Когда

Владелец просит «AMV», «аниме-клип», «аниме-эдит», «эдит по фильму под песню». Бои записей игры под песню —
плейбук `frag-movie`; клип на свою песню из сгенерированных картинок — `music-video`.

Из сервиса: «Новое видео» → «AMV» (видео проекта, песня из музыки / файлом / ссылкой, сюжет по актам, формат) —
заводит работу AMV (`amv_id`), открывает чат проекта с этим плейбуком (закреплён за перепиской) и первым заданием.
Группа инструментов чата — `amv` (`load_tools(["amv"])`, подгружается сама по слову «AMV»).

## Правила владельца

1. **Один тайтл — одна история.** Фильм, сезон, арка; трейлеры, тизеры, опенинги одного тайтла — можно вместе. Монтаж
   рассказывает сюжет по порядку актов: знакомство → сближение → поворот/предательство → бой → финал (свой у тайтла).
2. **Только официальные источники.** Файл владельца; официальные каналы правообладателя (трейлеры, PV, опенинги без
   титров). Торрент — только если владелец сам дал magnet на то, что у него есть право использовать; спорно — спроси.
   Ссылку на источник (канал, ролик) — в описание работы.
3. **Песня — от владельца или из референса**, целиком или его участок. Без ИИ-музыки.
4. **Проба до полного.** 20 секунд вокруг кульминации, лист кадров глазами, потом владельцу. Полный рендер — после «ок».
5. Вертикаль 9:16 — для TikTok/Shorts (длиннее 60 с — части, `plan_tiktok_parts` по клипу); 16:9 — YouTube.

## Шаги

**Референсы.** Если в проекте есть референсы — сначала посмотри их (`references_list`, лист кадров и числа —
`reference_get`) и следуй отмеченным в заметке приёмам; чужие кадры/музыку не переиспользуй, только приёмы.

1. **Песня.** `amv_analyze_song(amv_id)` — темп (если трекер поймал восьмые, «ощущаемый» темп вдвое ниже — план
   считает по нему сам), дропы, части по громкости (story — тихо, action — громко, climax — последний дроп), тихие
   провалы перед дропами (`breaths`: там картинка уйдёт в чёрное). Пришли структуру словами: вступление 0–22 с, куплет,
   припев с дропом на 37.6 с… Смысл строк песни (если слышно) — подсказка, какой акт куда.
2. **Разметка исходников.** `source_contact_sheet` по каждому видео (шаг 1–2 с; на трейлере — 0.5 с):
   - `exclude` — логотипы студии, титры, плашки с текстом и датами, рейтинг, «скоро в кино», чужие вставки, чёрные
     перебивки, кадры с вшитыми субтитрами;
   - `acts` — акты истории по секундам ИСХОДНИКА (`[[от, до, "meet"], …]`), имена актов свои, короткие латиницей;
   - `box` — если в полосах letterbox субтитры: картинка без полос `[x, y, w, h]`.
   `amv_index_sources(amv_id, sources: [{source_id, acts, exclude, box}])` — сцены (склейки, кадры до 3 с, длинные
   планы целиком), цвет Lab, движение, центр кадра для 9:16, лица, свои вспышки исходника (`impacts`), дубли одного
   кадра из разных трейлеров. Первый раз — минуты (скан каждого кадра, фоном: повтори вызов), потом кэш.
3. **Сюжетная арка.** `story` — части в секундах ПЕСНИ: `[{t0, t1, acts: ["meet"], mode, colour, note}]`.
   - `mode` — `story` (тихие фразы: склейка раз в 2–4 такта, длинные кадры родной скорости, наплывы), `action`
     (склейки в долю), `climax` (последний припев: один фильм/сцена, длинные серии). Нет — по громкости.
   - `colour` — палитра части (`red`, `blue`, `warm`, `cool`, `dark`… или `[L, a, b]`): между частями цвет меняется
     широко, внутри — мелкими шагами.
   - Кульминацию держи одним фильмом и одним цветом: 6–8 кадров одной сцены подряд.
   Пришли владельцу план коротко: часть песни → акт → что видно.
4. **Проба.** `amv_plan(amv_id, test: true, story)` → смотри `checks` и `failed_checks`; правь `story` и
   `overrides` (`ban` — кадр с текстом, логотипом, обрезанным лицом; `boost` — сильный кадр; `act` — перенести кадр
   в акт; `motif` — склейка по смыслу: `hand`, `coin`, `sword_draw`, `eyes`, `falling`, `sky`, `fire`; `cx_916` —
   центр кадра). id кадров — из `shots` плана. Потом `amv_render(amv_id, name: "test")` (минуты, фоном) и
   `amv_status(amv_id, sheet: "test")` — лист кадров глазами: нет ли текста/логотипов, пустых и чёрных кадров, лиц,
   обрезанных кропом 9:16, повторов, застывших кусков (`frozen`). Пришли клип пробы.
5. **Полная версия** — после «ок»: `amv_plan(amv_id, name: "full", story)` (вся песня; участок — `start_sec`/
   `end_sec`), `amv_render(amv_id, name: "full")` (1080p, затухание в конце песни) — клип проекта и новая версия в
   ленте (вид AMV, «на проверке»; поле `feed` ответа — `work_id`, `version_id`; `error` — сдай сам
   `feed_add_version`). Второй формат — `amv_render(…, aspect: "16:9")`. Ссылки на источники (канал правообладателя)
   — в заметке версии; в подписи поста — тайтл и «Исполнитель — Песня», без списка ссылок и авторов. Владельцу —
   одна строка со ссылкой на ленту (плейбук `handoff`).

## Приоритеты референса (что делает план, и что проверять)

Числа — из разбора «Warriors» (analysis_refs2.md); `amv_plan` меряет их сам (`checks`).

1. **Цветовой порядок.** Кадры идут сериями похожего цвета (3–8 кадров), на склейке — мелкий шаг цвета. Цель:
   скачок цвета на склейке ≤ 0.65 от случайного порядка (`colour_jump`), серии ≥ 20 % времени (`colour_runs`).
2. **Контраст темпа.** Тихие части дышат: окна по 10 с — p10 ≤ 20 склеек/мин, пики 70–90 (`window_cpm_p10/p90`).
   Не рубить всё в долю — внутри фразы склейка идёт по картинке (конец действия, пик движения, свой удар).
3. **Вдох в чёрное перед дропом**: тихий провал ≥ 8 дБ ≥ 0.4 с за 4 доли до дропа — уход в чёрное за 4–6 кадров,
   картинка возвращается ровно на ударе; перед последним ударом — моргание в 1 кадр; в конце — затухание 3–6 с.
4. **Свои удары исходника** (белый кадр, слеш, вспышка света) — на акцентах и дропах; искусственная вспышка — только
   на дропе без своего удара, ≤ 6/мин (`flashes_per_min`).
5. **Скорость по частям**: экшен — родная 1.0× (`native_share` ≥ 0.7), разгон — только на дропах; замедление
   0.4–0.6× — только «геройские» доли (первый кадр тихой части, поза перед дропом). Трейлеры режут коротко — тихие
   части там идут замедлением до 0.45× (лучше дать исходник подлиннее).
6. **Склейки по мотиву** (рука → рука, монета, обнажение меча, падение в одну сторону) — `motif` в overrides.
7. **Кульминация одним фильмом** (`mode: climax`).
8. **Строб на последнем дропе** — 4–5 вставок по 2–3 кадра, потом кадр дропа.
9. **Сдержанность**: тряска только всплесками после дропов (≤ 12 % кадров, `shake_frac`), без вайпов, зум-панч — только
   на дропе, 0–3 слова поверх (лучше без текста).

## Чек-лист перед сдачей

- [ ] Один тайтл, история по актам в порядке сюжета; кульминация — одним фильмом.
- [ ] В листе кадров нет текста исходника, логотипов, чёрных и пустых кадров, обрезанных лиц, повторов одного плана.
- [ ] `failed_checks` пуст или каждое отклонение объяснено владельцу (например, «трейлеры короткие — тихая часть с
      замедлением»).
- [ ] Проба прислана и одобрена до полного рендера; полная версия — в ленте (`feed` ответа без `error`), источники —
      в заметке версии.
