# Моушн-слои клипа (`render.layers`, `render.camera`)

Контракт между редактором (превью в браузере), рендером (Node-компоновщик + ffmpeg),
ИИ-ассистентом и внешними агентами. Меняешь схему — меняй этот файл первым.

## Зачем

Нарезка клипа — это только основа. Поверх неё монтажёр кладёт титры, плашки,
стикеры, мемы, стрелки «смотри сюда», счётчики, графики, звуки на акценты и
делает наезды камеры на панчлайны. Всё это — **слои**: у каждого есть время
появления, место на кадре, ключевые кадры и анимации входа/выхода.

Главный принцип: **один код рисует и превью, и финальное видео.** Модуль
`frontend/src/motion/` — чистый TypeScript без React и без DOM-зависимостей
(только Canvas 2D API). В браузере он рисует превью поверх плеера, в рендере тот же
модуль, собранный в `node/motion-render.mjs`, рисует кадры через `@napi-rs/canvas`.

## Где хранится

В настройках рендера клипа (`clip_plans.render_settings_json`), рядом с
`inserts` и `transition`:

```jsonc
"render": {
  ...,
  "layers": [ Layer, ... ],      // по умолчанию []
  "camera": [ CameraKey, ... ]   // по умолчанию [] — без наездов
}
```

Значит, бесплатно работают: файл клипа `vvf.clip/1`, Ctrl+Z (история
снапшотов), сохранение из редактора (`PATCH /api/clip-plans/{id}/render-settings`).

Нормализация — `app/motion.py::normalize_layers / normalize_camera`: всё
неизвестное отбрасывается, числа зажимаются в допустимые рамки, у слоя без `id`
появляется id. Невалидный слой молча не выкидывается — `validate_layers`
возвращает список проблем для файла клипа и для ИИ-агента.

## Система координат

* Кадр описывается в **опорных единицах 1080×1920** (вертикальное видео).
  `x`, `y` — доли кадра (0..1), центр слоя (якорь по умолчанию — центр).
  Размеры (`w`, `h`, `size`, `strokeWidth`, отступы) — в опорных пикселях 1080×1920.
  Рендер масштабирует всё на реальный размер выхода коэффициентом `W / 1080`.
  Холст в квадрате 1:1 / 4:5 (`render_settings.aspect`, app/aspect.py): слои остаются в опорных
  1080×1920, сервис перед компоновщиком переносит их в кадр 1080×1080 / 1080×1350 — `x`/`y` и ключи
  аффинно (рамка содержимого сцены → центр кадра), `scale` и ключи `scale` × общий масштаб; фон во всю
  ширину не масштабируется. Ключи камеры — тем же переносом (центр наезда — та же точка содержимого),
  zoom/центр подправлены так, чтобы слои `followCamera` при наезде не выходили за кадр.
  Движок о формате не знает: ему приходит обычная композиция.
* Время — секунды **от начала готового клипа** (как субтитры на дорожке).
  `start` / `end` слоя — в клиповом времени. Ключевые кадры — в **локальном**
  времени слоя (`t = 0` — момент `start`).

## Layer

```jsonc
{
  "id": "l_7f3a",              // ^[A-Za-z0-9_-]{1,32}$
  "type": "text",              // см. типы ниже
  "name": "Панчлайн",          // подпись на дорожке, необязательно
  "start": 3.2, "end": 6.0,    // клиповое время, end > start, длина ≥ 0.1
  "track": 0,                  // дорожка графики 0..7; больше — выше по Z
  "hidden": false, "locked": false,

  "x": 0.5, "y": 0.3,          // центр, доли кадра (можно за пределами 0..1 — для въезда)
  "scale": 1.0,                // 0.05..10
  "rotation": 0,               // градусы
  "opacity": 1.0,              // 0..1

  // Ключевые кадры свойств. Ключ — имя свойства, значение — точки по времени слоя.
  // Анимируемые: x, y, scale, rotation, opacity, а также progress
  // (общий «ход» для counter/progress/chart/shape draw-on, 0..1)
  // и у image/video — cropX, cropY, cropW, cropH (окно props.crop в долях картинки/кадра);
  // псевдо-3D — z, rotX, rotY (см. «3D: глубина, перспектива, камера»).
  "keys": {
    "scale": [ { "t": 0, "v": 0.6, "ease": "outBack" }, { "t": 0.4, "v": 1.0 } ]
  },

  "in":  { "type": "pop",   "duration": 0.35 },   // анимация входа
  "out": { "type": "fade",  "duration": 0.25 },   // анимация выхода
  "loop": { "type": "none", "speed": 1, "amount": 1 }, // постоянное движение пока виден

  "shadow": { "color": "#000000", "blur": 0, "x": 0, "y": 0, "opacity": 0.6 }, // необязательно
  "blend": "normal",           // normal|multiply|screen|overlay|add
  "behind": false,             // под вырезанной основой (хромакей источника)
  "followCamera": false,       // едет и зумится вместе с видео (см. «CameraKey»); кратко "camera": "follow"
  "react": { "source": "voice", "prop": "scale", "amount": 1, "smooth": 0.15 }, // необязательно, см. «Реакция на звук»
  "z": 0, "rotX": 0, "rotY": 0, // необязательно: глубина (опорн. px) и наклоны с перспективой, см. «3D»
  "pivot": {"x": 0.5, "y": 0.6}, // необязательно: точка наклона и наезда группы, см. «Наклон экрана группой»
  "motionBlur": 0.5,           // необязательно: затвор 0..1 — быстрое движение смазано, см. «Motion blur»

  "props": { ... }             // своё у каждого типа
}
```

Значение свойства в момент `t` слоя: база (`x`, `y`, …) → если есть ключи — значение
интерполяции ключей (до первого — первое, после последнего — последнее) →
поверх применяются `in` / `out` / `loop` (они не перезаписывают, а комбинируются:
сдвиг прибавляется, масштаб и прозрачность умножаются).

### Easing

`linear, inQuad, outQuad, inOutQuad, inCubic, outCubic, inOutCubic, inBack,
outBack, inOutBack, outElastic, outBounce, step`. Ease точки действует на отрезке
**от этой точки до следующей**. По умолчанию `inOutCubic`.

Своя кривая — строка `"bezier(x1,y1,x2,y2)"` с семантикой CSS `cubic-bezier()`:
x1, x2 в 0..1 (иначе зажимаются), y1, y2 любые — y > 1 или < 0 даёт перелёт
(`"bezier(0.3,1.6,0.6,1)"` — пружинка). Неразобранная строка — как `inOutCubic`.
То же поле `ease` у ключей камеры.

### Анимации входа/выхода (`in`/`out`.type)

`none, fade, pop` (масштаб 0→1.1→1), `zoom` (0.6→1 + fade), `slideUp, slideDown,
slideLeft, slideRight` (въезд с края на 0.15 кадра + fade), `drop` (падение сверху с
отскоком), `spin` (поворот −90°→0 + scale), `blur`, `wipe` (раскрытие маской слева
направо), `typewriter` (только text: буквы по одной), `words` (только text: слова по
одному с pop), `rise` (только text: слова по одному выезжают снизу из-под невидимой маски
своей строки с проявлением — слово i идёт за два слота из n + 1, как `words`; ход outCubic,
старт — на высоту полосы ниже, т.е. целиком под маской; маска — полоса строки
`cy ± (capH/2 + 0.32·size + обводка)`, с плашкой `bg` — ровно строка плашки; по ширине
весь блок), `draw` (shape: обводка рисуется, заливка проявляется к концу; у
стрелки наконечник едет с кончиком линии; бэкенд пускает его у line/arrow/ellipse/scribble), `glitch` (только text: RGB-расслоение, срезы-сдвиги
полос и мерцание, к концу входа — чисто), `scramble` (только text: буквы перебираются случайными
символами и «расшифровываются» слева направо), `stomp` (любой слой: удар — влетает крупным,
«впечатывается» и встряхивается). Подробно — «Кинетическая типографика». Выход — те же типы,
проигранные назад. `duration` 0.05..3 с, не больше половины длины слоя. Анимация не своего типа
заменяется похожей: `typewriter` у не-текста → `fade`, `words` → `pop`, `rise` → `slideUp`,
`draw` у не-фигуры → `wipe`, `glitch`/`scramble` у не-текста → `fade` (нормализация бэкенда у
не-текста ставит `fade` с пометкой). Похожие имена агентов нормализация переводит с пометкой:
`decode`/`decrypt` → `scramble`, `slam`/`stamp`/`punch`/`impact` → `stomp`, `rgb` → `glitch`.

### Постоянное движение (`loop`.type)

`none, pulse` (дыхание масштаба), `float` (плавает вверх-вниз), `shake` (тряска),
`wiggle` (покачивание поворотом), `spin` (вращение), `blink` (мигание), `glitch` (только text:
короткие сбои ~0.22 с раз в 1.6/speed с), `wave` (только text: буквы волной по синусоиде).
`speed` 0.1..5, `amount` 0..3. Тряска и покачивание — детерминированный шум от `id`
слоя и времени (никакого random): превью и рендер совпадают кадр в кадр. У не-текста
`glitch` → `shake`, `wave` → `float` (бэкенд — с пометкой); у эффекта кадра `fx` цикла нет.

### Тень (`shadow`)

`blur`, `x`, `y` — в опорных px и масштабируются вместе со слоем. Тень отбрасывает
**силуэт** слоя: плашка `bg` (если есть), иначе обводка текста (если есть), иначе
заливка; у фигуры — заливка (без заливки — обводка); у картинки/эмодзи — сама
картинка (по альфе); у графика и прогресса — карточка/дорожка. Детали поверх
силуэта своей тени не дают. Свечение — та же тень цветом акцента с `x = y = 0`.

## Пределы

Слоёв в клипе ≤ **200** (`MAX_LAYERS`), ключей камеры ≤ **120**, точек ключей на одно свойство ≤ **200**
(`GET /api/motion/schema` → `limits`). Сверх предела ничего не теряется молча: проверка
(`validate_layers`, файл клипа, `/layers/validate`) называет, сколько и какие слои/ключи не попадут
(«слоёв 226, предел 200 — слои с layers[200] по layers[225] (26 шт.) НЕ попадут в клип…»), а
`add_layers` агента отказывает целиком и говорит, сколько ещё можно добавить; от 90 % предела ответ
`add_layers` предупреждает заранее. Россыпь звёздочек/искр — один слой `particles`, не десятки `shape`.
Замер (`npm run test:motion`, «200 слоёв»): 200 простых слоёв (текст с обводкой, фигуры, pop/pulse) —
≈ 4 мс на кадр 1080×1920 без кодирования; 200 слоёв с тенями + 200 частиц через CLI — 90 кадров с
кодированием за 2.5 с (≈ 35 кадр/с).

### Частицы (`particles`)

`layers/particles.ts`. Одна функция `particlesAt(props, seed, local)` — чистая: частица i — от
`rand01(seed, i·12 + k)` и локального времени слоя, без `Math.random` и без истории, поэтому превью и
рендер совпадают кадр в кадр, а перемотка в любую точку честная. `seed` не задан — зерно от `id` слоя.
Координаты — опорные px от центра слоя (`x`, `y`, `scale`, `rotation`, ключи — как у любого слоя).

| kind | что | `duration` по умолч. | `gravity` по умолч. | форма по умолч. |
|---|---|---|---|---|
| `burst` | разлёт из центра на 0.3..1·`spread` (outCubic), растёт за 10% жизни, тает в последние 35%; `repeat` — каждые `duration` | 1.2 | 500 | star4 |
| `sparkle` | искры в круге `spread` мигают своим циклом `duration`·(0.7..1.3): видны первые 60% цикла | 1.6 | — | star4 |
| `confetti` | сверху области (−`spread`) вниз с сопротивлением воздуха (τ 0.45 с), качаются и «переворачиваются»; без `repeat` — стартуют за первую половину `duration`, с `repeat` — непрерывный дождь | 3 | 900 | square |
| `rise` | снизу (+`spread`) вверх через область, проявляясь и тая, петлёй | 3 | 0 | dot |

`glow` — мягкое свечение цветом частицы радиальным градиентом (дешевле тени: тень слоя на 200 частиц
дорогая). Картинка частиц (`asset_id` или `src`) пока грузится — слой пуст. Рамка выделения —
`(spread + size)·2`. Шаблон «Искры и конфетти» (`particles`, категория «Акценты»).

### Кинетическая типографика (`glitch`, `wave`, `scramble`, маркер, `stomp`)

`layers/text.ts` (буквы), `animate.ts` (сила по времени). Всё «случайное» — `rand01`/`noise1` от `id`
слоя (`hashString`) и **номера шага** времени слоя (не кадра превью: превью 60 Гц и рендер 30 кадр/с
берут один и тот же шаг) — превью и рендер совпадают кадр в кадр. Раскладка текста не меняется:
эффекты только двигают, подменяют и прячут уже разложенные буквы, строка не «прыгает».

* **`glitch`** (вход/выход, цикл; только text). Сила `st.glitch` 0..1: на входе `1 − inQuad(p)`
  (прозрачность × min(1, 3p)), в цикле — вспышки `0.85·amount·sin(πu)` длиной 0.22 с, по одной в
  период 1.6/`speed` с в своём месте периода (`rand01(seed + 17, № периода)`). Рисунок, шаг 1/24 с:
  красная `#ff2a55` и голубая `#19f0ff` копии букв (без обводки, плашки и подсветки) разъезжаются на
  ±(обводка + 0.04..0.12·кегль)·сила, поверх — сам текст; 1–4 горизонтальных среза блока сдвинуты
  вбок до ±0.3·кегля·сила; кадр с вероятностью 0.07·сила выпадает, 0.2·сила — тускнеет до 0.4. Тень
  отбрасывает только сам текст. Рамка слоя на время глитча шире на 0.8 кегля (промежуточный холст).
* **`wave`** (цикл; только text): графема `i` (номер во всём тексте, как у typewriter) сдвинута вверх
  на `0.12·кегль·amount·sin(2π·0.9·speed·t − 0.55·i)`; эмодзи и символы-декор — целиком. Позиции букв —
  по ширине префикса строки: кернинг сохраняется.
* **`scramble`** (вход/выход; только text, синоним `decode`): фронт перебора идёт слева направо,
  `fraction·(n + W)` графем, окно `W` = 0.35·n, но 3..12. Графемы дальше фронта не видны, в окне перед
  ним — случайная буква того же регистра из набора `А–Я A–Z 0–9` (строчные — строчными), 20 смен в
  секунду (`SCRAMBLE_RATE`, символ — `rand01(seed, шаг·7919 + i·131)`), за окном — настоящая.
  Подменённая буква — по центру ячейки настоящей. Плашка строки — с первого видимого слова.
* **Маркер** — подсветка `highlight` с `style: "marker"`: полоса цвета `bg` (нет — `#ffd400`, плотность
  0.92) от верхней трети заглавных до 0.18 кегля ниже строки, со скосом штриха 0.2 и наклоном −0.7°;
  соседние подсвеченные слова строки — одна полоса. `draw` (с) — прорисовка слева направо по порядку
  чтения (inOutCubic по общей длине полос), у маркера по умолчанию 0.45 с; `delay` — с какой секунды
  слоя, нет — сразу после входа `in`. Плашка (`bg` без `style`) с `draw` > 0 выезжает так же (без
  `draw` — сразу, как было). Цвет букв маркера: `color` подсветки, если он не совпадает с цветом
  маркера, иначе — цвет текста (жёлтое на жёлтом не видно); бэкенд у маркера без своего `color`
  ставит цвет текста.
* **`stomp`** (вход/выход; любой слой): до 0.38 входа масштаб 2.2 → 1 с разгоном (inQuad), прозрачность
  × min(1, 3q) — удар в момент наибольшей скорости; после — «сплющивание» до −7 % и встряска ±22 опорн.
  px / ±2.5°, затухающие (1 − q)². В субтитрах — `animation: "stomp"` (и пресет «Удар»): слово не видно
  до своего `t0`, за 0.09 с влетает с 1.7× масштаба, 0.32 с встряска ±0.07 кегля; слово из
  `highlightWords` бьёт в 1.35 раза сильнее. Страница целиком не выпрыгивает.

### Эффект кадра (`fx`)

`layers/fx.ts`. Процедурно, без файлов, во весь кадр **поверх видео и слоёв на дорожках ниже**: слои
выше по `track` остаются чистыми (титры над VHS). `x`/`y`/`rotation`/камера не действуют; прозрачность
слоя (ключи `opacity`, `in`/`out` fade, `react` opacity) гасит эффект целиком, масштаб (ключи `scale`,
`react` scale) умножает `intensity`. `in`/`out` — только `none`/`fade`, цикла нет (скорость —
`props.speed`); `followCamera`, тень и `blend` слоя бэкенд снимает с пометкой (`blend` → `props.blend`).
Мышью в превью эффект не выбирается (иначе закрыл бы слои под собой) — только на дорожке.

сдвигом (`lighter`), без `getImageData`. Зерно — 6 плиток шума 256×256 из `rand01` (серый ~128, сумма трёх
равномерных), одни на окружение; плитка и её сдвиг — `rand01(seed, шаг)`. Нет фабрики холстов
(`createCanvas`) — пиксельные части и зерно пропускаются. Режимы наложения — те же пять, что у слоёв.
Больше `FX_MAX_AT_ONCE` (2) эффектов одновременно — предупреждение агенту (`fx_crowding`, не ошибка).
**Глитч на отрезке** (`app/glitch.py`, MCP `add_glitch`, шаблон «Глитч на отрезке»): слой `fx` вида
`rgb_split`/`tear`/`vhs`/`datamosh_lite`/`pixel_sort_lite` с ключами `scale` (сила рывками —
`glitchKeys` / `app/glitch.glitch_keys`: 0.25 → 1 за ≤ 0.05 с, ступенька 0.45 на 30 %, удар 1 на 42 %,
ступенька 0.6 на 70 %, 0.95 на 82 %, затухание 0.15), первым на дорожке 0 — под всеми слоями (сбоит
видео, титры чистые) или над всеми (`over_layers`); звук — слой `audio` с записью пака freesound
(`GLITCH_SFX`: `hit-transition`, `record-scratch`, `bass-drop`, `whoosh-4`), без файла — без звука с пометкой.
В квадрат/16:9 эффект не переносится (он во весь кадр; масштаб — сила, переносить нечего). Шаблоны
«Эффект кадра» (категория «Эффекты») и «Глитч-титр» (категория «Титры»).

### Motion blur (`motionBlur`, `render.motion_blur`)

`frontend/src/motion/motionblur.ts`. Быстрое движение смазывается по пути, как с затвором камеры:
въезд/вылет плашки, вращение, слой с камерой на whip, сама основа под быстрым наездом, сцена 3D.

* **Затвор** `0..1` — доля интервала кадра (0.5 — киношные «180°», 1 — сильный смаз). Где задаётся:
  у слоя `motionBlur` (MCP `update_layer`, инспектор «Положение» → «Motion blur»; null — как у клипа,
  0 — резко); у ключа камеры `motionBlur` — на отрезок от этого ключа, как `ease` (MCP `set_camera`
  per-key или верхним полем всем ключам без своего, `camera_preset motionBlur`; панель ключа камеры);
  значение клипа по умолчанию `render.motion_blur` (MCP `set_motion_blur`, ползунок «Motion blur» в
  настройках рендера, `comp.motionBlur`) — слоям и ключам без своего. Нет нигде — резко, рендер прежний.
* **Только где быстро.** Путь меряется до рисования: углы рамки слоя (с ключами, `in`/`out`, `loop`,
  масштабом и поворотом, с наездом у `followCamera`, с проекцией у слоёв с `z`/3D-камерой) в моменты
  открытия и закрытия затвора; у `scene` ещё и вершины граней внутри рамки (`sceneTravel` — сцена крутится
  в неподвижной рамке); у основы — углы кадра после камеры (`cameraBlurTimes`, с окном игры раскладки и
  плоскостью 3D-камеры). Путь меньше `MOTION_BLUR_THRESHOLD` (1.5 опорн. px) — слой рисуется один раз,
  ровно как без размытия: **в покое размытие — тождество, пиксель в пиксель** (тест движка). Иначе
  подкадров `N = clamp(⌈путь / 6⌉ + 1, 4, 12)`.
* **Подкадры** — затвор по центру кадра: `t + (i/(N−1) − ½)·shutter/fps`, у слоя зажаты в его
  `[start, end)` (первый и последний кадр не гаснут наполовину), у основы — `≥ 0`. Всё — функция `t`:
  превью и рендер считают одни и те же моменты (детерминировано). Превью ограничивает N
  (`env.motionBlurSamples` = `MOTION_BLUR_PREVIEW_SAMPLES`, 6): ширина смаза та же, полосы чуть заметнее.
* **Усреднение без `getImageData`.** Слой: подкадры рисуются режимом `normal` на холст подкадра, копятся
  бегущим средним на холсте-накопителе (накопленное × (1 − 1/k) через `destination-out`, плюс подкадр × 1/k
  через `lighter`) внутри прямоугольника пути с полями под тень/свечение/размытие; итог кладётся в кадр
  режимом наложения слоя (`paintLayerBlur`). Непрозрачная основа — первый (средний) подкадр прямо в
  кадр, k-й сверху с прозрачностью 1/k (`paintOpaqueBlur`); вырезанная хромакеем основа — как слой.
  Ошибка округления 8-битных каналов — в среднем 1–2 уровня из 255 при 12 подкадрах (замер на Skia).
* **Не смазываются:** `fx` (эффект кадра; поле снимается с пометкой), `audio`; внутреннее движение
  частиц, букв текста (`scramble`, `wave`), кадров видео-слоя и анимаций — рамка стоит, подкадры не
  нужны. Элементы-функции сцены (текст, картинки) в путь `scene` не входят — их смаз виден, только если
  движется сам слой или грани рядом.
* **Переход `whip`** (а также `slide`/`smooth` — сдвиги `xfade`) склеивается ffmpeg-ом: при
  `transition.motion_blur` (или значении клипа) на окне перехода — горизонтальный `gblur` на длину пути
  за затвор (`app/transitions.whip_blur_sigma`: ширина кадра / (длина перехода × fps) × затвор,
  σ ≈ 0.3·путь); остальные переходы не смазываются.

Стоимость (компоновщик, 1080×1920, 180 кадров, CPU хоста, `node/motion-render.mjs`): всё стоит —
2.3 с с размытием и без (путь меряется, подкадров нет); whip камеры три раза за 6 с (≈ 26 смазанных
кадров по 12 подкадров основы) — 5.1 → 7.6 с (≈ +95 мс на смазанный кадр); плюс всё время крутящиеся
звезда и сцена-куб, въезд титра и пролёт плашки — 4.9 → 11.6 с (≈ +11 мс на смазанный слой в кадре).
Тест `node/motion.test.mjs` печатает свой замер (540×960).

### Реакция на звук (`react`)

`levels.ts` + `app/audio_react.py`. Любой рисуемый слой: `react {source, prop, amount, smooth, color?}`
— `source` `voice` (по умолчанию: дорожки распознавания речи источника `speech_tracks`, нет — смесь
рендера) / `music` (фоновый трек клипа с `music_start_sec`, по кругу, во времени готового ролика; без
приглушения под голосом) / `mix` (смесь дорожек рендера источника + музыка с громкостью трека, по
мощности); `prop` `scale` (×(1 + 0.25·amount·L)) / `glow` (тень цветом `color`, нет — цвет тени слоя или
белый: размытие тени слоя + 60·amount·L опорн. px) / `opacity` (×(1 − min(1, amount)·(1 − L)): в тишине
гаснет) / `y` (вверх на 40·amount·L опорн. px); `amount` 0..3 (1), `smooth` 0..1 (0.15). У эффекта кадра
`scale` — сила эффекта. Звуковому слою `react` не нужен — бэкенд отбрасывает с пометкой. Синонимы:
`speech`/`mic` → voice, `all`/`audio`/`sound` → mix, `brightness` → glow, `jump`/`bounce` → y.

1. Сервер (`plan_levels`) один раз на клип читает звук тем же путём, что голос PNGtuber
   (`app/pngtuber.py`: моно 8 кГц, куски по кускам клипа через `ClipClock`, RMS окна 1/fps в дБ) и
   переводит громкость в огибающую 0..100: ноль — шум (15-й перцентиль слышимых кадров) + 3 дБ, но не
   ближе 12 дБ к громкому (97-й перцентиль) — микрофон с шумодавом и ровный тон не становятся «шумом»;
   спад плавный, ~0.12 с.
2. `comp.levels = {voice|music|mix|wave:<id>: {t0, fps, v: [0..100]}}` (`wave:<id>` — свой звук слоя `waveform`,
   app/waveform_levels.py) — кадр k — момент `t0 + k/fps` (время клипа;
   рендер — готового ролика после вырезов, стоп-кадры со вставкой дописывают тишину, как у голоса
   PNGtuber). Только источники, которые нужны видимым слоям.
3. Движок: `levelAt(track, t, smooth)` — значение кадра (за краем — 0), сглаживание — экспоненциальное
   окно назад по массиву (постоянная времени `smooth`·0.5 с, длина окна — 3 постоянных), без состояния
   между кадрами: перемотка честная, превью == рендер. Применяется после `in`/`out`/`loop`.

Превью: `POST /api/clip-plans/{id}/levels {sources?, fps?}` → `{levels, notes, scale: "clip"}`. Кадр
агента (`/motion/frame`) берёт огибающую всего клипа (нормировка та же, что в рендере). Нет файла
источника / трека — огибающая нулевая (слой стоит), пометка в ошибке клипа.

### Символы-декор в тексте

`glyphs.ts`. Символов `✦ ✧ ★ ☆ ✶ ✷ • ● ○ ◆ ◇ ♥ ♡ → ← ↑ ↓ ✓ ✔ ✕ ✖ ▶ ►` нет в шрифтах `vendor/fonts` —
канвас рисовал квадрат, а браузер подставлял системный шрифт со своей шириной (перенос в превью
расходился с рендером). Теперь они всегда рисуются путями: ширина — доля кегля (`adv`, +
`letterSpacing`), не зависит от шрифта; цвет — заливка/градиент/подсветка слова текста, обводка
текста обводит и символ; контурные (✧ ☆ ○ ◇ ♡ ✓ ✕) — линией цветом текста. Работает везде, где
текст раскладывает `layoutText` (text, counter, callout, подписи графиков). С селектором эмодзи
(`♥️` = ♥ + FE0F) символ остаётся эмодзи Twemoji. Агентский фильтр эмодзи (владелец их запретил)
эти символы не вычищает.

### Плашка канала (`nameplate`)

`layers/nameplate.ts`. Пилюля высотой `size` = H: поля 0.42·H, значок высотой 0.56·H, зазор 0.26·H,
ник кеглем 0.5·H (раскладка `layoutText` — ширина та же в превью и рендере). Без ника — только значок
(пилюля не уже H), без значка (`none`) — только ник; ни того ни другого — слой пуст (проверка ругается).
`glass` — стекло `rgba(14,10,24,0.67)` с обводкой `max(2, 0.034·H)` цветом `accent`, значок цветом
`accent` (TikTok — белая нота с голубой и красной копиями), ник `color`; `solid` — заливка `accent`,
значок и ник белые (на светлом акценте, как зелёный Kick, — тёмные). Цвета площадок (`PLATFORM_COLORS`,
зеркало `app/brand_kit.PLATFORM_COLORS`): Twitch `#9146ff`, YouTube `#ff0033`, TikTok `#fe2c55`,
Telegram `#229ed9`, Kick `#53fc18`.

**Значки** — `PLATFORM_ICONS` в `glyphs.ts`, свои упрощённые глифы путями (как символы-декор), не файлы
логотипов: Twitch — «пузырь» со срезанным углом и двумя полосками, YouTube — скруглённый экран с
треугольником, TikTok — нота, Telegram — круг с самолётиком, Kick — ступенчатая K. Внутренние контуры
вырезаются правилом evenodd — сквозь полоски и треугольник видна плашка.

**Рамка**: размер слоя — `max(boxWidth, ширина пилюли) × H`; пилюля в рамке по `align`. Так плашка
ставится «от края кадра», не зная ширины ника: `align: "left"`, `x = (24 + boxWidth/2) / 1080`. Тень
слоя (`shadow`) отбрасывает пилюля. Поставить по бренду или одной командой — `set_nameplate` / `apply_brand` (docs/AGENTS.md):
место считает `app/brand_kit.nameplate_place` (под разделителем раскладки split, ниже субтитров, иначе
безопасный угол). Шаблон «Плашка канала» (`channel-plate`, категория «Плашки»).

**Анимация** (`anim`) — своя у слоя, поверх обычных `in`/`out`/`loop` (их бренд не ставит). Всё —
функция локального времени слоя `nameplateMotion(props, local, duration, букв)` без состояния и случайности:
превью = рендер кадр в кадр (тест движка сверяет кадр компоновщика и движка на каждом пресете в 0.1 / 0.4 /
0.8 / 7 с). Плашка видна весь ролик — после входа анимация редкая и мягкая.

| | `subtle` (по умолчанию) | `lively` |
|---|---|---|
| вход | 0.7 с: значок с «таблеткой» вокруг выпрыгивает (0–0.32 с, outBack), пилюля вытягивается вправо (0.16–0.52, outCubic), ник проявляется по буквам с подъёмом (0.3–0.7, полутень 3 буквы) | 0.8 с: перелёт сильнее (`bezier(0.3,1.9,0.55,1)`), пилюля outBack, ник 0.32–0.8 |
| блик | косая светлая полоса по пилюле, 0.9 с, с 6.6 с каждые 7 с, яркость 0.22 | 0.8 с, те же моменты, 0.28 |
| тик значка | с бликом (6.6 + 7k с), 0.45 с | каждые 3.5 с с 3.1 с, 0.5 с, сильнее ×1.5 |

`none` — плашка стоит с первого кадра (как раньше; мягкий вход тогда — `in: fade`). Тик по площадке: Twitch —
глитч (две ступеньки вбок с голубой и розовой копиями), YouTube — пульс «играть» (масштаб до +12 %),
TikTok — ноту «растаскивает» по цветам, Telegram — самолётик кивает носом, Kick — K приседает. Ник и всё
содержимое обрезаются текущей пилюлей — ник выезжает из-под её края.

`live: true` — красная точка `#ff2d2d` (радиус 0.11·H) после ника, проявляется последней; с анимацией
пульсирует (кольцо расходится раз в 1.6 с), с `none` стоит. Пилюля шире на 0.48·H.

`outro: "collapse"` — в последние 0.6 с слоя вход проигрывается назад: ник гаснет, пилюля сворачивается в
значок, значок уходит. Бренд (`outro: auto`) ставит его, когда есть призыв: слой кончается через 0.6 с после
начала `brand_cta` — плашка уступает место концовке.

### От руки (`shape.rough`), штриховка и курсор

`layers/sketch.ts`. `rough` > 0 у ellipse/rect/line/arrow/scribble — обводка «маркером» вместо геометрии:
линия сдвинута по нормали на сумму трёх синусов по длине пути (на весь путь, на треть и мелкая дрожь
~48 px), амплитуда `rough · (min(16, max(3, 0.016·размер)) + 0.18·толщина)`; у line/arrow концы стоят на
месте (остриё попадает в цель). Круг не замыкается: начинается левее верха и проходит ~1.06–1.18 оборота,
радиус к концу чуть уходит — линия ложится рядом с началом. Рамка — с перехлёстом первого угла на ~8 %
стороны. Наконечник стрелки — два штриха от острия назад под ±28°, дорисовываются в последние 18 %
хода `draw`. Фазы — от `seed` (целое, 0): никакой случайности, превью = рендер. `boil: true` — seed
меняется 8 раз в секунду («кипящая» линия рисованной анимации). Без `rough` фигуры прежние.

`scribble` — зигзаг слева направо и обратно сверху вниз по `w`×`h`, проходов `ceil(h / (0.8·толщина))`
(2..24); с полупрозрачным цветом (`#ffd40080`) — маркер по слову, с плотным — зачёркивание каракулями.
`cursor` — силуэт стрелки мыши (сетка 12.4 × 19.6) на всю рамку `w`×`h`, остриё — левый верхний угол:
чтобы остриё было в точке (x, y), центр слоя — `x + w/2/1080`, `y + h/2/1920`.

Шаблоны галереи (frontend/src/motion/templates/sketch.ts): «Стрелка от руки» (`hand-arrow`: цель x/y,
откуда идёт, длина, подпись рукописным Caveat — печатается по буквам), «Обвести от руки» (`hand-circle`:
область x/y/w/h), «Подчеркнуть от руки» (`hand-underline`: подчеркнуть / дважды / зачеркнуть / маркером),
«Курсор и клики» (`cursor-clicks`) и «Касания пальцем» (`finger-taps`): путь `"x y секунда; …"` — ключи
x/y острия (inOutCubic), касания `"1.3, 2.9"` — нажатие (масштаб 1 → 0.84/0.78 → 1) и на каждое касание
волна (круг 0.25 → 1, гаснет за 0.6 с) и вспышка в точке, где курсор в этот момент.

### Карточка соцсети (`social`)

`layers/social.ts`. Без логотипов и названий площадок: значки — свои пути (сердце из `glyphs.ts`,
«облачко» ответа, стрелки репоста), шрифт по умолчанию Inter (кириллица).

- `comment` (ширина `w`, 900): кружок аватара 92 px слева, справа колонка 130 px с сердечком и счётом;

  текст на всю ширину (44 px, 1.3), картинка `image` в рамке 5:3 по ширине текста (обрезается по
  центру, скругление 26), внизу ответы / репосты / лайки по трети ширины; счётчик без значения не показан.
- Высота — по раскладке текста (`layoutText`, перенос по словам); строк больше `maxLines` (8) — текст
  срезается по графемам и кончается «…». Оценка для перекомпоновки и проверок — `app/aspect.layer_size`
  (зеркало `reframe.ts`): comment `max(160, 172 + строк·44·1.28)`, post `250 + строк·44·1.3 + 28` (+
  `(w − 80)·0.6 + 30` с картинкой), строки — по 0.58 кегля на букву.
- Аватар: `avatarImage` (по кругу, cover), иначе кружок с градиентом `accent` и эмодзи `avatar` (Twemoji)
  или буквами (`avatar`, нет — первая буква `name`).
- Лайки: `likes` → `likesTo` по `progress` (ключи; нет — outCubic за первые 60 % слоя); пока счёт идёт,
  сердечко закрашено `#ff3b5c` и «пульсирует» в первые 30 % хода. Число по-русски: `9 876`, `15,4 тыс.`,
  `1,2 млн`. `liked: true` — закрашено сразу.
- Непрозрачная карточка подчиняется правилу «не закрывать видео» (`app/layer_lint.cover_share` — площадь
  по оценке выше): комментарий ≈ 10–20 % кадра, пост с картинкой ≈ 37 %; длинный пост с картинкой
  может перейти 40 % — тогда меньше `maxLines` или без картинки.

Шаблоны (frontend/src/motion/templates/social.ts, категория «Мемы»): «Комментарий зрителя»
(`comment-card`) и «Пост из ленты» (`post-card`) — появление pop / slideUp / fade, счёт лайков вверх
через 0.5 с за 1.8 с (ключи `progress`).

docs/research/hyperframes-vs-ours.md); код, пути и значки свои, из каталога ничего не скопировано.

### Страница сайта (`page`)

Снимок страницы (app/webpages.py, `page_snapshot` / вкладка «Страницы») — кадр всей страницы PNG (DPR 3 у телефона,
2 у компьютера) версии `version`; ссылка картинки — `webpage:<page_id>:<version>` (рендер: `assets.json`, превью —
`/api/web-pages/<id>/versions/<n>/image`). Движок (`layers/page.ts`) вырезает окно `region` (CSS px страницы),
листает его ключами `scroll` (верх окна по секундам СЛОЯ, кривая inOut по умолчанию), приближает `zoom` (окно
сжимается вокруг cx/cy — доли окна) и рисует волну касания `taps` в точке страницы. Пропорция окна постоянна,
поэтому размер слоя — `w` × по пропорции `region` (+ корпус телефона). Правки страницы (подсветка, цена, обрезка)
делаются в HTML копии новой версией (`page_edit`), не поверх слоя. Шаблоны (templates/page.ts, «Промо»):
«Страница: прокрутка» (`page-scroll`) и «Страница в телефоне» (`page-phone`, касание в конце).

Страница по слоям (app/webpage_layers.py, `page_to_layers` / «Разобрать на слои» во вкладке «Страницы») — не слой
`page`, а обычные `image` (и `text` для простого текста со шрифтом, который подключается): «Фон страницы» (область
без блоков) и каждый блок — шапка, заголовок, текст, кнопка, цена, значок, картинка, карточка (её дети — свои слои) —
прозрачной PNG из «Файлов для монтажа» на своём месте. Раскладка `fit_width` (блоки вписаны в кадр) или `as_page`
(страница во всю ширину). Вход лесенкой сверху вниз; `focus` — наезд на блок вместе с детьми (одни ключи x/y/scale
у каждого слоя блока, дорожкой выше), остальное притухает. Групп слоёв нет: слои вставки связаны id `wp<page>_<метка>_…`.

### Рекламный пакет (одометр, пузыри, карусель, волна, стена плиток, схема сделки)

Слои и шаблоны для промо продукта и сервиса в стиле современных UI-промо. Палитра нейтральная (тёмное стекло
`#161821`, текст `#f5f6fa`, приглушённый `#a2a7b5`), один акцент `accent` (`#6c5cff`), гарнитура Manrope; `theme:
light` — светлое стекло. Значки `icon` — свои векторные (`layers/adicons.ts`, сетка 24×24): shield, lock, check,
user, users, store, card, star, bolt, heart, chat, music, play, cart, gift, bell, mic, coin, globe, phone, headphones,
sparkle, trend, game — или 1–3 буквы; эмодзи и логотипы чужих марок не используются. Картинки — id файла или
`sticker:`; не нашлась — слой остаётся (пузырь со значком, карточка с буквой, плитка своя), пометка в ошибке.
Всё — чистые функции props и времени: превью = рендер (проверка — `node/motion-ads.test.mjs`).

* **Одометр** (`counter.roll`, `layers/odometer.ts`): раскладка — итоговое (самое длинное) значение в ячейках одной
  ширины; каждая цифра — барабан от цифры `from` к цифре `to` (вверх при росте, вниз при счёте назад) с лишними
  оборотами: у старшего разряда 1, у младшего `laps`. Ход разряда i — ход слоя (`progress`, ключи или первая
  половина слоя) в момент `local − i·stagger`. Окно барабана — по высоте цифры, края мягкие (прозрачность по
  сдвигу), быстрый барабан смазан двумя бледными копиями; встав, цифра рисуется обычной (со свечением слоя).
  Разряды, которых не было в начале, проявляются, пока крутятся.
* **Пузыри** (`layers/bubbles.ts`): диаметр — `minSize..maxSize` по корню доли наибольшего `value` (не меньше
  четверти пути), без чисел — по зерну. Упаковка: крупные первыми, каждый — в первую свободную точку спирали
  Ферма от центра (поворот — от `seed`), с зазором `gap`, внутри `w×h` (не влез — уменьшается). Появление — от
  центра к краям через `stagger` (outBack 0.5 с), число считает от 0 за 0.9 с, парение ±`float` px своим ритмом.
  `focus` (номер) с `focusAt` (нет — после всех появлений): растёт ×`focusScale`, остальные ×0.88 и гаснут до 38 %,
  задетые — расступаются по линии центров. Числа по-русски коротко: `9 876`, `480 тыс.`, `2,4 млн`.
* **Карусель** (`layers/carousel.ts`): лента — непрерывный номер c(t) = `start` + Σ кривых переездов (`switchAt` или
  каждые `interval`, длина `switchDur`, кривая `ease`); карточка i — со сдвигом d = i − c (по кругу — ближайший путь),
  x = d·`spacing`, масштаб 1 → `sideScale`, прозрачность 1 → `sideOpacity`, дальше соседа тает. За центром —
  свечение и 4 концентрических кольца, дышат (±1.8 %), одно кольцо волной уходит наружу. Карточка: картинка
  «cover» (нет — градиент цвета и крупная буква имени), низ в тень, имя, подпись, строка `meta` со значком play.
* **Волна** (`layers/waveform.ts`): высоты столбиков — огибающая в момент t − задержка столбика (`center`: от
  середины к краям за `span/2`; `scroll`: лента за `span`), × `sensitivity`, узор (середина выше, неровные соседи),
  не ниже `minLevel`. Огибающая: `auto` — `comp.levels["wave:<id слоя>"]` (сервер считает звук `audio_layer` —
  секунда файла `offset + (t − start)` слоя-звука — или `asset_id` с `from`, app/waveform_levels.py, как огибающие
  `react`); `voice`/`music`/`mix` — огибающие клипа; нет огибающей или `fake` — образец «речи» по `seed`.
  Свечение — одной тенью на весь путь.
* **Стена плиток** (`layers/tilewall.ts`): бесконечная сетка в плоскости, поворот `tiltZ`, наклон вглубь `tiltX`
  (верх дальше) с перспективой фокусного 2638; плитка (i, j) — в (i·шаг + сдвиг, j·шаг + сдвиг), сдвиг = `speed`·t
  по `angle`, картинка — от хэша (i, j): петля бесшовная. Плитка — своим аффинным преобразованием по проекции углов,
  дальние темнее; сверху — `overlay` и виньетка под текст. Во всю ширину — фон: в другом формате тянется по
  сторонам (как фигура-фон), в «не закрывать видео» — закрывает весь кадр (на холсте правило не действует).
* **Схема сделки** (`layers/flow.ts`): узлы в ряд (`row`) или столбец, центральный (`center`, по умолчанию средний)
  крупнее — щит цветом акцента с кольцом-импульсом и замком `lock`. Шаги: узел k — в `delay + k·stepGap` (pop),
  связь k → k+1 тянется пунктиром между ними (пунктир «бежит», на конце светится точка-платёж, в конце — шеврон),
  замок защёлкивается после щита, плашка `done` с прорисовкой галочки — после последнего узла (`doneAt`).
* **Фраза по словам в карточке** — уже есть: слой `captions` со `style: "karaoke"` (сказанные слова — `color`,
  звучащее — `activeColor`, впереди — `dimColor`) поверх стеклянной фигуры-карточки, `bg: null`, `maxWords` 6,
  `maxLines` 2, `maxWidth` по карточке. Слова — субтитры клипа (`comp.words`): у озвучки на холсте — её субтитры.
  Шаблон «Фраза по словам в карточке» (`karaoke-card`) собирает карточку, подпись и маленькую волну голоса.

Шаблоны (frontend/src/motion/templates/ads.ts, ads2.ts, категория «Реклама»): «Счётчик-одометр»
(`odometer-counter`), «Облако пузырей» (`bubbles-cloud`), «Рейтинг и отзывы» (`rating-badge`: ★ загораются по
одной, оценка и отзывы считают), «Экран с наклоном и наездом» (`screen-tilt`), «Карусель карточек»
(`card-carousel`), «Волна голоса» (`voice-wave`), «Фраза по словам в карточке» (`karaoke-card`), «Стена плиток»
(`tile-wall`), «Схема безопасной сделки» (`deal-flow`). Списки в одном поле — «a | b | c; d | e | f».

### Наклон экрана группой (`pivot`, пресет `screen_tilt`)

Наклоны `rotX`/`rotY` и ключи `scale` у слоя с `pivot {x, y}` (доли кадра) действуют вокруг этой точки, а не
центра слоя: ключ scale k (относительно базы `scale`) уводит центр от точки в k раз (`animate.ts`), наклон
поворачивает вектор «точка → центр» теми же поворотами, что плоскость (`render.ts`, `layerPlane`). У группы слоёв
с одним `pivot` и одинаковыми ключами наклон и наезд общие — блоки страницы (`page_to_layers`) или макет интерфейса
наклоняются и приближаются как один экран; `in`-анимации (pop, slideUp) остаются у каждого свои. Отдельный
3D-режим камеры не нужен: это те же ключи слоя и проекция `space3d.ts`. При переносе формата `pivot` едет вместе с
x/y (app/aspect.py, reframe.ts, `fitTemplate`). Одной командой — `camera_preset` `screen_tilt` (`layer_ids` или
`layer_prefix`, точка `x`/`y`, `zoom` 1.3, `intensity` — наклон 24°·i): rotX 24 → 10.8 → 2.9°, rotY −14 → −6.7 →
2.4°, scale 0.9 → 1 → zoom, мягкие кривые; слою, начавшемуся позже, — значение кривой в его начале.

### Перетекающие переходы между сценами (`transition`, инструмент `flow_transition`)

`frontend/src/motion/flow.ts` (геометрия) + `render.ts` (рисование групп), схема и подгонка времени —
`app/motion_flow.py`, инструмент — `app/layer_tools_flow.py`. Сцена A не сменяется сценой B склейкой, а
перетекает в неё. Слой `type: "transition"` **сам не рисуется**: на своём отрезке `start..end` он собирает
слои `props.from` (сцена A) и `props.to` (сцена B) в две группы и рисует каждую одной картинкой со своей
матрицей (масштаб `s` и сдвиг в px кадра), маской и общей прозрачностью. Фон холста, субтитры, звук, `fx`,
чат и слои через весь стык не трогаются.

| `kind` | что | параметры |
|---|---|---|
| `reveal_from` | из элемента `target` сцены A (точка, кружок в цифре) растёт круг (`shape: "rect"` — скруглённый прямоугольник от рамки элемента) и раскрывает B; A вокруг — с обратной маской | `depth` 0..0.5 (0.12): A растёт на depth, B вырастает из 1 − depth — «пролёт камеры»; `feather` px; `edge` + `edgeWidth` (8) — светящееся кольцо по краю; `fill` — заливка под B внутри круга (гаснет ко второй половине); без `target` — точка `x`/`y` слоя и `w`×`h` |
| `zoom_through` | камера пролетает сквозь элемент `target` A (кнопку, карточку): он растёт по экспоненте `S^p` до «накрыл кадр» (`S = max(W/w, H/h)`) и едет в центр; B растёт вместе с камерой: в начале заполняет рамку элемента (cover — элемент становится кадром B), к концу — ровно 1:1 (масштаб — геометрическое среднее cover и `s/S` по ходу наезда), виден в рамке элемента (маска — рамка со скруглением `radius`·s) | `radius`, `feather`, `edge`; `fill` — непрозрачный фон рамки под B (A не просвечивает сквозь прозрачные места B), гаснет вместе с A; A гаснет на последних 30 %, B проявляется на 10–45 % |
| `shared_element` | элемент есть в обеих сценах: `target` (в A) едет и меняет размер в `match` (в B). Две фигуры одного вида — один слой, у которого плавно меняются props (числа, цвета `#rrggbb(aa)`, обводка, тень) — настоящий морфинг; иначе обе копии стоят в одном месте одного размера (по площади рамки), A гаснет, B проявляется | остальное A растёт на 10 % и гаснет к 55 %, остальное B — из 0.92 и проявляется с 40 % |
| `push_slide` | A и B одной лентой встык: A уезжает в `direction` (left/right/up/down), B въезжает с другой стороны, без щели | `dip` 0..0.4 (0.08) — камера «отъезжает» посередине (масштаб 1 − dip·sin πp); `distance` 0.2..1 (1) — путь в долях кадра: меньше 1 — сцены едут на часть кадра и перетекают прозрачностью (30–70 % хода), у редких сцен нет пустого кадра посередине |

Общее: ход `p` — `props.ease` (по умолчанию `inOutCubic`, можно `bezier(…)`) от `start` к `end`. Концы
точные: при p = 0 сцена A стоит как без перехода, при p = 1 сцена B — тоже (матрица единичная, маска на весь
кадр, прозрачность 1), поэтому ставится на стык: A кончается в `end`, B начинается в `start`.

**Группы.** Заданы `from`/`to` — они (слой из обоих списков — в B). Оба пусты — по времени: A — слои,
начавшиеся до перехода и кончающиеся в `start − 0.12 … end + 0.12`; B — начинающиеся в `start − 0.12 … end`
и живущие дальше. Группа рисуется на месте своего первого слоя по дорожкам; слой может быть только в одной
группе (первый переход по списку). У `shared_element` `target`/`match` не входят в группы — их рисует
морфинг на месте верхнего из двух.

**Рисование.** Группа — на промежуточный холст во весь кадр. Без 3D-слоёв матрица ставится прямо под слои
(вектор: пролёт в 10× остаётся резким); со слоями в перспективе (`z`, наклоны, `pivot`-наклон экрана —
space3d сам сбрасывает матрицу) группа рисуется как есть и переносится картинкой. Маска — только
`destination-out` (Skia и браузер одинаково трогают лишь покрытые пиксели): «оставить внутри» = стереть кадр
вокруг фигуры, «вырезать» = стереть фигуру; растушёвка — радиальный градиент у круга, `blur` пути у
прямоугольника. Нет фабрики холстов — матрица и прямая маска клипом. Motion blur слоёв группы на переходе
не считается. Всё — функция времени: превью = рендер (node/motion-flow.test.mjs сверяет кадр CLI и
`drawFrame`).

**Инструмент** `flow_transition(kind, at, duration?, from?|from_prefix?, to?|to_prefix?, target?, match?, x?, y?,
w?, h?, shape?, radius?, feather?, depth?, edge?, edge_width?, fill?, direction?, dip?, ease?, fit_timing?,
keep_in?)`. Длина по умолчанию: reveal 0.7, zoom 0.8, shared 0.7, push 0.55 с. `fit_timing` (по умолчанию да):
A живут ровно до `end` без своего `out`, B начинаются со `start` без своего `in` (`keep_in` — оставить), ключи
B сдвигаются на столько же, чтобы их абсолютное время не изменилось (props со своим временем — `focusAt`,
`stagger` — нет: ответ напоминает проверить кадр). Слой `transition` можно положить и через `add_layers` —
времена слоёв тогда на совести автора. Убрать — `remove_layers`.

### Затемнение за текстом (`backdrop`, scrim)

Эллипс-градиент за блоком текста: полуоси `0.6·ширина + spread` и `0.725·высота + spread` (`spread`
по умолчанию 0.9 кегля), цвет `color` плотностью `opacity` в центре (0.82 до половины радиуса, 0.35
к 78%, 0 на краю). Рисуется первым (под плашкой `bg` и буквами), своей тени не даёт; размер слоя
(рамка, промежуточный холст) его вмещает. Нужен, когда под титр заезжает наездом телефон или
пёстрый фон: `"backdrop": true` — чёрный 0.55.

### Корпус телефона (`device: "phone"` у `image` и `video`)

`layers/device.ts`. Экран — содержимое слоя: ширина `w`, высота по пропорции картинки/кадра (или окна
`crop`); скругление экрана — `radius`, 0 — как у iPhone (0.14·w). Вокруг: металлический пояс
0.017·w (градиент поперёк + тонкий блик по краю сверху-слева и снизу-справа), чёрная рамка 0.03·w,
боковые кнопки (слева кнопка действия и громкость, справа питание, выступ 0.012·w), «островок»
камеры 0.3·w × 0.088·w у верха экрана (`island: false` — без него). Размер слоя = корпус с кнопками;
`border` с корпусом не рисуется. Тень слоя отбрасывает силуэт корпуса. Пока содержимого нет (превью
грузит файл) — корпус с тёмным экраном. Шаблон «Запись экрана в телефоне» (`phone-screen`).

**Строка статуса** `statusBar` — полоса высотой `statusBar·w` над содержимым (экран становится выше на
неё, содержимое не сжимается и не обрезается): цвет `statusBarColor` (`#000000`), слева «9:41», справа
связь, Wi-Fi и батарея (белые на тёмном, чёрные на светлом). Нужна, когда в записи экрана нет своей
строки статуса — иначе островок ложится на шапку приложения. Поэтому **островок по умолчанию**: у
`image` (скриншот обычно со строкой статуса) — есть, у `video` — только со `statusBar`; `island: true/false`
— явно. **Блик** `screenGlare: true` — светлая диагональ сверху-слева с резким краем поверх экрана.

### Видео-слой: откуда кадры

Движок видео не декодирует: `env.getVideo(layer)` → `{duration, width, height, frame(time)}`
(синхронно), секунду файла считает `videoFileTime(props, local, duration)` (то же —
`app/motion.video_file_time`).

* **Превью**: свой `HTMLVideoElement` на слой (muted). Время превью идёт — элемент играет сам со
  скоростью слоя и подправляется при рассинхроне > 0.25 с; пауза/скраб — точный seek. Слой ушёл из
  кадра — пауза, через минуту без нужды элемент отпускается.
* **Рендер**: перед моушн-проходом `app/motion_render.prepare_video_frames` режет ffmpeg'ом каждому
  видимому слою только его отрезок файла в JPEG (`-q:v 2`): шаг `fps / speed` (на кадр выхода — один
  файл), ширина — сколько слой займёт на кадре (с наибольшим `scale` из ключей и самым узким окном
  `crop`, ×1.15, ≤ 1080 и ≤ исходника), не больше 9000 кадров на слой (дальше — стоп-кадр). Кадры
  лежат в work-папке прохода и удаляются вместе с ней. Компоновщик получает `--videos videos.json`
  (`{"<id слоя>": {dir, pattern "%05d.jpg", start, rate, count, duration}}`, кадр i — секунда
  `start + i / rate`), декодирует кадр к моменту отрисовки и пару следующих заранее, держит в памяти
  до 6 кадров на слой. Видео не нарезалось — слой без кадров, пометка в ошибке клипа.
* «Кадр для агента» (`/motion/frame`) режет по одному кадру на слой — тот, что виден в `t`.
* Слой с `hold: true` (стоп-кадр) — тоже один кадр (секунда `from`; у самого конца файла — за 0.25 с до
  конца), а не нарезка на всю длину слоя. В превью элемент встаёт на паузу на `from`.

### PNGtuber (`pngtuber`)

Аватар владельца в углу, который открывает рот, когда звучит его голос. Рот решает **сервер**, а не
движок — превью и рендер показывают одно и то же состояние в один и тот же кадр:

1. `app/pngtuber.py` перед компоновщиком читает звук дорожки голоса (моно 8 кГц, ffmpeg
   `app/source_audio.extract_args`, кусками по кускам клипа) и считает громкость каждого кадра слоя:
   RMS в дБ по окну 1/fps вокруг момента. Время слоя (шкала `clip` — редактор и кадр агента, `final` —
   рендер после вырезов) переводится в секунды источника через `app/timebase.ClipClock`: вырез или
   наплыв не сдвигает рот с голоса.
2. Громкость → состояния (`voice_states`): над `threshold_db` дольше `attack` — говорит; после спада
   рот держится открытым ещё `hold` (не хлопает между слогами); громче `shout_db` (только если есть
   `states.shout`) — кричит, с тем же attack/hold. `threshold_db: "auto"` (по умолчанию) — шум
   дорожки (15-й перцентиль) + 12 дБ, но не выше речи − 12 дБ (речь — 75-й перцентиль кадров громче
   шума на 6+ дБ) и не ниже −55 (пустая дорожка — запасные −45; ровная громкая без пауз — речь, порог
   на 12 дБ ниже неё). `hold` по умолчанию 0.15 с. Кадр агента слушает окно вокруг `t`, а порог "auto" берёт со всего слоя — как рендер.
3. `comp.voice = {"<id слоя>": {t0, fps, states: "000111122…", levels: [0..100], threshold_db}}` —
   кадр k — момент `t0 + k/fps`; `"0"` молчит, `"1"` говорит, `"2"` кричит; `levels` — огибающая для
   подскока (плавный спад ~80 мс). Нет записи / за краем массива — молчит.
4. Движок (`frontend/src/motion/layers/pngtuber.ts`): `voiceStateAt(track, t)` → файл состояния
   (`shout` → `talk` → `idle`), кадр его анимации — `animFrameIndex(times, duration, t)` по времени
   **клипа** (каждое состояние циклится своей анимацией, смена состояния не сбивает фазу). Статичная
   картинка — просто `getImage`.

Превью: `POST /api/clip-plans/{id}/voice {layers?, fps?}` → `{voice, notes}` — тот же массив в шкале
`clip`; кадр для агента считает голос в окне вокруг `t`. Нет файла источника / дорожки — аватар молчит,
пометка в ошибке клипа. Агенту проще `add_pngtuber` (docs/AGENTS.md, «PNGtuber»).

### Анимированные картинки с альфой (GIF, APNG, webm-alpha)

`app/anim_frames.py`: `animation_info(path)` — кадры, их времена (у GIF задержка своя у каждого кадра;
0 и 10 мс — 100 мс, как в браузерах), fps, альфа. Кадры: ffmpeg `-fps_mode passthrough -pix_fmt rgba
-c:v png` (webm с альфой — декодером `libvpx-vp9`), пиксель-арт (≤ 256 px) не пережимается, большие —
до ширины на кадре ×1.15 (≤ 1080), не больше 600 кадров. Компоновщик получает `--anims anims.json`
(`{"<asset_id>": {dir, pattern "%05d.png", count, times, duration, width, height}}`): маленькие анимации
держит в памяти целиком, большие (> 48 МБ RGBA) — окном кадров, как видео-слой. Превью берёт те же кадры
одним листом: `GET /api/montage-assets/{id}/anim` (`{animated, count, cols, rows, frame_w, frame_h,
times, duration, sheet}`) и `…/anim-sheet.png` (PNG с альфой, кэш в `runtime/anim-sheets`).

* Слой `image` с анимированным файлом играет его по кругу с **локального** времени слоя (гифка с
  первого кадра, когда слой появился); статичная картинка — как раньше.
* Анимированный WebP распознаётся (кадры, fps — из RIFF), но ffmpeg 8 его не декодирует: рисуется
  первый кадр, загрузка подсказывает «перегони в GIF/APNG».
* Загрузка (`POST /api/montage-assets`, `upload_image`, `vvf.py asset`) отвечает `animation {frames,
  fps, duration, alpha, decodable}` и `animation_note` — «анимированная картинка: 5 кадров, 16.7 fps».
* Webm с альфой (kind `video`) годится и слою `image`: рендер берёт его анимацией (`_resolve_ref`), превью
  играет сам файл в `<video>` (`anim` отвечает `video: true`; лист кадров большого баннера вышел бы мыльным).

**SVG → webm с альфой** (`app/svg_webm.py` + `node/svg-to-webm.mjs` — перенос
[svg-to-webm](https://github.com/yakoodev/svg-to-webm) владельца). SVG с CSS `@keyframes`/SMIL открывается в
headless Chromium (CDP через `--remote-debugging-pipe`, без Puppeteer; в образе — `/usr/bin/chromium`), на
каждый кадр все анимации ставятся на паузу и перематываются на его время (`pauseAnimations` +
`setCurrentTime`, `getAnimations()` → `currentTime`), PNG с прозрачным фоном потоком идёт в ffmpeg
(`libvpx-vp9`, `yuva420p`, `alpha_mode=1`, crf 18). Кадров ровно `round(duration·fps)`, тяжёлый SVG просто
считается дольше. Шрифты сервиса (`vendor/fonts`, `data/fonts`) подключаются по семействам из текста SVG;
`<script>`/`on*` вырезаются, сеть браузеру закрыта; `data-fit="<px>"` у `<text>` ужимает кегль до ширины.
Без `duration` — доминирующая длительность анимаций SVG (как у оригинала), `strip_bg` — убрать первый
прямоугольник-фон. Кэш — по sha256 SVG + параметров: файл `data/montage_assets/svg-webm/<хеш>.webm` и тот же
файл библиотеки (тот же `asset_id`). Браузер — один за раз и закрывается после конвертации. Вход:
`POST /api/svg-to-webm {svg | asset_id, duration?, fps?, width?, height?, scale?, strip_bg?, label?}`, MCP
`svg_to_webm`; SVG-баннер рендера (`POST /api/banners` с `.svg`) переводится в webm сам.

### Концовка-баннер (`render.end_screen`)

Отдельное решение монтажа, а не ещё один титр (`app/end_screen.py`): на последних `duration` с готового
ролика основа плавно уходит в размытие и темнеет, поверх — анимированный баннер.

```jsonc
"end_screen": {"duration": 3, "blur": 18, "dim": 0.35, "ramp": 0.6,   // 1.5..8 с; px сигмы 0..60; 0..0.8; 0.1..2 с
               "template": "live", "svg_asset_id": null,              // шаблон или свой SVG из библиотеки
               "asset_id": 41,                                         // собранный webm баннера
               "text": "Стримлю с 8 утра — заходи", "handle": "sareamura", "platform": "twitch",
               "accent": null, "days": "пн–пт", "time": "8:00 МСК", "font": ""}
```

* **Размытие — фильтр, не слой.** Компоновщик между основой и слоями зовёт `paintEndScreen`
  (`frontend/src/motion/endscreen.ts`): всё, что уже на холсте (видео, фон раскладки, слои `behind`), —
  размытие с сигмой `blur·min(W,H)/1080` и чёрный поверх с `dim`; ход `inOutCubic` за `ramp`. Размытие
  считается на уменьшенной копии с краями «edge-clamp» (у кромки нет каймы и наезда). Слои, баннер,
  субтитры — резкие. Превью редактора (`preview/frame.ts`) зовёт ту же функцию на холсте основы.
* `comp.endScreen = {start, ramp, blur, dim}` (`app/end_screen.comp_end_screen`): `start` — начало слоя
  `end_banner` в этой композиции (вырезы и стоп-кадры его уже сдвинули), без слоя — `duration − end_screen.duration`.
  Концовка без слоёв и камеры тоже включает моушн-проход (`plan_motion`).
* **Баннер** — слой `image` `end_banner` (дорожка 7, `w` 960, `y` 0.44, без in/out — анимация в самом
  webm) на `tail_start(cuts, длина, duration)` … конец; webm на 0.5 с длиннее слоя (не начнётся заново).
  Шаблоны (`TEMPLATES`, SVG собирается в Python, анимации CSS с `cubic-bezier(.16,1,.3,1)` и пружинкой на «поп»,
  stagger 0.06–0.1 с, свечение фильтрами): `live` — стеклянная карточка, красная пилюля LIVE с пульсирующей
  точкой и кольцом, фраза крупно (после « — » вторая строка акцентом), ник со значком площадки (глифы
  `PLATFORM_ICONS` слоя `nameplate`), кнопка-стрелка, блик по стеклу; `schedule` — дни недели чипами,
  время крупно с неоновым свечением; `neon` — ник светящейся обводкой (рисуется и вспыхивает), адрес канала.
  Акцент по умолчанию — цвет площадки; шрифт заголовка — Unbounded (или `font`), текст — Manrope.
* Удалили слой `end_banner` руками — концовка снимается целиком (`normalize_render_settings`); редактор, не
  знающий поля, его не стирает (`PATCH …/render-settings` без `end_screen` оставляет сохранённое).
* Правило «не закрывай видео» (≤ 40 % кадра) к `end_banner` не относится — под ним размытое видео.
* Бренд: `cta.style = "banner"` (+ `template`, `blur`) — `apply_brand` ставит концовку-баннер вместо плашки
  `brand_cta` (текст — `cta.text — cta.url_text`, ник и площадка — `nameplate`, шрифт и акцент — бренда);
  нет браузера — плашка, как раньше, с пометкой.
* API: `POST /api/clip-plans/{id}/end-screen` (поля выше + `y`, `w`, `brand_id`), `DELETE` — снять;
  `GET /api/end-screen/templates`; MCP `set_end_screen`.

### Анимированные субтитры (`captions`)

Слова речи приходят не в слое, а в композиции: `comp.words = [{t0, t1, w}]` —
секунды готового клипа, по слову на запись. Их подставляет хост: редактор — из
субтитров клипа (`{word, start, end}` → `captionWordsFrom()`), рендер — из
сохранённых субтитров клипа (`clip_plans.subtitles_json.words`, со сдвигом на
переходы, как у прожигаемых субтитров; `app/motion_render.py::plan_caption_words`).

* Слой показывает только слова, чьё `t0` попадает в `[start, end)` слоя.
* Страницы: слова режутся на фразы по паузам > 0.6 с и концу предложения, фраза —
  на страницы поровну по `maxWords` (4 слова при 3 → 2 + 2), страница шире
  `maxWidth` × `maxLines` — дробится по ширине. Страница видна от `t0` первого слова
  до `t1` последнего + 0.45 с (но не дольше начала следующей; зазор < 0.35 с
  перекрывается — без мигания).
* Активное слово — последнее начавшееся. Оно увеличивается до `wordScale` и
  раздвигает соседей (строка остаётся по центру).
* Эмфаза слова — `comp.words[i].e` (1 pop, 2 shake; из `subtitles.words[i].emph`,
  `app/word_emphasis.py`): слово всю страницу крупнее в `emphScale` раз (уровень 2 — сильнее) и
  цветом `emphColor` (нет — `activeColor`; цвет `highlightWords` главнее); разбивка на строки
  считает его ширину с масштабом, строка с ним выше. В его момент — прыжок +28% за 0.09 с и назад к
  0.32 с, у уровня 2 — ещё затухающая встряска (сдвиг и поворот, шум от номера слова — превью ==
  рендер). Работает поверх любой `animation`.
* Низ блока не опускается ниже 82% высоты кадра (интерфейс TikTok/Shorts), даже
  если `y` ниже — блок поднимается. В кадре 1:1 / 4:5 — ниже 94%, в 16:9 — ниже 93%
  (поля площадок, `SAFE_ZONES` в formats.ts, app/safe_zones.py).
* Пресеты — `CAPTION_STYLES` движка (`{id, name, description, props}`); UI берёт
  оттуда список и превью, props слоя перекрывают пресет.
* Рендер: если у клипа есть видимый слой `captions` и сохранённые субтитры, прожигаемые
  субтитры (ASS) **не** накладываются — слой их заменяет. Субтитров нет — слой пуст,
  обычные субтитры жгутся как раньше, в ошибке клипа пометка.

### Чат стрима (`chat`)

Сообщения — в композиции: `comp.chat = [{t, user, color, text, fragments, badges}]`,
`t` — секунды готового клипа, по возрастанию. Это ровно ответ
`GET /api/clip-plans/{id}/chat` (`fragments`: `{text}` или `{emote, url}`, `badges`:
`{id, url}`). Его подставляет хост: редактор — запросом, рендер —
`app/motion_render.py::attach_chat` (тот же `clip_messages`, что и у ручки).

* Слой показывает сообщения, у которых `start ≤ t − delay < end`, и прошедшие фильтр
  (`minLength` символов, ссылки, команды «!…»; пустые без эмоутов — никогда).
* Колонка шириной `w`, якорь — её центр; высота рамки — `maxMessages` строк. Новые
  сообщения появляются снизу (въезд снизу-слева + проявление за ~0.3 с), стопка
  плавно уезжает вверх; сообщения старше `maxMessages` и старше `ttl` гаснут.
  Всё — функция времени, без состояния: превью == рендер.
* Ник — цветом пользователя (слишком тёмный на тёмной подложке осветляется, светлый
  на белом пузыре — затемняется), значки — перед ником, эмоуты — картинками высотой
  ~1.3 кегля внутри строки; длинные слова режутся по буквам.
* Картинки эмоутов и значков: ссылка `url:<адрес>` (`chatImageRef(url)`). Браузер
  грузит адрес напрямую (`assetUrl("url:…")` → адрес; кросс-доменная картинка «портит»
  канвас для getImageData, но рисовать можно). Рендер: бэкенд скачивает адреса в
  `runtime/emote-cache/<sha1(url)>.img` (таймаут 5 с, до 400 картинок, неудачные —
  пропускаются) и кладёт их в `assets.json` под ключом `url:<адрес>`. Не нашлась
  картинка — эмоут пишется своим именем, значок не рисуется.
* Чата у клипа нет — слой пуст, в ошибке клипа пометка; рендер идёт дальше.

## Движок сцен (`scene`)

`frontend/src/motion/scene/`, слой — `layers/scene.ts`; полная схема, примеры, пределы и замеры —
[scene-engine.md](scene-engine.md). Программный рендер на том же 2D-холсте (без WebGL), поэтому
превью = рендер пиксель в пиксель. Конвейер кадра: камера и свет в момент `t` (секунды слоя) →
обход узлов (перенос · поворот X→Y→Z · масштаб, enter/exit, stagger, repeat, follow-path, частицы)
→ грани сеток в пространство камеры → отсечение тыльных граней и ближней плоскости → цвет
(flat/lambert/toon/gradient/halftone/hatch, rim, блик, туман; у гладких — полосы по сглаженным
нормалям) → проекция → сортировка художника (`order`, затем глубина центра) → рисование с обводкой
силуэта и изломов. Единица сцены — опорный px на z = 0 у камеры по умолчанию, y вверх.
Анимация любого числа: ключи, переход с ease или пружиной, `rate`/`wiggle`/`osc`, безопасные
выражения `"=…"` (свой разборщик, без eval). JS-скрипты как формат не поддерживаются (небезопасно).
Сам слой — обычный: ключи, `in`/`out`, `followCamera`, `z`/`rotX`/`rotY` клипа поверх.

## 3D: глубина, перспектива, камера

`frontend/src/motion/space3d.ts` (движок), `app/camera3d.py` (пресеты). Псевдо-3D (2.5D): слои — плоские
картинки в пространстве, камера смотрит на них с перспективой. Старые слои и ключи камеры без 3D-полей
рисуются ровно как раньше (проверка `node/motion.test.mjs` «3D»).

**Мир.** Пиксели кадра: x вправо, y вниз от центра кадра, z — вглубь (плюс — дальше, минус — ближе к
зрителю), в опорных px слоя. Плоскость кадра — z = 0; камера смотрит на неё с фокусным `f0` (поле зрения 40°
по вертикали, у 1920 px — 2638 опорн. px), поэтому в покое z = 0 ложится на кадр один в один. Точка на
глубине z видна в `f0 / (f0 + z)` раза мельче: z = 600 — в 0.81, z = −300 — в 1.13; ближе ≈ −2400 — за
камерой, не рисуется.

**Слой.** `z` — глубина; `rotX` — наклон вокруг горизонтали (плюс — верх уходит вглубь), `rotY` — поворот
вокруг вертикали (плюс — правый край уходит вглубь), оба вокруг центра слоя после его `rotation` и `scale`.
Все три анимируются ключами (`keys.z`, `keys.rotX`, `keys.rotY`) и складываются с базой как остальные свойства.
Слой с заданной `z` (хоть 0) — **в сцене**: едет с 3D-камерой и плоским наездом, как `followCamera`; без `z` и
без `followCamera` слой стоит на экране (титры, субтитры), но наклоны рисуются с перспективой камеры покоя.
Изнанку (слой повёрнут спиной, |rotY| > 90°) не видно. Порядок рисования — по `track`, не по z.
Пределы: z −2000..20000, наклоны ±720°.

**Камера.** У ключа `render.camera` — `z` (dolly, опорн. px: плюс — камера ближе к сцене, ±2400), `rotX` /
`rotY` (наклон и облёт вокруг центра плоскости кадра, ±60°; облёт — мир поворачивается в обратную сторону),
`fov` (поле зрения по вертикали 10..120°, 40 — покой: меньше — «телевик», глубина сжата; фокусное меняется
без движения камеры), `baseZ` (глубина видео-основы, по умолчанию 1000). Интерполяция — те же отрезки и
`ease`, что у наезда; нет поля у ключа — покой. Плоский наезд (`zoom`/`x`/`y`/`shake`) работает поверх
3D-проекции, как раньше. В раскладке стрима (окно игры, окошко pip) 3D-поля не действуют — только наезд.

**Видео-основа** — плоскость на глубине `baseZ`, растянутая в `(f0 + baseZ)/f0` раз: в покое ровно кадр, при
движении камеры едет медленнее ближних слоёв — параллакс. При облёте и наклоне плоскость доувеличивается ровно
настолько, чтобы край основы не показался (`baseCover`, как запас под тряску), плюс 2 px.

**Перспектива на Canvas 2D.** WebGL в `@napi-rs/canvas` нет, аффинной матрицы для наклона мало. Слой с
наклоном (или любой слой в сцене при облёте/наклоне камеры) рисуется плоским на промежуточный холст и
переносится сеткой: ячейка — два треугольника, каждый своим аффинным преобразованием по точной проекции
вершин; ячеек — по перекосу глубины, чтобы ошибка аффинности была ≤ 0.5 px (у основы — 1.5 px), не больше
12×12. Треугольники кладутся в буфер режимом `copy` с клипом, расширенным на 1.5 px (перекрытия
перезаписываются, а не складываются — на полупрозрачном шов не темнеет; остаток — ≤ 10 % альфы на 1 px), потом
буфер — на кадр с режимом наложения слоя. Непрозрачная основа — прямо на кадр. Без наклонов (только z,
dolly, `fov`) проекция аффинна — обычная матрица, без буфера. Всё — функция времени и ключей: превью и рендер
совпадают кадр в кадр.

**Цена (замер CLI 1080×1920, 90 кадров с кодированием).** 4 плоских слоя — 67 кадр/с; те же слои в сцене +
облёт камеры (основа и все слои с перспективой) — 26 кадр/с; телефон с наклоном и тенью + подпись + облёт — 15
кадр/с (плоский вариант той же сцены — 33). Без 3D-полей — без изменений.

**Превью.** Холст видео редактора рисует основу плоскостью (`drawBasePlane`), холст слоёв — слои; рамка
выделения слоя с глубиной — по проекции его центра (наклон рамка не показывает).

### Пресеты движения (`camera_preset`, `POST /api/motion/camera-preset`)

Одна команда пишет ключи на отрезке `start..start + duration` (ключи камеры внутри заменяются, снаружи
остаются, плоский наезд на краях сохраняется); `intensity` 0.2..2 (1). Кривые — мягкий in/out
`bezier(0.45,0,0.55,1)`, перелёт `bezier(0.34,1.45,0.64,1)` — только у раскрытия и переворота.

| preset | что | длина | конец |
|---|---|---|---|
| `parallax_push` | dolly вперёд на 320·i, наклон −2°: ближние слои растут быстрее видео и дальних | 2 с | держится |
| `orbit` | облёт −10° → +10° (·i) с dolly 90 и наклоном ±2° | 3 с | покой |
| `dolly_zoom` | эффект Хичкока: камера отъезжает на 1600·i, поле зрения сужается так, что z = 0 стоит, фон «наезжает» | 2 с | держится |
| `tilt_reveal` | с `start` камера в наклоне 16°·i и выпрямляется с лёгким перелётом (до `start` стоит — ключ `step`) | 1.6 с | покой |
| `float` | медленное «дыхание»: наклон ±1.5°, облёт ±2.5°, dolly до 70 | 4 с | покой |
| `card_flip` | переворот слоя `layer_id`: `rotY` 90° (ребро) → 0 с перелётом — ключи слоя | 0.9 с | слой лицом |

«Держится» — до следующего ключа камеры (ключ без 3D-полей — возврат в покой по его `ease`). Нет слоёв в
сцене — ответ подсказывает дать им `z`. `GET /api/motion/camera-presets` — список для UI. Шаблоны галереи
(категория «3D»): «Телефон в пространстве», «Заголовок с глубиной», «Карточки веером».

## CameraKey — наезды камеры

```jsonc
"camera": [
  { "t": 4.0, "zoom": 1.0, "x": 0.5, "y": 0.5, "ease": "inOutCubic" },
  { "t": 4.3, "zoom": 1.35, "x": 0.5, "y": 0.4 },
  { "t": 6.0, "zoom": 1.35, "x": 0.5, "y": 0.4 },
  { "t": 6.2, "zoom": 1.0,  "x": 0.5, "y": 0.5 }
]
```

`t` — клиповое время; `zoom` 1..4; `x`, `y` — точка кадра, которая остаётся в центре
(зажимается так, чтобы за кадр не вылезти). Между ключами — интерполяция с ease
(ease левого ключа; отсутствующее поле ключа = 1 / 0.5 / 0.5 / 0).
Камера двигает **только видео** (под субтитрами, баннером и слоями) — и слои с
`followCamera: true`: движок (`drawFrame`, `comp.camera`) рисует их в той же матрице, что
кадр основы (`frameCameraMatrix`: с хромакеем — во весь кадр, в раскладке стрима — внутри
`comp.cameraBox`). Слой стоит в своих `x`/`y` «на видео» и уезжает/увеличивается вместе с ним;
тень и blur не масштабируются зумом. По умолчанию `false` — старые клипы не меняются.
Рамка выделения и перетаскивание в редакторе учитывают камеру (`layerBox(…, cam)`).
Отдельное поле `shake` у ключа (0..1) — тряска для «бума»: амплитуда 2% кадра при 1,
интерполируется как остальные поля (затухание — ключом с `shake: 0`). Чтобы тряске
было куда двигаться, камера сама чуть доприближается (зум ≥ 1/(1 − 0.04·shake)) —
край кадра никогда не виден.
Поле `anchor` у ключа: `"center"` (по умолчанию, как выше) или `"in_place"` — `x`/`y` не
центр, а **точка наезда**: она остаётся на своём месте в кадре, кадр масштабируется вокруг
неё (центр окна = p + (0.5 − p)/zoom — край кадра не открывается). Для раскладки «титр слева,
медиа справа» (16:9): наезд на медиа не утаскивает его под титр. Между ключами, где хоть один
«на месте», зум и точка идут плавно (центр-ключ с zoom 1 берёт точку соседа) — точка стоит
весь наезд и возврат. Зеркала: `app/promo_lint.camera_view`, `app/aspect._camera_view`.
Поле `motionBlur` у ключа (0..1) — motion blur основы на отрезке от этого ключа (быстрый whip/панч
смазан, покой и медленный наезд — резко); нет — значение клипа `render.motion_blur`. См. «Motion blur».

## Трекинг слоя (`layer.tracking`)

`app/tracking.py`. Слой (эмодзи, стикер, стрелка, плашка, текст) следует за целью в кадре: сервис
пишет ему обычные ключи `x`/`y` (и `scale`), движок о трекинге не знает — превью и рендер рисуют
ключи как всегда.

* **Где ищется цель.** Не в исходнике, а в **кадрах основы клипа**: тот же граф ffmpeg, что у рендера
  и `/motion/frame` (`motion_render.frame_preset` + `render._render_filter`: рефрейм x(t), кроп полей,
  раскладка split/pip/meme, «шире окна», зеркало, хромакей, формат вывода), 8–10 кадр/с (прореживание —
  на входе графа, время сдвинуто `setpts` на секунду куска: выражение рефрейма считает от начала куска),
  кадр детекции — до 960 px по длинной стороне. Значит, координаты цели — сразу доли кадра клипа, и
  переводить из исходника нечего. Слои размечены в другом формате, чем вывод, — отказ («разметить слои
  в этом формате»).
* **Цели** (`target`): `face` — лица YuNet (как автофокус; без модели — Haar); `object` + `class` — YOLOX,
  класс COCO (`person`, `car`, `dog`… или по-русски «человек», «машина»); `mode` `largest` (самое
  крупное), `near` (ближе к `x`, `y` в момент `t`), `index` (i-е слева). `point` — точка/область вручную
  (`x`, `y`, `t`, `w?`, `h?`, по умолчанию квадрат 12 % ширины): шаблон области ищется в окне вокруг
  прогноза нормированной корреляцией (`cv2.matchTemplate`, без OpenCV — то же через numpy FFT), медленно
  обновляется на уверенных кадрах, исходный шаблон страхует от сползания; трек идёт от кадра `t` вперёд
  и назад. Точка задаётся как её видно на превью / `view_frame` (с наездом камеры) — сервис переводит её
  в основу до камеры (`screen_to_base`). Размытая копия кадра (подложка `blur_background`) отсекается по
  резкости рамки.
* **Связывание и пропуски.** Детекции кадров — в один трек от кадра-семени вперёд и назад: следующая
  рамка — ближайшая к прогнозу (центр + скорость·dt) в воротах ~размера цели (на стыке кусков и после
  потери — шире). Нет рамки — прогноз до 0.8 с (`p`), дальше цель «потеряна» (`l`): стоит на месте и
  ищется снова. Цель видна меньше чем в 40 % кадров — отказ с интервалами потерь.
* **Сглаживание** — Калман с постоянной скоростью + проход назад (RTS): без запаздывания и без
  «притяжения» краёв; прогнозы и потери тянут слабо. `smooth` 0..1 (0.5 ≈ полоса 1 Гц). По кускам отдельно.
* **Ключи.** Во времени слоя, `ease: "linear"`, Дуглас–Пекер (≈ 1.3 px кадра 1080×1920, ≤ 200 точек); последний
  ключ куска перед стыком — `step` (слой не «проезжает» склейку). `offset {x, y, units, dx, dy}` — сдвиг от
  центра цели (`units: "target"` — в размерах цели, `"frame"` — доли кадра; `dx`/`dy` — опорные px);
  `follow {x, y, scale}` (`scale` — `layer.scale × размер цели / медиана размера`, у точки нет). Базовые
  `x`/`y` слоя — первый ключ трека (сняли трек — слой стоит там, где он начинался).
* **Пометка** `tracking: {target, offset, follow, smooth, props, range, fps, preset?}` — какие ключи записал
  трек: повторный запуск их заменяет (чужие ключи слоя не трогает), снятие (`untrack`) убирает. Вырезы,
  стоп-кадры-вставки и правка кусков (`app/cuts.remap_layers`, `app/piece_remap.py`) двигают ключи такого
  слоя вместе с кадром, даже если поставлены после трека: у краёв разрыва ставятся опоры с
  интерполированным значением, потом время переводится как у любых ключей.
* **Камера.** Ключи — координаты основы ДО наезда, слою ставится `followCamera` (едет и зумится с видео);
  цель в окошке раскладки, которое камера не двигает (pip, полоса вебки split), — `followCamera: false`.
  3D-камера: параллакс основы трек не повторяет (пометка в ответе).
* **Нагрузка.** Кадры + детекция — в очереди тяжёлых задач (`heavy_slot("tracking")`), сырые сэмплы
  кэшируются в `runtime/tracking/` по источнику (размер и время файла), кускам с фокусом, раскладке,
  формату, цели, диапазону и fps: смена отступа, пресета или плавности детекцию не повторяет.
* **Подсказки** (`preset`): `above_head` — эмодзи на голову (над лицом на его высоту, растёт с лицом);
  `under_face` — плашка с именем под лицом; `arrow_to` — стрелка из нижнего левого угла цели, поворот −45°,
  кончик у цели; `on_target`. Слой не должен закрывать лицо: ответ предупреждает, если перекрывает его
  больше чем на четверть в 20 % кадров.

API: `POST /api/clip-plans/{id}/track {layer, target, offset?, follow?, smooth?, fps?, preset?}` → `{job_id}`
(ничего не сохраняет), `GET /api/track-jobs/{id}` → `{state, progress, stage, result: {layer, report}, error,
hints}`, `GET /api/motion/track-presets`. MCP — `track_layer` / `untrack_layer` (docs/AGENTS.md). Редактор —
кнопка «Следовать за…» в «Положении» инспектора слоя: цель, клик по превью, ход.

## Рендер

Порядок в рендере клипа (реализовано: `app/render.py` + `app/motion_render.py`):

1. Основа: куски, кроп/рефрейм, лук, переходы — **без баннера**, если есть видимые
   слои или камера.
2. **Моушн-проход** (видимые не-`audio` слои или ключи камеры): Node-компоновщик
   читает основу покадрово, применяет камеру, рисует слои, кодирует видео без звука.
3. Дешёвый ffmpeg-проход: звук основы обратно (`-c:a copy`), видео копией; если у
   клипа баннер — он накладывается здесь, **поверх слоёв** (камера его не зумит).
4. Субтитры и музыка (`_finalize_render`) — поверх камеры **и слоёв**: субтитры всегда
   читаемы, слои под ними.
5. Обложка, вставки «Файлов для монтажа» — как было.
6. Звуки `audio`-слоёв и звук `video`-слоёв с `audio: true` — последним проходом (видео копией):
   adelay на `start`, `-ss offset`/`from` (у видео ещё atempo по `speed`, aloop по `loop`), volume, afade in/out, `duck` = громкость исходника ×0.3 на время
   звука (volume с enable). Последним — чтобы распознавание субтитров слышало
   чистую речь (то же правило, что у музыки).

Итог по Z снизу вверх: видео (с камерой) → слои → баннер → субтитры → вставки.

Нет ни видимых слоёв, ни камеры — рендер побайтно прежний (те же команды ffmpeg).
Клип с одними `audio`-слоями картинку не трогает: только шаг 6.

Сбой компоновщика (нет сборки, нет Node, ошибка, таймаут 30 мин —
`MOTION_TIMEOUT_SECONDS`) не теряет клип: остаётся основа (с баннером), причина —
в `error` клипа («моушн не наложен: …»). Слой, чей файл не найден (id файла для
монтажа, `emoji:`/`sticker:`/`sfx:` через `app.motion_assets.resolve_pack_ref`),
пропускается с пометкой в `error`; у `callout` пропадает только значок.

Настройки: `MOTION_NODE` (по умолчанию `node`), `MOTION_COMPOSITOR`
(`<корень>/node/motion-render.mjs`, в контейнере `/app/node/…`), `MOTION_FONTS_DIR`
(`<корень>/vendor/fonts`), `MOTION_TIMEOUT_SECONDS` (1800).

`assets.json`: ключ — id файла для монтажа строкой (`"7"`) или ссылка как есть
(`"emoji:1f525"`, `"sticker:pack/a.png"`); значение — путь к файлу. `asset_id` в
слоях бэкенд хранит строкой цифр.

Имя эмодзи — по правилам файлов Twemoji: кодовые точки в hex через `-`, селектор
FE0F выкидывается, если в последовательности нет ZWJ (`❤️` → `emoji:2764`,
`👁️‍🗨️` → `emoji:1f441-fe0f-200d-1f5e8-fe0f`). Картинки нужны не только слоям
`emoji`/`image` и значку `callout`, но и эмодзи **внутри текста** (`text.text`,
`counter.prefix/suffix`, `callout.title/subtitle`) — список всех ссылок даёт
`collectImageRefs(layers)` из движка; проще всего передать компоновщику
`--emoji-dir` (тогда `emoji:*` без записи в assets.json берутся оттуда). Не нашлась
картинка — эмодзи рисуется символом системного шрифта, ошибки нет.

### CLI компоновщика

```
node node/motion-render.mjs \
  --comp comp.json        # {"width":1080,"height":1920,"fps":30,"duration":42.1,"layers":[…],"camera":[…],"words":[{t0,t1,w}…]?,"chat":[{t,user,…}…]?,"levels":{voice|music|mix:{t0,fps,v}}?}
  --input base.mp4        # видео основы (без него — прозрачный фон, только слои)
  --output motion.mp4     # видео без звука (h264, yuv420p, crf из --crf, по умолчанию 18)
  --assets assets.json    # {"<asset_id>": "/data/.../file.png", "emoji:1f525": "...svg", ...}
  [--videos videos.json]  # кадры видео-слоёв: {"<id слоя>": {dir, pattern, start, rate, count, duration}}
  [--anims anims.json]    # кадры анимаций с альфой: {"<asset_id>": {dir, pattern, count, times, duration, width, height}}
  --fonts-dir /app/vendor/fonts   # fonts.json + файлы шрифтов
  [--emoji-dir DIR]               # запасной путь для emoji:<код> → DIR/<код>.svg
  [--ffmpeg ffmpeg] [--ffprobe ffprobe] [--crf 18] [--preset veryfast]
  [--frame 3.2 --png out.png]     # один кадр в PNG — для тестов и для «кадра» ИИ-агенту

node node/motion-render.mjs --list-templates             # JSON шаблонов галереи (id, name, category, params)
node node/motion-render.mjs --build-template job.json    # job {id, params?, at?, format?} → {layers, camera?}
```

Код выхода: 0 — готово, 2 — ошибка аргументов, 1 — прочие ошибки; текст в stderr.
Прогресс — строки `progress <frame>/<total>` в stderr (каждые 30 кадров и в конце;
с `MOTION_DEBUG=1` — ещё и память процесса).

* Основа приводится к кадру композиции: `fps`, масштаб с сохранением пропорций +
  чёрные поля. Матрица цвета берётся из основы (ffprobe): bt709 туда и обратно,
  иначе как есть — цвета клипа не плывут. Без основы выход помечен bt709.
* Основа короче `duration` — до конца держится её последний кадр; длиннее — лишнее
  не читается. Кадров на выходе ровно `round(duration·fps)`.
* `--frame T` за концом основы — берётся её последний кадр.
* `comp.cameraBox {x,y,w,h}` и `comp.pinned [{x,y,w,h}]` (px кадра) — раскладка стрима
  (`app/stream_layout.camera_regions`): камера двигает только кадр внутри `cameraBox`
  (окно игры), прямоугольники `pinned` (окошко вебки pip) кладутся поверх из незумленной
  основы. Без них камера, как раньше, двигает весь кадр.
* `comp.freezes [{at, d, insert, hold}]` — стоп-кадры посреди ролика (`app/freeze.py`,
  инструмент `freeze_frame`), если хоть на одном слои стоят (`hold`). Основа уже со
  стоп-кадрами (ffmpeg до компоновщика); слои, камера, слова и кадры видео-слоёв читаются во
  «времени слоёв» `motionTime(u)`: на стоп-кадре с `hold` оно стоит на `at`, после вставки
  (`insert`) идёт за вычетом её длины. Стоп-кадры без `hold` («слои анимируются дальше»)
  сервис сам сдвигает в слоях (`FreezeMap`), компоновщику они нужны только для счёта сдвигов.
  `at` — секунда без стоп-кадров.
* `comp.baseHeight` (> `height`) и `pinned[].sy` — основа выше кадра на полосу окошка
  (`app/render.pin_band`, при камере в раскладке pip): строки `0..height` — игра **без**
  окошка (её и зумит камера), ниже — строки собранного кадра с окошком; окошко `pinned[i]`
  берётся из основы с строки `sy` и кладётся на `x, y`. Раньше окошко было в самой основе:
  наезд увеличивал и его, рядом с неподвижным появлялась вторая, большая копия. Выход —
  всегда `width×height`. Упал компоновщик — сервис собирает прежний кадр из полосы
  (`build_unband_args`).
* `comp.key {color: "0xrrggbb", similarity, blend, despill, spill?, grade}` — хромакей основы
  (`app/chroma_key.py`, ключ источника): компоновщик вырезает фон (ffmpeg `chromakey`), кладёт
  `comp.background`, слои `behind`, сверху основу. `despill` `green`/`blue` без `spill` —
  фильтр ffmpeg `despill` по умолчанию (ключ источника `despill: "auto"`, как было: свой канал
  опускается до среднего двух других — жёлтое в кадре рыжеет, зелёное сереет); `"none"` — без
  подавления ореола; `spill` 0..1 — мягкая сила (`despill=type=green:green=-s`, у синего
  `blue=-s`). Превью (`frontend/src/pages/workspace/chromaKey.ts`) считает ту же формулу.
* Слою, который идёт до конца композиции (`end ≥ duration − 0.05`), сервис
  (`app/motion_render.write_comp`) снимает `out`: готовый ролик держит последний кадр
  стоп-кадром, и плашка не гаснет перед ним. Музыка клипа доигрывает и затухает на этом
  стоп-кадре (проход музыки тянет её на `RENDER_END_HOLD_SEC`, финальный проход держит
  кадр ровно на хвост звука).
* `comp.endScreen {start, ramp, blur, dim}` — концовка-баннер: с `start` основа (с фоном и слоями `behind`)
  размывается и темнеет под слоями (см. «Концовка-баннер»).
* `comp.motionBlur` (0..1, необяз.) — затвор клипа по умолчанию (`render.motion_blur`): слоям и ключам
  камеры без своего `motionBlur`; быстрая камера — подкадры основы (см. «Motion blur»).
* Без `--input`: `.mp4` — слои на чёрном; `.mov` — ProRes 4444 с альфой.
* Кадры идут потоком (один кадр в памяти), запись в кодировщик ждёт `drain`.
  Скорость на обычном CPU — около 45–50 кадр/с для 1080×1920 с десятком слоёв
  (60-секундный клип ≈ 40 с).

### Шрифты

`vendor/fonts/fonts.json`: `[{ "family": "Montserrat", "file": "Montserrat-Black.ttf",
"weight": 900, "style": "normal", "cyrillic": true, "tags": ["display"] }, …]`.
Браузер подключает те же файлы через `/api/motion/fonts` + `@font-face`.
Свои шрифты (app/user_fonts.py) — `data/fonts/` с реестром `data/fonts/fonts.json` той же схемы
(+ `user`, `variable`, `weight_range`, `axes`): загрузка `POST /api/motion/fonts` (multipart `file`
TTF/OTF/WOFF2 ≤ 20 МБ, `family?`, `weight?`, `style?`), удаление `DELETE /api/motion/fonts/{file}`,
агенту — `upload_font`; компоновщику — `--user-fonts-dir`. Шрифты комплекта — статические файлы на
каждое начертание. Вариативный свой: Skia (компоновщик) сама берёт только начертание по умолчанию,
поэтому сеттер `ctx.font` в node/motion-render.ts ставит `fontVariationSettings` (`"wght"` — толщина
из строки шрифта, `"opsz"` — кегль, как `font-optical-sizing: auto`); браузер — FontFace с диапазоном
`weight_range`. Статические начертания не генерируются (fontTools нет в зависимостях). Строка шрифта
одна и та же в превью и рендере — `fontString()` движка:
`[italic ]<weight> <size>px "<family>", "Montserrat", "Rubik", "Inter", …, sans-serif`.
Пустое `font` — семейство по умолчанию (`Montserrat`).

## API

* `GET /api/motion/fonts` — список шрифтов; `GET /api/motion/fonts/{file}` — файл; `POST /api/motion/fonts` — свой шрифт, `DELETE /api/motion/fonts/{file}` — убрать свой.
* `GET /api/motion/templates` — шаблоны (готовые наборы слоёв с параметрами).
* Агент и MCP: `list_motion_templates(category?, q?)` и `add_motion_template(template, params?, at, duration?)` —
  те же шаблоны через `--list-templates` / `--build-template` компоновщика (app/motion_template_tools.py), вставка —
  как `add_layers`. Категория «Плоский UI» и параметр `theme` (red/dark/light/brand; у старых `counter`, `progress`,
  `top-3`, `lower-third-*` — ещё `classic`, по умолчанию) — [flat-ui.md](flat-ui.md); тема `brand` без `accent`/`plate`
  берёт цвета бренда проекта.
* `GET /api/motion/emoji/{code}.svg`, `GET /api/motion/packs/...` — стикеры/звуки паков.
* `POST /api/clip-plans/{id}/motion/frame?t=3.2` — PNG кадра готового вида (для агента).
  Тело необязательно: `{layers?, camera?}` — несохранённый вариант. Основа кадра —
  исходник с кропом/рефреймом/луком (без баннера и субтитров), готовый рендер — только
  если исходника нет. Нет компоновщика — 503.
* `POST /api/clip-plans/{id}/voice` — тело `{layers?, fps?}` (нет слоёв — сохранённые) →
  `{voice: {id слоя: {t0, fps, states, levels, threshold_db}}, notes, scale: "clip"}` — состояния
  PNGtuber для превью (тот же массив, что `comp.voice` рендера).
* `POST /api/clip-plans/{id}/levels` — тело `{sources?, fps?}` (нет `sources` — по `react` сохранённых слоёв) →
  `{levels: {voice|music|mix: {t0, fps, v}}, notes, scale: "clip"}` — огибающие громкости для `react` в
  превью (тот же массив, что `comp.levels` рендера).
* `GET /api/montage-assets/{id}/anim`, `GET /api/montage-assets/{id}/anim-sheet.png` — анимация файла
  листом кадров с временами (превью GIF/APNG/webm-alpha); статичный файл — `{animated: false}`.
* `GET /api/motion/schema` — машиночитаемая схема слоёв (типы, props с умолчаниями и
  рамками, easing, анимации, пределы) — из `app/motion.py`.
* `POST /api/clip-plans/{id}/layers/validate` — тело `{layers?, camera?}` (нет — берутся
  сохранённые) → `{problems: [...], layers, camera, clip_duration}`; ничего не сохраняет.
  Проверяет ещё, что слои попадают в клип и файлы существуют.
* В файле клипа (`PUT …/spec`) проблемы формы слоёв/камеры отклоняют файл (422,
  `problems` с префиксом `render.layers[i]…`); слой за концом клипа там не ошибка.
* Слои меняются через `PATCH /api/clip-plans/{id}/render-settings` (весь список) или
  через файл клипа.
* `POST /api/clip-plans/{id}/snap-beats` (MCP `snap_to_beats`, `app/beat_snap.py`) — начала слоёв
  (`start`, длина та же), ключи слоёв (`keys[*].t` — через абсолютное время слоя, порядок ключей
  сохраняется), ключи камеры и склейки кусков — на ближайшую долю сетки музыки клипа
  (`audio_map.music_beats`, шкала final) с допуском `tolerance`; слои `captions`, `chat`, `pngtuber` и
  запертые не двигаются. В редакторе — «♪ К долям» в шапке таймлайна.
