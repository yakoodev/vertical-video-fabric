# Расширение «VVF: cookie аккаунтов»

Личное расширение для Chrome, Edge и Firefox (на компьютере). Берёт cookie TikTok или YouTube из вашего браузера и
одной кнопкой отправляет их в ваш сервис — в новый аккаунт или в уже существующий. Вместе с cookie уходит User-Agent
браузера: TikTok потом загружает ролики с тем же браузером, который выдал cookie.

Ни в какие магазины расширение не выкладывается. Сборки нет: это обычная папка с файлами.

## Установка

### Chrome или Edge

1. Откройте `chrome://extensions` (в Edge — `edge://extensions`).
2. Включите «Режим разработчика» (переключатель справа вверху; в Edge — слева).
3. Нажмите «Загрузить распакованное» и выберите папку `browser-extension` из репозитория.
4. Закрепите значок расширения на панели (значок пазла → булавка).

Папку после установки не переносите и не удаляйте: браузер читает расширение прямо из неё. Обновилось расширение в
репозитории — нажмите ↻ на его карточке в `chrome://extensions`.

### Firefox

**На время (до перезапуска Firefox).** Откройте `about:debugging` → «Этот Firefox» → «Загрузить временное
дополнение…» → выберите файл `browser-extension/manifest.json`. После перезапуска Firefox расширение пропадёт, и его
нужно загрузить снова.

**Насовсем.** Обычный Firefox ставит насовсем только подписанные Mozilla дополнения. Честные варианты:

- **Подписать «для себя» на addons.mozilla.org (unlisted).** Нужен аккаунт Mozilla. Загружаете zip-архив содержимого папки (`manifest.json` — в корне архива) как
  дополнение «не для каталога» (On your own), проверка автоматическая, обратно получаете подписанный `.xpi`. В каталоге
  оно не появится, никто его не увидит. Ставите `.xpi` из файла («Дополнения» → шестерёнка → «Установить дополнение из
  файла»). Минус: каждое обновление расширения — снова подписывать, с новым номером версии в `manifest.json`.
- **Firefox Developer Edition или Nightly.** В них можно выключить проверку подписи: `about:config` →
  `xpinstall.signatures.required` = `false`, затем поставить такой же zip-архив из файла. В обычном Firefox эта настройка не
  работает.

При первом сохранении настроек Firefox спросит доступ к адресу сервиса и к сайтам TikTok и YouTube — разрешите.
Если пользуетесь контейнерами Firefox, cookie берутся из контейнера открытой вкладки.

## Первая настройка

Значок расширения → «Настройки» (или правой кнопкой по значку → «Параметры»):

- **Адрес сервиса** — уже вписан `https://video.d.yakoo.dev`.
- **Токен сервиса** — тот же, что для входа в сервис (на сервере: `docker compose exec app cat /data/api_token.txt`).

«Сохранить и проверить» → должно появиться «Связь с сервисом есть, аккаунтов: N».

## Как пользоваться

1. Войдите в нужный аккаунт на сайте в этом браузере: `tiktok.com` или `studio.youtube.com`.
2. На вкладке этого сайта нажмите значок расширения — должно быть «Вход найден». «Войдите в аккаунт на сайте» значит,
   что браузер не вошёл в аккаунт: войдите и откройте расширение снова.
3. В списке «Аккаунт в сервисе» выберите аккаунт, которому обновить cookie, или «+ новый аккаунт» и впишите название
   (например, `tt-main`).
4. Нажмите «Отправить в сервис». Ответ сервиса: «Сохранено: «tt-main», вход есть».

Прокси аккаунта остаётся в сервисе: отправка cookie его не меняет. Cookie лучше снимать в браузере с того же IP, что и
прокси аккаунта (подробнее — `docs/cookie-import.md`).

**Запасной путь.** «Скопировать JSON» кладёт cookie в буфер в формате Cookie-Editor — их можно вставить руками в поле
Cookies в «Настройки → Аккаунты» сервиса. Такой JSON — ключ от аккаунта: никому его не пересылайте.

## Какие данные трогает

- **Cookie TikTok** — все cookie домена `tiktok.com`: сервис кладёт в загрузку весь набор.
- **Cookie YouTube** — только те, что браузер отправляет на `studio.youtube.com` (они на `.youtube.com`). Cookie
  `google.com` расширение не читает: сервису они не нужны.
- **User-Agent браузера** — строка, которой браузер представляется сайтам.
- **Адрес сервиса и токен** — хранятся только в этом профиле браузера (`storage.local`), никуда, кроме сервиса, не
  уходят и не пишутся в журналы.

Cookie читаются только когда вы открываете окно расширения, и уходят только по адресу из настроек — в ваш сервис
(`GET` и `POST /api/accounts` с токеном). Фоновых скриптов, аналитики, сторонних библиотек и запросов куда-то ещё нет.

Разрешения расширения: `cookies`, `storage` и доступ к `*.tiktok.com` и `*.youtube.com`. Firefox дополнительно
спрашивает доступ к адресу сервиса (Chrome и Edge обходятся без него, см. ниже).

## Для сервиса

- Сервис хранит User-Agent при аккаунте (`user_agent`) и загружает в TikTok с ним. Новые cookie без User-Agent
  (вставленные руками) стирают прежний: тогда берётся `TIKTOK_USER_AGENT` из `.env`, как раньше.
- Chrome и Edge обращаются к сервису с адреса `chrome-extension://nmhfjjfmmidnfhfjmpglcfaogegfiedg` (он не меняется:
  закреплён ключом `key` в `manifest.json`). Сервис разрешает этому адресу CORS только для `/api/accounts`. Другие
  адреса можно добавить через `BROWSER_EXTENSION_ORIGINS` в `.env` (через запятую).
- Firefox даёт расширению случайный адрес, поэтому там расширение просит доступ к адресу сервиса и CORS не нужен.
- Пока сервис не обновлён до версии с этим расширением, Chrome скажет «сервис не пускает расширение».

Проверка чистых функций: `node --test browser-extension/tests/lib.test.js`.
